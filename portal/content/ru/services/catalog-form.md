# Каталог услуг: форма

В каталоге Центра компетенций перечислено то, что Центр компетенций эксплуатирует, уже создал, испытывает и может развернуть повторно. На этой странице установлена форма каталога: два вида записей, поля каждого вида и состояние или статус записи. Действующий каталог — экземпляр этой формы, он ведётся в портфеле Центра компетенций (п. 4.4 Бизнес-модели); портал устанавливает только форму (п. 5.4 Каталога документов). Для иллюстрации приведено по одной записи каждого вида.

## 1. Два вида записей

1.1. Запись каталога о решении описывает одно решение Центра компетенций по его описанию решения: эксперимент, продукт или сервис. Запись каталога о пакете описывает один пакет, оставшийся по итогам взаимодействия с заказчиком, по его описанию пакета (шаблон AICC-TPL-14): методику, комплект средств, программный компонент, каталог автоматизаций, набор шаблонов.

1.2. Решение служит своему заказчику, пакет — следующему взаимодействию с заказчиком. Второе подразделение получает пакет за дни, тогда как первое взаимодействие заняло недели. Каталог решений и пакетов позволяет небольшому подразделению обслуживать весь Банк.

## 2. Поля записи каталога о решении

| Поле | Значение | Источник |
| --- | --- | --- |
| Идентификатор | SOL-nnn; не меняется на протяжении всего жизненного цикла решения | Описание решения |
| Наименование | Наименование решения | Описание решения |
| Категория | Категория услуг, в рамках которой решение создано | Соглашение о взаимодействии |
| Тип | Эксперимент, продукт или сервис | Описание решения |
| Состояние и стадия | Состояние согласно разделу 5 Модели жизненного цикла решений и, после внедрения, стадия, соответствующая типу решения | Описание решения; портфель |
| Инициатива | Инициатива, в составе которой создаётся решение | Бэклог портфеля |
| Направление и владелец направления | Подразделение-заказчик и его представитель | Соглашение о взаимодействии |
| Получатель | Кто эксплуатирует или внедряет решение после завершения разработки; для эксперимента — кто принимает передачу | Описание решения |
| Категория риска | 1, 2 или 3 | Реестр AI-решений |
| Уровень поддержки | Без поддержки, по запросу, с согласованными целевыми сроками реакции, эксплуатация силами Центра компетенций | Соглашение о взаимодействии |
| Состояние обслуживания | Четыре сигнала — уровни обслуживания, инциденты, использование и затраты — на дату последнего обзора | Система Service Management; текущий обзор |

## 3. Поля записи каталога о пакете

| Поле | Значение |
| --- | --- |
| Пакет | Наименование пакета |
| Назначение | Одна-две строки |
| Вид | Методика, комплект средств, программный компонент, каталог, набор шаблонов |
| Направление и категория услуг | Категория услуг, которая создаёт и использует пакет, с указанием направления услуг |
| Статус | Запланирован, в подготовке, доступен или отозван; это статус, а не состояние задачи |
| Ответственный | Инженер решений или руководитель Центра компетенций, который сопровождает пакет |
| Пользователи | Подразделения и решения, которые используют пакет |
| Условия повторного развёртывания | Что должно предоставить новое подразделение: корпус документов, источник данных, набор шаблонов, ответственного |
| Место хранения | Репозиторий или папка |

## 4. Состояние записи каталога о решении и статус записи каталога о пакете

4.1. Запись каталога о решении проходит состояния, установленные пунктом 5.1 Модели жизненного цикла решений: «Предложено», «Проработка» и «Одобрено» — до начала разработки; «В работе» — от начала разработки до конца жизненного цикла, а после внедрения — со стадиями, соответствующими типу решения; «Закрыто» — при выводе из эксплуатации, передаче или завершении работы (п. 8.1 Модели жизненного цикла решений). Приёмки отмечаются в разделе о выпуске описания решения. У записи каталога о пакете есть статус, а не состояние: «запланирован» — если категория предусматривает такой пакет; «в подготовке» — если пакет создаётся в ходе взаимодействия с заказчиком; «доступен» — если у пакета есть ответственный, описание и указания по повторному развёртыванию; «отозван».

## 5. Примеры

5.1. Запись каталога о решении из портфеля по состоянию на дату базовой версии:

| Идентификатор | Наименование | Тип | Состояние | Инициатива | Направление |
| --- | --- | --- | --- | --- | --- |
| SOL-001 | Конвейер отчётности FP&A для Совета директоров | Определяется на этапе MVP | Предложено | INI-004 FP&A: отчётность по финансовым показателям для Совета директоров | FP&A |

5.2. Запись каталога о пакете:

| Пакет | Назначение | Вид | Категория | Статус | Пользователи |
| --- | --- | --- | --- | --- | --- |
| Генератор портала | Формирует портал из комплекта нормативных документов: разделы, документы по частям, якоря пунктов, перекрёстные ссылки, термины с установленными значениями, схемы, поиск, два языка | Программный компонент | Платформы | Доступен | Центр компетенций — для этого портала |

## 6. Источник правил

Разделы 5 и 8 Модели жизненного цикла решений; пункты 4.4 и 5.5 Бизнес-модели; пункт 5.4 Каталога документов; шаблоны «Описание решения» и «Описание пакета» (AICC-TPL-14).
