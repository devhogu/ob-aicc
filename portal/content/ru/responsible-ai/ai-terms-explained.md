# Термины AI: пояснения

Здесь простыми словами объясняется терминология этой области для читателей курса. Документ «Терминология и стиль» устанавливает значения терминов, которые документы корпуса используют в своих правилах; эта страница поясняет технологические термины, знание которых документы предполагают. Если термин относится к обеим группам, применяется определение корпуса.

## 1. Виды систем

| Термин | Значение |
| --- | --- |
| Искусственный интеллект (AI) | Машинная система, которая для заданного набора целей на основе получаемых входных данных определяет, как сформировать выходные данные — прогнозы, содержание, рекомендации или решения, способные влиять на окружающую среду; это определение используют ОЭСР и ЕС |
| Машинное обучение | Способ построения модели на примерах вместо описания её правил; модель находит закономерность, соответствующую примерам, и применяет её к новым случаям |
| Модель | Сама выявленная в ходе обучения закономерность: функция, преобразующая входные данные в выходные, с параметрами, заданными при обучении. Скоринговая карта, модель выявления мошенничества и языковая модель — всё это модели |
| Большая языковая модель (LLM) | Модель, обученная на очень больших массивах текста предсказывать следующий токен; основа генеративного AI для работы с языком |
| Генеративный AI | AI, который создаёт содержание — текст, изображения, программный код, аудио, — а не только прогноз или класс |
| Базовая модель, модель общего назначения | Крупная модель, обученная решать задачи общего характера и адаптируемая ко множеству задач; Акт ЕС об AI называет её моделью AI общего назначения |
| AI-агент, агентный AI | Система, в которой модель планирует и действует для достижения цели с помощью инструментов: получает данные, вызывает сервисы, заполняет формы, выполняет код и выстраивает шаги в цепочку |
| Ассистент, copilot | Приложение, которое помогает пользователю ответами, предложениями или проектами документов. В корпусе ассистент не совершает действий за пределами формирования своего результата; система, которая действует через инструменты, является AI-агентом. |

## 2. Создание и использование

| Термин | Значение |
| --- | --- |
| Обучение модели | Процесс, в ходе которого параметры модели определяются на основе данных |
| Дообучение | Дополнительное обучение существующей модели с использованием данных конкретной задачи или организации |
| Запрос к модели | Инструкции и контекст, которые модель получает в момент использования; системный запрос — постоянная инструкция, заданная разработчиком |
| Контекстное окно | Объём текста, который модель может учитывать одновременно; всё, что находится за его пределами, модель не видит |
| Токен | Единица текста, которую языковая модель читает и формирует, — слово или его часть; затраты и лимиты исчисляются в токенах |
| Генерация ответов на основе семантической выборки (RAG) | Модели в момент вопроса передаются относящиеся к нему фрагменты одобренных документов, чтобы она отвечала по ним и ссылалась на них, а не опиралась на свою память |
| Эмбеддинг, векторное хранилище | Числовое представление текста, позволяющее системе находить фрагменты, наиболее относящиеся к вопросу; хранилище таких представлений |
| Опора на источники | Привязка ответов модели к одобренным источникам, чтобы их можно было перепроверить |
| Оценка, оценочный набор | Оценка модели или приложения на наборе случаев с ожидаемыми результатами. Оценочный набор в значении, установленном корпусом, согласуется с направлением и используется для тестирования решения или модели до начала применения и после каждого существенного изменения. |
| Эталонный тест | Стандартная оценка для сравнения моделей; полезна при выборе модели, но недостаточна для одобрения её применения |
| Защитные механизмы | Правила, фильтры и ограничения, установленные вокруг модели: на что она вправе отвечать, на что не вправе и какие действия может совершать |
| Человек в цикле, человек над циклом | Работник рассматривает каждый результат до того, как он будет применён; либо работник контролирует систему и может вмешаться и остановить её |
| Шлюз доступа к моделям | Единая контролируемая точка доступа к моделям с маршрутизацией запросов, контролем затрат, регистрацией событий и политикой защиты данных |
| Шлюз доступа к инструментам | Доступ системы AI к информационным системам и сервисам на основании разрешений, с ограничениями для каждого инструмента |

## 3. Виды сбоев

| Термин | Значение |
| --- | --- |
| Галлюцинация, конфабуляция | Гладкий, уверенный и ошибочный результат: несуществующий факт, число или ссылка на источник |
| Предвзятость | Систематическая несправедливость результатов, усвоенная из данных или заложенная при проектировании |
| Дрейф | Ухудшение качества работы модели по мере того, как реальность отходит от данных, использованных для её обучения |
| Промпт-инъекция | Текст во входных данных, который модель выполняет как инструкцию вопреки замыслу разработчика; прямая — если её пишет пользователь, косвенная — если она скрыта в документе или веб-странице, которые обрабатывает модель |
| Утечка данных | Попадание данных туда, где их быть не должно: в обучающий набор поставщика, в ответ другому пользователю, в журнал |
| Обход защитных ограничений (jailbreak) | Специально составленные входные данные, которые заставляют модель игнорировать защитные механизмы |
| Отравление данных | Искажение данных, используемых для обучения модели, или документов, которые она извлекает, с целью изменить её поведение |
| Избыточная самостоятельность | AI-агент, функциональность, права доступа или автономность которого превышают то, что нужно для его задачи |
| Чрезмерное доверие | Пользователи принимают результаты, не перепроверяя их, потому что система обычно права |
| Коллапс модели | Деградация моделей, для обучения которых всё больше используется содержание, созданное другими моделями |

## 4. Управление применением AI

| Термин | Значение |
| --- | --- |
| Ответственный AI, AI, заслуживающий доверия | Принципы и практики, благодаря которым организация остаётся подотчётной за применение AI; см. страницу «Что означает ответственный AI» |
| Категория риска | Классификация Банком случая применения AI по классу данных, по влиянию AI на принятие решения, по тому, доходит ли результат до клиента или затрагивает ли его, и по степени автономности; наивысший из этих факторов определяет применимые контрольные процедуры; термин, установленный пунктом 3.1 Политики применения AI |
| Риск-ориентированный подход | Меры контроля соразмерны риску; этот принцип лежит в основе [Акта ЕС об AI](../reference/regulations/eu-ai-act.md), [системы NIST](../reference/regulations/nist-ai-rmf.md) и категорий риска Банка |
| AI высокого риска | В [Акте ЕС об AI](../reference/regulations/eu-ai-act.md) — перечисленные в нём случаи применения, в том числе кредитный скоринг физических лиц, на которые распространяется полный набор обязанностей |
| Реестр AI | Запись о каждом решении, модели и AI-агенте Банка с указанием ответственного, области применения, доступа к данным и категории риска; реестр ведёт руководитель AICC; термин Заявления о намерениях |
| Управление модельным риском | Практика валидации, документирования и мониторинга моделей с назначенным владельцем; банковская практика, которую расширяет управление применением AI |
| Валидация, независимая валидация | В корпусе — рассмотрение решения категории риска 2 или 3 представителями контрольных функций до начала применения; её результаты действуют до истечения установленного срока; рассмотрение решения категории риска 1 лицом, не участвовавшим в его разработке, является проверкой. В управлении модельным риском — оценка модели лицами, которые её не создавали |
| Объяснимость | Способность объяснить, почему система сформировала результат, в таких формулировках, на основании которых затронутое лицо, надзорный орган или аудитор могут действовать |
| Прозрачность | Информирование людей о применении AI: о том, что они имеют дело с AI, и о том, как он используется |
| Оценка воздействия | Проводимая до начала применения с повышенным риском оценка его влияния на затрагиваемых лиц и их права |
| Карточка модели, карточка системы | Стандартный документ, в котором указано, что представляет собой модель или система, для чего она предназначена, порядок и результаты её тестирования и в каких случаях её не следует использовать |
| Грамотность в области AI | Понимание того, что AI делает и чего не делает, которое должно быть у каждого, кто его использует; обязанность по [Акту ЕС об AI](../reference/regulations/eu-ai-act.md) и требование Банка к обучению |
| Открытый банкинг | Предоставление данных о счетах и инициирование платежей лицензированными третьими лицами через интерфейсы с согласия клиента |
| Встроенные финансовые услуги | Финансовые услуги, предлагаемые внутри нефинансового продукта или приложения через банк-партнёр |
| Регуляторные технологии (regtech) | Технологии, в том числе AI, применяемые в работе по соблюдению требований: скрининг, мониторинг, отчётность, отслеживание изменений регулирования |
| Альтернативные данные | Данные, помимо кредитной истории, используемые для оценки клиента: транзакционные, мобильные и поведенческие, — с вытекающими из этого требованиями к справедливости и согласию |
| Проверка присутствия живого человека | Тест, подтверждающий, что лицо, предъявляющее документ, удостоверяющий личность, действительно присутствует и живо, а не представлено фотографией или записью |
| Скоринг в реальном времени | Результат модели, получаемый в пределах времени транзакции или взаимодействия, например при противодействии мошенничеству и проведении платежей |
