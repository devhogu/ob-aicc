# Термины ИИ: пояснения

Терминология области простым языком для читателя курса. Терминология корпуса определяет понятия, используемые документами как правила; эта страница объясняет технологические понятия, предполагаемые документами. Если термин относится к обеим группам, действует определение корпуса.

## 1. Виды систем

| Термин | Значение |
| --- | --- |
| Искусственный интеллект (ИИ) | Машинная система, которая для заданного набора целей выводит из получаемых входных данных способ формирования прогнозов, содержания, рекомендаций или решений, способных влиять на среду; определение ОЭСР и ЕС |
| Машинное обучение | Способ создания модели на примерах вместо записи правил; модель находит соответствующую примерам закономерность и применяет к новым случаям |
| Модель | Сама выученная закономерность: функция преобразования входных данных в результаты с параметрами, установленными обучением. Скоринговая карта, средство обнаружения мошенничества и языковая модель — модели |
| Большая языковая модель (LLM) | Модель, обученная на огромных массивах текста предсказывать следующий токен; основа генеративного ИИ для языка |
| Генеративный ИИ | ИИ, создающий содержание — текст, изображения, код, аудио, — а не только прогноз или класс |
| Базовая модель, модель общего назначения | Крупная модель, обученная для универсальных возможностей и адаптируемая к множеству задач; Акт ЕС об ИИ называет её моделью ИИ общего назначения |
| Агент, агентный ИИ | Система, в которой модель планирует и действует для достижения цели с помощью инструментов: читает, вызывает сервисы, заполняет формы, выполняет код и связывает шаги |
| Ассистент, помощник | Приложение ИИ, помогающее человеку в задаче предложениями и подготовкой материалов; решение принимает человек |

## 2. Как они создаются и используются

| Термин | Значение |
| --- | --- |
| Обучение модели | Процесс определения параметров модели на основе данных |
| Дообучение | Дополнительное обучение существующей модели на данных задачи или организации |
| Запрос к модели | Инструкции и контекст, предоставляемые модели при использовании; системный запрос — постоянная инструкция, заданная разработчиком |
| Контекстное окно | Объём текста, который модель может учитывать одновременно; находящееся за его пределами модель не видит |
| Токен | Единица, которую языковая модель читает и формирует, — слово или его часть; затраты и лимиты исчисляются в токенах |
| Генерация с дополнением результатами поиска (RAG) | Предоставление модели относящихся к вопросу фрагментов одобренных документов в момент запроса, чтобы она отвечала по ним со ссылками, а не по памяти |
| Эмбеддинг, векторное хранилище | Числовое представление текста, позволяющее находить наиболее подходящие к вопросу фрагменты; хранилище таких представлений |
| Опора на источники | Привязка ответов модели к одобренным источникам для возможности проверки |
| Оценка, Оценочный набор | Измерение качества модели или приложения на наборе случаев с известными правильными ответами; набор создаётся совместно со специалистами по соответствующей работе |
| Эталонный тест | Стандартная оценка для сравнения моделей; полезна при выборе, но недостаточна для одобрения применения |
| Защитные механизмы | Правила, фильтры и ограничения вокруг модели: на что она вправе отвечать, на что не вправе, что может делать |
| Человек в цикле, человек над циклом | Человек проверяет каждый результат до его вступления в силу либо наблюдает за системой и может вмешаться и остановить её |
| Шлюз моделей | Единая контролируемая точка доступа к моделям с маршрутизацией, контролем затрат, журналированием и политикой защиты данных |
| Шлюз инструментов | Доступ системы ИИ к системам и сервисам по разрешениям с ограничениями для каждого инструмента |

## 3. Как возникают ошибки

| Термин | Значение |
| --- | --- |
| Галлюцинация, конфабуляция | Связный, уверенный и неверный результат: несуществующий факт, число или ссылка |
| Предвзятость | Систематическая несправедливость результатов, усвоенная из данных или заложенная в проектировании |
| Дрейф | Ухудшение работы модели по мере расхождения реальности с данными её обучения |
| Внедрение инструкций в запрос (prompt injection) | Текст во входных данных, которому модель следует как инструкции вопреки замыслу разработчика; прямое — написанное пользователем, косвенное — скрытое в документе или странице, читаемых моделью |
| Утечка данных | Попадание данных туда, где их быть не должно: в обучающий набор поставщика, ответ другому пользователю, журнал |
| Обход защитных ограничений (jailbreak) | Специально составленные входные данные, побуждающие модель игнорировать защитные механизмы |
| Отравление данных | Искажение обучающих данных модели или извлекаемых ею документов для изменения поведения |
| Избыточная самостоятельность | Агент с функциональностью, разрешениями или автономностью сверх необходимых для задачи |
| Чрезмерное доверие | Принятие людьми результатов без проверки, поскольку система обычно права |
| Коллапс модели | Деградация моделей, всё чаще обучаемых на машинно-сгенерированном содержании |

## 4. Как осуществляется управление

| Термин | Значение |
| --- | --- |
| Ответственный ИИ, ИИ, заслуживающий доверия | Принципы и практики, сохраняющие ответственность организации за применение ИИ; см. «Что означает ответственный ИИ» |
| Категория риска | Классификация применения ИИ Банком по классу данных, влиянию ИИ на решение, доступности результата клиенту или воздействию на него, степени автономности; наивысший уровень определяет контрольные процедуры; термин Политики применения искусственного интеллекта 3.1 |
| Риск-ориентированный подход | Контрольные меры соразмерны риску; принцип [Акта ЕС об ИИ](../reference/regulations/eu-ai-act.md), [системы NIST](../reference/regulations/nist-ai-rmf.md) и Категорий риска Банка |
| ИИ высокого риска | В [Акте ЕС об ИИ](../reference/regulations/eu-ai-act.md) — перечисленные применения, включая оценку кредитоспособности физических лиц, с полным набором обязанностей |
| Реестр ИИ | Запись по каждому Решению, модели и Агенту Банка с владельцем, областью применения, доступом к данным и Категорией риска, которую ведёт Руководитель AICC; термин Заявления о намерениях |
| Управление модельным риском | Практика Валидации, документирования и мониторинга моделей с назначенным владельцем; банковская практика, расширяемая управлением ИИ |
| Валидация, независимая Валидация | В корпусе — рассмотрение Решения Категории риска 2 или 3 Представителями контрольных функций до применения и до истечения срока действия; рассмотрение Решения Категории риска 1 другим лицом является Проверкой. В управлении модельным риском — оценка модели лицами, не создававшими её |
| Объяснимость | Способность объяснить причину результата системы в терминах, на основании которых затронутое лицо, регулятор или аудитор может действовать |
| Прозрачность | Информирование людей о взаимодействии с ИИ и способе его применения |
| Оценка воздействия | Оценка влияния применения повышенного риска на затрагиваемых людей и их права до начала использования |
| Карточка модели, карточка системы | Стандартный документ о модели или системе, её назначении, способе проверки и недопустимых областях использования |
| Грамотность в области ИИ | Понимание возможностей и ограничений ИИ, необходимое каждому пользователю; обязанность по [Акту ЕС об ИИ](../reference/regulations/eu-ai-act.md) и требование обучения Банка |
| Открытый банкинг | Передача данных счетов и инициирование платежей лицензированными третьими сторонами через интерфейсы с согласия клиента |
| Встроенные финансовые услуги | Финансовые услуги внутри нефинансового продукта или приложения через банк-партнёр |
| Регуляторные технологии (Regtech) | Технологии, включая ИИ, для соблюдения требований: проверки, мониторинг, отчётность, изменения регулирования |
| Альтернативные данные | Данные помимо кредитной истории для оценки клиента: транзакционные, мобильные и поведенческие, с соответствующими требованиями справедливости и согласия |
| Проверка присутствия живого человека | Проверка того, что предъявляющий документ человек действительно присутствует и жив, а не представлен фотографией или записью |
| Скоринг в реальном времени | Решение модели в пределах времени транзакции или взаимодействия, например при противодействии мошенничеству и проведении платежей |
