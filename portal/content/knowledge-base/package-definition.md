# Package Definition

A draft template, proposed for the templates of the charter. A package is the reusable asset that an Engagement leaves: a method, a kit, an engine, a catalog of automations, or a template set, which the next Engagement takes in days where the first took weeks. The Package Definition is the record of one package. Until it is adopted into the charter by a decision record, this page is the draft form.

## 1. When it is used

1.1. A Package Definition is opened when a category foresees a package (state planned), is completed while an Engagement produces it (in preparation), and is kept current while the package is available. It is kept in the Portfolio beside the Solution Definitions, and the catalog of packages reads it.

## 2. The form

| Field | Entry |
| --- | --- |
| Identifier | PKG-nnn |
| Package | The name |
| Kind | Method, kit, engine, catalog, template set |
| Category | The service category that produces and uses it |
| What it does | In one or two lines |
| Status | Planned, in preparation, available |
| Owner | The Solution Engineer or the AICC Lead who keeps it |
| Produced by | The Engagement or the Initiative that left it |
| Used by | The functions and the Solutions that use it |
| Needs to re-deploy | What a new function must provide: a corpus, a data source, a template set, an owner, an environment |
| Risk Tier of its uses | The Risk Tier that a use of the package normally carries, and what raises it |
| Where it is kept | The repository or the folder, and the version |
| Date of last change | |

## 3. The sections

3.1. What it does and does not do. 3.2. How it is re-deployed, step by step. 3.3. What it depends on: providers, platforms, data classes. 3.4. The check or validation that a use of it needs. 3.5. The lessons from its uses.

## 4. Rule source

Business Model 4.4 (the reusable assets of the Engagements kept in the Portfolio); Solution Lifecycle Model 8; Document Catalog 4 (the life cycle of a template). Proposed as the fourteenth template of the charter.
