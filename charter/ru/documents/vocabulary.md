# Терминология и стиль

## 1. Назначение и область применения

1.1. Настоящий документ закрепляет терминологию и стиль документов, чтобы каждый термин имел одно значение, а изложение было единообразным.

## 2. Приоритет документов

2.1. При расхождениях между документами приоритет имеет документ, указанный ранее в следующем перечне: Заявление о намерениях по внедрению искусственного интеллекта, Положение об AICC, Бизнес-модель, Операционная модель, Модель управления портфелем, Модель жизненного цикла решений, Политика применения искусственного интеллекта, Каталог документов. По вопросам терминологии и стиля приоритет имеет настоящий документ. Шаблоны и Записи подчиняются документам. Схемы процессов и руководства поясняют документы и не устанавливают самостоятельных правил.

## 3. Стиль

3.1. Излагайте текст короткими нумерованными пунктами: один пункт — одно требование. Обязанность выражайте словами «должен», «должна» или «должны», а факт или полномочие — глаголом в настоящем времени.

3.2. Соблюдайте нормы русского литературного языка; используйте простые и точные формулировки. Пишите «Примите решение», а не «Осуществите принятие решения».

3.3. Пишите определённый термин с прописной буквы и используйте его в одном значении. Не используйте обозначения из столбца «Не используется».

3.4. Документ, устанавливающий определения и правила, описывает существующее положение и необходимые действия. Он не содержит сведений о происхождении текста, открытых вопросов и ссылок на файлы.

3.5. Документ ссылается на другой документ по его названию, а не по пути к файлу, и не повторяет его содержание. Заявление о намерениях повторяет отдельные определения, поскольку используется как самостоятельный документ.

3.6. Роль именуется по её ответственности, а не по лицу, которое её исполняет. Имена лиц указываются в Записи о назначениях.

3.7. В заголовках и названиях документов с прописной буквы пишутся первое слово, собственные имена и определённые термины. Каждой таблице предшествует вводный пункт, кроме журнала изменений.

3.8. Документ использует собственные термины, а не терминологию внешней методологии. Запись о стандартах сопоставляет термины внешней методологии с терминами документов.

3.9. Страницы Портала AICC, поясняющие документы, используют термины настоящего документа и не устанавливают самостоятельных правил; документы имеют приоритет перед такими страницами. Порядок ведения этих страниц установлен в Каталоге документов 5.4.

4.2. В следующей таблице определены состояния. Каждый элемент любого уровня находится в одном состоянии. Переходы между состояниями установлены Моделью жизненного цикла решений.

| Состояние | Значение | Не используется |
| --- | --- | --- |
| Предложено | Поступило в бэклог и ещё не рассмотрено |  |
| Проработка | Уточняется: исследуется, определяется объём, оценивается размер работ, формируется описание или проектируется. Работа до одобрения направлена на получение знаний и не включает испытание Решения |  |
| Одобрено | Допущено к работе и поставлено в очередь на выполнение; Зависимости известны |  |
| В работе | Работа выполняется |  |
| Ожидание | Работа остановлена из-за указанной Зависимости за пределами AICC. Это состояние, отображаемое на досках флагом |  |
| Отложено | Работа приостановлена по указанной причине и возвращена в свой бэклог |  |
| Выполнено | Работа завершена, но ещё не рассмотрена |  |
| На рассмотрении | Проверяется соответствие Критериям приёмки. Возможен возврат в состояние «В работе» |  |
| Принято | Соответствие Критериям приёмки подтверждено с фиксацией лица и даты. Владелец продукта принимает Функциональность или Функциональную возможность, а Владелец Домена — Решение и результат Инициативы. Владелец Домена одобряет Описание решения |  |
| Закрыто | Работа полностью завершена: принята; для Решения — также выведена из эксплуатации, передана либо прекращена |  |
| Перенаправлено | Элемент разделён или преобразован в новый элемент, с которым установлена связь |  |
| Отклонено | Принято отрицательное решение по существу ввиду отсутствия ценности: до одобрения, после MVP либо при рассмотрении. Работа выполняться не будет |  |
| Отменено | Элемент отозван без решения по существу, например из-за ошибки, недоразумения или дублирования, в любом состоянии от «Предложено» до «На рассмотрении», кроме «Выполнено»; либо Решение остановлено Контрольной функцией |  |

4.3. В следующей таблице определены Стадии. Стадия — фаза работы внутри состояния «Проработка» или «В работе».

| Стадия | Уровень | Значение |
| --- | --- | --- |
| Определение объёма | Инициатива, проработка | Определение объёма потребности совместно с функцией |
| Экономическое обоснование | Инициатива, проработка | Подготовка и одобрение экономического обоснования в Паспорте инициативы |
| MVP | Инициатива, в работе | Определение архитектуры и Описания решения для первого Решения и его пробное применение для проверки гипотезы |
| Реализация | Инициатива и Функциональная возможность, в работе | Поставка Решений Инициативы либо Функциональностей в составе Функциональной возможности |
| Определение | Решение, проработка | Определение Решения в его Описании решения |
| Поставка | Решение, в работе | Поставка Решения через его Функциональные возможности и Функциональности |
| Анализ | Функциональная возможность, проработка | Определение Функциональной возможности и её разделение на Функциональности |
| Исследование, Проектирование | Функциональность, проработка | Исследование потребности и проектирование реализуемой архитектуры |
| Разработка, Проверка, Развёртывание | Функциональность, в работе | Разработка, Проверка или Валидация и развёртывание |
| Эксплуатация, Развитие, Вывод из эксплуатации | Сервис, в работе | Эксплуатация Сервиса, его совершенствование и прекращение использования |
| Передача, Поддержка, Пересмотр, Вывод из эксплуатации | Продукт, в работе | Поставка версии, поддержка по запросу, выпуск новой версии и прекращение использования у потребителя |
| Испытание, Предложение, Передача | Эксперимент, в работе | Испытание Решения, предложение о его внедрении и Передача Получателю |
