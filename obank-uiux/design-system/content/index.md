# One O! approach across our portals

Use the same visual language for knowledge, service, document and working portals: a recognizable O! frame, a large central working surface, readable content and predictable controls.

This is the **working internal portal standard, version 0.1**. It consolidates the supplied internal examples and the existing O! asset kit. It is ready for implementation trials and UI/UX refinement; it is not an independently certified corporate brand manual.

## Find what you need

- **Foundations:** brand, colour, typography, icons, spacing and density.
- **Layout:** header, global navigation, central content, supporting context and responsive behaviour.
- **Components:** tabs, menus, tables, fields, dialogs and feedback.
- **Patterns:** seven functional examples built with the same styles.
- **Assets:** selected logos, the common icon family, fonts and downloadable implementation kit.
- **Adoption:** instructions for designers, developers and agents.

## The governing composition

**Global sections on the left → the selected subject in the centre → supporting navigation on the right.** Concern/view controls sit above the central content. On small screens, navigation becomes a disclosure and the reading surface remains a single column.

A catalogue, a document and a flow need different content composition. They share the same identity, control grammar, type, colour roles and behaviour. Application-specific information architecture remains the consuming portal's responsibility.

## What belongs where

| Area | Responsibility |
| --- | --- |
| Header | Portal identity, current scope and working global controls |
| Left navigation | Stable primary sections, labelled and ordered |
| Centre | The selected profile, document, results, form, comparison or diagram |
| Right context | Contents, related references and local navigation |
| Horizontal view navigation | Alternate presentations of the same selected subject |

Personal account screenshots and real enterprise data are excluded from the examples. Example interactions run locally in the browser and demonstrate a pattern; no business records are saved.
