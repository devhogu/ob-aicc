## Меры контроля и подтверждающие материалы {#controls-controls-and-evidence}

Страница предназначена для представителей контрольных функций и лиц, принимающих управленческие решения по пилоту. По каждому требованию на ней указаны механизм его выполнения, исполнитель, лицо, контролирующее выполнение, и рабочий документ, в котором хранятся подтверждающие материалы. Сами требования установлены Политикой применения AI, Моделью жизненного цикла решений и реестром стандартов. Подтверждающие материалы хранятся в описании решения, реестре AI-решений и заключениях контрольных функций, а не на этой странице.

### Ожидаемая категория риска 2 и условия её сохранения {#controls-risk-tier}

Руководитель Центра компетенций присваивает категорию риска при определении каждого решения и сообщает её владельцу направления; если решение создаёт руководитель Центра компетенций, категорию риска присваивает куратор Центра компетенций. Представитель любой контрольной функции вправе повысить категорию риска в пределах своей компетенции; понизить её вправе только представитель контрольной функции по модельному риску. Решению присваивается наиболее высокая категория риска, на которую указывает любой из факторов риска.

| Фактор риска | Пилот | Категория риска по фактору | Обеспечение |
| --- | --- | --- | --- |
| Класс данных | персональные данные клиентов и конфиденциальные данные обслуживания: контакты, обращения, жалобы и статус по клиентскому маршруту | 2 | перечень полей установлен контрактом контекста; применение для класса данных одобряет владелец направления |
| Влияние на принятие решений | результат помогает работнику объяснить ситуацию клиенту и выбрать следующий шаг; по каждому обращению решает работник | 2 | никакие действия не выполняются, пока работник не примет решение; действия по умолчанию нет |
| Доведение результата до клиента | только через работника, после проверки работником | 2 | на рабочем месте нет функции отправки; черновики маркируются отметкой «Подготовлено AI» |
| Степень автономности | ассистент: без инструментов и без права записи | 2 (AI-агенту с правом совершать действия в информационных системах присваивается категория 3) | у модели нет учётных данных; любая запись выполняется действием на рабочем месте, которое работник подтверждает нажатием |

Категория риска повышается, если модель получает право записи или инструмент, если результат доводится до клиента без проверки работником, если подключается внешний поставщик и представитель контрольной функции повышает категорию по этой причине, а также если представитель контрольной функции признаёт масштаб применения существенным. Для клиентского маршрута «Сопровождение оформления и KYC» (KYC — принцип «Знай своего клиента») представитель контрольной функции по комплаенсу вправе повысить категорию риска с учётом рисков, связанных с финансовыми преступлениями. Каждый из этих случаев является существенным изменением либо требует нового решения. При категории риска 3 управленческое решение о выпуске переходит к куратору Центра компетенций.

### Данные и размещение модели {#controls-data-and-hosting}

| Вопрос | Механизм | Принятие решения или контроль | Рабочий документ |
| --- | --- | --- | --- |
| Место работы модели | В Банке. Модель, размещённая в Банке, до начала обработки любых данных Банка проходит проверку как поставщик; лицензия каждого компонента с открытым исходным кодом и каждой модели фиксируется. | представители контрольных функций по информационной безопасности, защите данных и правовым вопросам (проверка поставщика) | заключение контрольной функции по итогам проверки поставщика; описание решения, раздел 3 |
| Внешняя модель | Не используется без выполнения трёх условий: проверки поставщика (где обрабатываются и хранятся данные, использование данных для обучения моделей, условия договора, резервный вариант и прекращение работы с поставщиком); одобрения применения для класса данных; подтверждения представителями контрольных функций соблюдения правил Банка об аутсорсинге и о персональных данных (реестр стандартов, EXT-001, EXT-002). Договор запрещает поставщику использовать данные Банка для обучения моделей. Подключение внешней модели в дальнейшем является существенным изменением. | те же представители контрольных функций; владелец направления — в части класса данных | заключение контрольной функции; реестр AI-решений, раздел «Модели, версии и поставщики» |
| Применение для класса данных и цели | Данные клиентов не обрабатываются с применением AI ни в ходе проработки, ни позднее, пока владелец направления не одобрит такое применение. Одобрение даётся после согласований, которые ВНД Банка требуют от владельца каждого источника и от контрольной функции по защите данных. Если решение создал руководитель Центра компетенций, применение одобряет куратор Центра компетенций. | владелец направления либо куратор Центра компетенций | реестр AI-решений, поля «Одобрено для» и «Кем одобрено, дата» |
| Данные фазы 1 в лабораторной среде | Выгрузки с доступом только для чтения; для каждой указаны владелец источника и класс данных. Персональные данные минимизируются и оцениваются до загрузки. Обратная запись в источники не выполняется. Доступ предоставляется по ролям, каждое действие регистрируется. Ключ повторной идентификации, если он есть, хранится вне лабораторной среды и недоступен модели. | представитель контрольной функции по защите данных; владельцы источников | блок «Эксперимент», пункты «Выгрузки данных» и «Сведения о среде»; заключение контрольной функции по защите данных |
| Чтение рабочих данных в фазе 2 | Только после валидации. Сервис контекста читает только поля, указанные в контракте контекста, и отбрасывает все остальные до обращения к модели. Сегмент клиента читается, только если он необходим для клиентского маршрута и с этим согласен представитель контрольной функции по защите данных. | представитель контрольной функции по защите данных при валидации | контракт контекста; ссылка на него приводится в разделе 3 описания решения |
| Цель | Результаты пилота используются только для решения вопросов клиентов и оценки ассистента. Любое иное использование требует отдельного одобрения для класса данных и цели. | владелец направления; представитель контрольной функции по защите данных | описание решения, «Условия применения» |
| Хранение | Журналы, снимки и хранилище данных пилота хранятся или удаляются в соответствии с правилами Банка о сроках хранения. По завершении права доступа отзываются, а запись в реестре AI-решений отмечается как выведенная из эксплуатации. | вывод из эксплуатации одобряет владелец направления | описание решения, «Вывод из эксплуатации или завершение» |

| Выпуск | Развёртывание для первых пользователей — после валидации, окончательной приёмки командой и одобрения в порядке управления изменениями Банка. Использование за пределами круга первых пользователей — только после подписания контрольного листа приёмки и выпуска решения владельцем направления. | руководитель Центра компетенций (окончательная приёмка командой); управление изменениями Банка; владелец направления (выпуск) | каждый подписант контрольного листа приёмки | раздел о выпуске в описании решения; заявка на изменение; контрольный лист приёмки |

Проверка поставщика повторяется при каждой повторной оценке и при любом изменении условий поставщика или его модели. | руководитель Центра компетенций; представители контрольных функций — в части проверки поставщика | представитель контрольной функции по модельному риску | реестр AI-решений, поле «Срок повторной оценки» |

### Подтверждение готовности для каждого управленческого решения {#controls-readiness-evidence}

Готовность к применению в промышленной среде не является отдельным одобрением. Подтверждающие материалы по архитектуре, данным, мерам контроля, эксплуатационной готовности и качеству рассматривают лица, указанные ниже. В процессах Центра компетенций прежние контрольные точки проекта одобрениями не являются: их содержание — подтверждающие материалы, которые рассматривают лица, принимающие управленческие решения согласно корпусу документов. Подробный перечень пунктов по IT приведён на странице [«Контрольный лист готовности IT»](#it-readiness).

| Прежняя контрольная точка | Подтверждающие материалы | Управленческое решение, для которого они нужны | Кто принимает решение | Рабочий документ |
| --- | --- | --- | --- | --- |
| Архитектура | профиль клиентского маршрута заполнен и согласуется с приложением по клиентскому маршруту; по каждой функции определены способ её обеспечения и ответственный; временные компоненты названы; логика клиентского маршрута отделена от функций платформы AI | одобрение описания решения | владелец направления (куратор Центра компетенций, если решение создал руководитель Центра компетенций) | описание решения, раздел 3 |
| Данные и интеграция | подтверждены источники, идентификаторы, значения статусов и способы чтения; перечни полей и источников знаний протестированы; выгрузки зарегистрированы с указанием владельца и класса данных; персональные данные оценены | одобрение применения для класса данных; загрузка данных в лабораторную среду | владелец направления совместно с владельцами источников; представитель контрольной функции по защите данных | реестр AI-решений; блок «Эксперимент»; заключение контрольной функции |
| Меры контроля | контроль идентификации, цели, доступа к полям, маршрута к модели, поиска и извлечения информации и результатов модели реализован и регистрируется; запрещённые данные, решения и действия блокируются программно; модель угроз, порядок обработки инцидентов и порядок приостановления зафиксированы | валидация; проверка поставщика | представители контрольных функций | заключения контрольных функций |
| Эксплуатационная готовность | среды, развёртывание, управление секретами, регистрация событий, резервный вариант и поддержка отработаны на практике; ручная обработка работает при отказе системы, от которой зависит решение; порядок обработки инцидентов встроен в процесс управления инцидентами Банка; мониторинг включён, сигнальные значения и ответственные за их отслеживание определены | окончательная приёмка командой; первое развёртывание в промышленной среде | руководитель Центра компетенций; управление изменениями Банка | раздел о выпуске; заявка на изменение |
| Качество | получены результаты на зафиксированном наборе обращений для типовых состояний и существенных нестандартных ситуаций; критические ошибки не выявлены; исправление, эскалация и фиксация результата работают от начала до конца; каждая Feature протестирована лицом, не участвовавшим в её разработке | окончательная приёмка командой; бизнес-приёмка | руководитель Центра компетенций; владелец направления | ссылки на результаты тестирования в Features; отчёт о результатах |

Работа решения в промышленной среде, при которой результат скрыт от работников (скрытый запуск), уже является развёртыванием: она допускается только после валидации, окончательной приёмки командой и одобрения в порядке управления изменениями Банка, а не до них.

### Правило приёмки {#controls-acceptance-rule}

Это единственное правило приёмки пилота; другие страницы ссылаются на него. Правило состоит из двух частей и одного управленческого решения.

**Часть 1: обязательные условия.** Это критерии приёмки, указанные в разделе 5 описания решения. Сначала они применяются к зафиксированному набору обращений в лабораторной среде, а результат отражается в отчёте о результатах; сервис определяется, только если на этом этапе условия выполнены. Руководитель Центра компетенций применяет их при окончательной приёмке командой, а владелец направления — к работающему сервису с первыми пользователями при бизнес-приёмке. Если какое-либо условие не выполнено, сервис возвращается на доработку или отклоняется.

| Условие | Критерий приёмки |
| --- | --- |
| Ссылка на источник | Дано: любой факт, статус или ранее выполненное действие на экране; когда: работник открывает ссылку на источник; тогда: ссылка ведёт к записи и её версии, сохранённым в снимке обращения. |
| Достоверный статус | Дано: обращение; когда: рабочее место показывает его состояние; тогда: состояние является значением из системы клиентского маршрута и никогда не является текстом модели. |
| Обработка критических ошибок | Дано: зафиксированный набор обращений; когда: проводится оценка; тогда: критические ошибки не выявлены. Критическая ошибка, выявленная на любом этапе, блокирует первое развёртывание или очередной выпуск до её исправления и повторного тестирования. Выборка не может доказать отсутствие ошибок; условие подтверждает лишь то, что ошибки не выявлены. |
| Минимальный уровень качества | Дано: выборка интерпретаций состояния и следующего шага; когда: эксперты направления их рассматривают; тогда: качество не ниже минимального уровня, установленного в приложении по клиентскому маршруту. Подразделение — владелец процесса вправе повысить минимальный уровень, но не понизить его. |
| Ручная обработка | Дано: запись отсутствует, устарела, противоречит другим записям или недостоверно связана с обращением; когда: обращение открывается; тогда: результат AI не отображается, а обращение передаётся на ручной разбор. |
| Ограничение действий | Дано: результат модели не является утверждённым кодом действия для подтверждённого состояния; тогда: он отбрасывается, и шаг не предлагается. Дано: любая запись в систему; тогда: она содержит идентификатор работника и его подтверждение нажатием. |
| Контрольные лимиты | Дано: период наблюдения; тогда: каждый контрольный лимит остаётся в пределах допустимого отклонения и не происходит ни одного недопустимого события. |
| Одобрение процесса | Дано: перечень действий и определения результатов; тогда: они одобрены подразделением — владельцем процесса, что зафиксировано как выполненная зависимость. |
| Фиксация | Дано: любое исправление, принятое действие, эскалация или результат; тогда: они фиксируются в хранилище данных пилота. |

**Часть 2: опережающие индикаторы.** В паспорте инициативы устанавливаются от двух до четырёх индикаторов: результат для клиента, трудозатраты на обработку и использование ассистента по обращениям, отвечающим критериям отбора, а также один индикатор клиентского маршрута. Каждый индикатор указывается ссылкой на источник и ответственного, а не числом на портале. Схема сравнения, период наблюдения и необходимое число обращений приведены в приложении об измерениях. Паспорт и приложение размещены на странице [«Паспорт инициативы»](#charter).

**Управленческое решение по итогам минимально жизнеспособного продукта (MVP).** Лицо, одобрившее бизнес-кейс (владелец направления, а если инициатива охватывает несколько направлений, — куратор Центра компетенций), рассматривает подтверждающие материалы и принимает управленческое решение.

| Подтверждающие материалы | Управленческое решение | Последующие действия |
| --- | --- | --- |
| Обязательные условия выполнены; индикаторы достигли целевых значений; владелец направления видит ценность | Продолжить | Capabilities вносятся в бэклог программы; использование за пределами круга первых пользователей — после оформления контрольного листа приёмки; в дальнейшем — предложение и передача решения IT-функции Банка в качестве получателя |
| Обязательные условия выполнены; индикаторы изменяются в нужном направлении, но обращений недостаточно для обоснованного вывода | Вернуть с указанием срока продления | MVP продлевается на указанное число итераций; недостающие сведения указываются в протоколе решения и в изменении паспорта инициативы |
| Потребность подтверждена, но подход или объём работ нужно изменить | Перенаправить | новая инициатива со ссылкой на прежнюю; сужение объёма работ в рамках той же гипотезы оформляется изменением паспорта инициативы |
| Сроки, зависимость или более высокий приоритет другой работы | Отложить | указываются причина и дата повторного рассмотрения; в протоколе решения указывается, сохраняется ли у первых пользователей принятый сервис |
| Обязательное условие не выполнено, и это нельзя исправить; ценность не подтверждена; состояние обращения невозможно надёжно отображать; контрольный лимит невозможно соблюсти | Отклонить | сервис выводится из эксплуатации: права доступа отзываются, с данными поступают в установленном порядке, запись в реестре AI-решений отмечается как выведенная из эксплуатации |

Выигрыш от ассистента по сравнению с режимом «только контекст» учитывается при принятии этого управленческого решения, но не является критерием по принципу «выполнено — не выполнено». Если основную часть улучшения дают сами связанные записи, это говорит в пользу инвестиций в интеграцию контекста и ограничения дальнейших инвестиций в модель. Остановка, объявленная представителем контрольной функции в пределах своей компетенции, окончательна.

### Контрольные лимиты и недопустимые события {#controls-control-limits}

До того как первые пользователи увидят какой-либо результат AI, в разделе 7 описания решения указывается каждый контрольный лимит: показатель, источник, ответственный, допустимое отклонение, периодичность пересмотра и сигнальное значение. Недопустимые события перечисляются отдельно от лимитов, которые отслеживаются в сопоставлении с допустимым отклонением.

| Недопустимое событие | Предупреждающие меры | Способ выявления |
| --- | --- | --- |
| Пропуск по вине ассистента срока, установленного законом или правилами платёжной системы | сроки берутся только из систем-источников и не входят в формат результата модели; обращения с критичными сроками передаются в порядке, установленном приложением по клиентскому маршруту | анализ обращений; жалобы |
| Утрата клиентом какого-либо права | обращения, по которым решается вопрос о правах клиента, исключены критериями отбора; возможность подать жалобу и обратиться к сотруднику сохраняется | анализ обращений; жалобы |
| Раскрытие информации лицу, не имеющему на это права, в том числе данных другого клиента | снимок привязан к одному клиенту; доступ по ролям и по принципу служебной необходимости; тестирование на доступ к данным другого клиента при валидации | анализ журналов; сообщения работников |
| Сообщение, дошедшее до клиента без отправки работником | на рабочем месте нет функции отправки | сверка записей каналов с хранилищем данных пилота |
| Запись в систему без действия работника | у модели нет возможности записи; каждая запись содержит идентификатор работника и его подтверждение нажатием | сверка журналов |
| Запрещённое действие или регулируемое решение, предложенное работнику в качестве следующего шага | контроль результата пропускает только утверждённые коды для подтверждённого состояния | журнал контроля результатов |
| Обход обязательной меры контроля или причинение клиенту критического вреда | перечисленные выше программные меры контроля срабатывают до отображения результата; ручная обработка доступна всегда | мониторинг; сообщения об инцидентах |

Каждое недопустимое событие является инцидентом AI. Любой работник, обнаруживший такое событие, сообщает о нём по каналу Банка для сообщений об инцидентах и указывает, что инцидент связан с применением AI. Подразделение по управлению инцидентами Банка уведомляет руководителя Центра компетенций, который вносит инцидент в реестр рисков и проблем и вправе приостановить применение сервиса.

К отслеживаемым лимитам относятся жалобы по клиентскому маршруту, исправления и отклонения результатов работниками, срок нахождения нерешённых обращений, повторные контакты и доля обращений, переданных на ручную обработку. Ухудшение любого из этих показателей по сравнению с базовым значением сверх согласованного допустимого отклонения не допускается. Достижение сигнального значения служит основанием для рассмотрения вопроса владельцем направления. В условиях валидации могут быть указаны значения, при которых руководитель Центра компетенций приостанавливает применение сервиса.

### Мониторинг: сигнальные значения и ответственные за их отслеживание {#controls-monitoring}

Инженер решений указывает каждое сигнальное значение в разделе 7 описания решения, а представители контрольных функций согласовывают его при валидации. Значения — это поля для заполнения; на этой странице они не устанавливаются. Владелец платформы обеспечивает регистрацию событий и мониторинг. Владелец направления на каждом ревью и демонстрации итерации рассматривает четыре сигнала (уровни обслуживания, инциденты, использование и затраты) и уведомления поставщиков и делает отметку о рассмотрении в описании решения.

| Сигнал | Измеряемый показатель | Сигнальное значение | Ответственный за отслеживание |
| --- | --- | --- | --- |
| Качество работы | качество на регулярной выборке рабочих обращений, которую рассматривают эксперты направления, не участвовавшие в разработке решения, — по каждому языку; доля результатов, из которых удалены отдельные утверждения | [инженер решений, раздел 7 описания решения] | инженер решений как эксплуатирующая сторона; эксперт направления — в части выборки |
| Дрейф | изменение соотношения языков, видов обращений, предлагаемых кодов действий, числа безрезультатных поисков и доли обращений, переданных на ручную обработку | [инженер решений, раздел 7 описания решения] | инженер решений |
| Частота отмены и исправления результатов работниками | принятые, исправленные и отклонённые результаты по неделям | [инженер решений, раздел 7 описания решения] | инженер решений; руководитель группы обслуживания — в части использования командой |
| Инциденты | инциденты AI, события, при которых причинение вреда было предотвращено, и недопустимые события | любое событие | подразделение по управлению инцидентами Банка; руководитель Центра компетенций |
| Затраты | затраты на одно обращение и за месяц в сопоставлении с лимитом затрат | [лимит затрат, раздел 7 описания решения] | инженер решений; владелец направления, которое несёт эксплуатационные затраты |
| Уровни обслуживания | доступность, время отклика и частота использования режима «только контекст» | [целевые сроки реагирования по соглашению о взаимодействии] | инженер решений |

### Приостановление и ручная обработка {#controls-suspension}

- **Кто приостанавливает.** Руководитель Центра компетенций или представитель любой контрольной функции. Приостановление и его снятие вносятся в журнал решений; при снятии фиксируются подтверждающие материалы о том, что причина устранена, а исправление повторно протестировано.
- **Переключение по решению команды.** Руководитель группы обслуживания вправе в любой момент перевести команду на действующий процесс. Это не является приостановлением; руководитель Центра компетенций уведомляется в тот же день.
- **Порядок отключения.** Предусмотрены три переключателя: отключение генерации (рабочее место остаётся в режиме «только контекст»), отключение отдельного действия и отключение рабочего места целиком. Ни один из них не удаляет записи об использовании. Все три переключателя тестируются до того, как первые пользователи увидят результат AI.
- **Резервный вариант.** Режим «только контекст» и ручная обработка допускаются всегда. Другую модель допускается использовать, только если она заранее прошла валидацию и указана в описании решения как резервная. Автоматическое переключение на другую модель или другого поставщика, как и автоматическое расширение круга пользователей, не допускается.

### Информирование, объяснение и возможность пересмотра решения {#controls-disclosure}

- **Что доходит до клиента.** Только то, что говорит работник, либо письменный ответ, который работник редактирует и отправляет через действующий канал. Ассистент лишь готовит черновики.
- **Информирование.** При категории риска 2 клиента информируют о применении AI, если результат доходит до клиента. Владелец направления организует информирование до того, как первые пользователи увидят результат AI; форму информирования определяет представитель контрольной функции по комплаенсу при валидации (например, фраза в письменных ответах и то, что работник отвечает на вопрос клиента по телефону).
- **Маркировка.** Каждый черновик на рабочем месте маркируется отметкой «Подготовлено AI». Кнопка «Использовать черновик» копирует его в канал и регистрирует факт использования черновика.
- **Объяснение.** Работник даёт объяснение на основе записей из источников, показанных на экране, а не текста модели.
- **Возможность пересмотра решения.** Клиент, не согласный с объяснением, пользуется действующим порядком подачи жалоб и исправления данных; в записи об обращении видны использованные факты из источников.

### Тестирование на предвзятость и ошибки {#controls-bias-and-error}

- **Что сравнивается.** Доля ошибок в определении состояния, препятствия и следующего шага, доля неподтверждённых утверждений и качество черновиков по группам, согласованным с представителями контрольных функций по защите данных и комплаенсу: например, по языку записей, каналу обращения, региону и виду обращения. Для формирования групп используются только поля, уже включённые в контракт контекста или в разметку оценочного набора.
- **Когда.** В лабораторной среде на зафиксированном наборе обращений — до анализа результата; повторно — до первого развёртывания в промышленной среде; в ходе мониторинга — на рассмотренной выборке рабочих обращений.
- **Кто.** Эксперты направления размечают зафиксированный набор обращений; за набор отвечают лица, не участвовавшие в разработке решения. Тестирование проводит тестировщик, не участвовавший в разработке. Представители контрольных функций по модельному риску и комплаенсу контролируют результаты при валидации.
- **Последующие действия.** При существенном различии между группами затронутая группа по критерию отбора направляется на ручную обработку до исправления и повторного тестирования. Результат фиксируется в сведениях о разработке в описании решения и в отчёте о результатах.

### Существенные изменения {#controls-significant-changes}

Каждое изменение оформляется как Feature. Существенными являются: смена модели, версии модели, поставщика или маршрута к модели; поле или класс данных за пределами контракта контекста; любое право записи или инструмент у модели; доведение результата до клиента без проверки работником; второй клиентский маршрут; любое изменение, указанное при валидации. По каждому такому изменению руководитель Центра компетенций решает, требуется ли новая валидация, и вносит это управленческое решение в журнал решений; изменение проходит окончательную приёмку командой и выпускается владельцем направления. Изменения запросов к модели, форматов результата или набора процедур сначала тестируются на зафиксированном наборе обращений, и руководитель Центра компетенций решает, являются ли они существенными. Расширение круга пользователей за пределы первых пользователей — это управленческое решение о выпуске, а не изменение.
