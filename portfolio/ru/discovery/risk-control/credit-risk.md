# Кредитный риск

Кредитный риск потребляет больше регуляторного капитала банка, чем любой другой риск. Это риск того, что заёмщик или контрагент не исполнит договорные обязательства, а возникший непредвиденный убыток уменьшит капитал CET1. В соответствии с пруденциальными требованиями кредитным риском управляют с помощью комплекса моделей PD/LGD/EAD, резервов под ожидаемые кредитные убытки (ОКУ) по МСФО (IFRS) 9, лимитов концентрации и ведения списка наблюдения. Basel III/IV устанавливает нижнюю границу требований к капиталу; если банк применяет внутренние модели, они калибруются в этих пределах. **Генеративный AI позволяет сократить цикл анализа кредитного портфеля** — вместо квартальных пакетов материалов, которые неделями собираются вручную, Банк получает еженедельный анализ, подготовленный с применением AI, где сигналы миграции, структура концентраций и риски списка наблюдения сведены в единый обзор.

## Проблемы

### Экспозиции на контрагентов {#counterparty-exposure}

| Аспект | Проблема |
| --- | --- |
| Аналитика | Аналитика миграции PD, ухудшения кредитов из списка наблюдения и экспозиций на контрагентов готовится каждая в своём отчётном цикле, из разных систем управления рисками и кредитных систем. У директора по рискам и директора по кредитным рискам нет непрерывной картины того, как меняется качество отдельных контрагентов по сравнению с портфелем в целом: новые кандидаты в список наблюдения выявляются только на ежемесячном заседании кредитного комитета, через несколько недель после того, как сигналы раннего предупреждения появились в данных. |
| Поддержка | Подготовка к рассмотрению кредита на комитете — формирование досье контрагента, сверка текущей финансовой отчётности с кредитным меморандумом, по которому кредит был одобрен, и подготовка презентации для комитета — отнимает 60–80% времени, которое клиентский менеджер или кредитный аналитик тратит перед заседанием. Аналитическая работа, ради которой собирается комитет, начинается только после того, как материалы собраны. |
| Автоматизация | Отчёты по списку наблюдения, пакеты материалов по кредитному портфелю для комитета по рискам и пояснительные записки о резервах под ОКУ по МСФО (IFRS) 9 ежемесячно или ежеквартально собираются из выгрузок кредитной системы, управленческой отчётности и выходных данных моделей. У каждого документа есть заданный формат и известные источники данных; сборка повторяется из цикла в цикл и требует обработки большого объёма данных. |
| Новые возможности | Кредитный портфель под непрерывным мониторингом — еженедельные сигналы миграции, запас до лимитов концентрации в режиме реального времени и показатели поколений кредитов по периодам выдачи — даёт директору по кредитным рискам опережающий сигнал, которого не дают квартальные циклы обзора. Решения об использовании кредитного риск-аппетита и о перебалансировке портфеля можно принимать по текущей позиции, а не по отчёту прошлого месяца. |

## Аналитика экспозиций на контрагентов {#counterparty-exposure-analytics}

Агрегирование всех балансовых и внебалансовых экспозиций на одного контрагента или группу связанных лиц — кредитов, обязательств по предоставлению средств, производных инструментов и торгового финансирования — и отчётность по ним в сравнении с лимитами концентрации на одного контрагента. Правила о крупных рисках, соответствующие базельским стандартам по крупным рискам, обычно требуют расширенной отчётности, когда экспозиция на одного контрагента превышает 10% капитала первого уровня. Аналитика экспозиций на контрагентов сводит полную картину экспозиций по видам продуктов и юридическим лицам, что позволяет контролировать лимиты и готовить материалы к рассмотрению кредитов.

### Пакет уведомления о превышении лимита экспозиции на контрагента

- URN: urn:financial-services:scenario:risk-control/credit-risk/counterparty-exposure-analytics/counterparty-exposure-breach-pack
- Аспект: Поддержка
- Сложность: S
- Назначение: Когда экспозиция на одного контрагента превышает регуляторный лимит крупного риска, AI-агент готовит пакет уведомления надзорного органа: полную разбивку экспозиции и структуру юридических лиц, которые нужны директору по рискам для ответа.
- Решаемая задача: Превышение лимита крупного риска влечёт обязательное уведомление надзорного органа в соответствии с правилами о крупных рисках. Для пакета уведомления — совокупная экспозиция по продуктам, схема связей юридических лиц, хронология возникновения экспозиции и меры руководства — нужны данные из нескольких систем, и до установленного регулятором срока аналитики тратят на него часы работы.
- Решение: AI-агент выявляет превышение лимита по ежедневному реестру экспозиций, получает полную разбивку по продуктам, строит схему структуры юридических лиц и готовит пакет уведомления надзорного органа в установленном формате. Директор по рискам рассматривает и утверждает пакет до его направления.
- Критерии приёмки: По каждому превышению лимита крупного риска директор по рискам рассматривает и утверждает пакет уведомления надзорного органа, подготовленный AI-агентом (совокупная экспозиция по продуктам, схема связей юридических лиц и хронология возникновения экспозиции), и не ждёт, пока аналитики соберут его в оставшееся до установленного регулятором срока время.

| Измерение | Ключевой результат |
| --- | --- |
| Внедрение | В первые 12 месяцев после запуска AI-агент готовит пакет уведомления не менее чем по 95% превышений лимита крупного риска, выявленных по ежедневному реестру экспозиций; с момента запуска каждый пакет содержит разбивку по продуктам и схему структуры юридических лиц. |
| Принятие | ≥85% пакетов, подготовленных AI-агентом, директор по рискам утверждает до направления без существенных дополнений; при контроле качества в ≥95% пакетов данные об экспозиции по продуктам подтверждаются как точные по системам-источникам. |
| Цикл | Пакет уведомления поступает директору по рискам не позднее 4 часов с момента выявления превышения; при прежнем подходе аналитики собирали его из нескольких систем не менее одного рабочего дня. |

### Агрегирование экспозиций на контрагентов

- URN: urn:financial-services:scenario:risk-control/credit-risk/counterparty-exposure-analytics/counterparty-exposure-aggregation
- Аспект: Автоматизация
- Сложность: M
- Назначение: AI-агент агрегирует балансовые и внебалансовые экспозиции на каждого контрагента и группу связанных лиц по кредитам, обязательствам по предоставлению средств, производным инструментам и торговому финансированию и готовит отчёт об экспозициях на одного контрагента для контроля лимитов крупных рисков.
- Решаемая задача: Чтобы агрегировать экспозиции на одного контрагента, нужно объединить по контрагенту данные систем учёта кредитов, производных инструментов и торгового финансирования. Связи юридических лиц — когда экспозицию на дочернюю компанию следует относить к группе связанных лиц материнской компании — определяются вручную, и здесь легко ошибиться, особенно с корпоративными группами, действующими в нескольких юрисдикциях.
- Решение: AI-агент считывает данные об экспозициях из систем учёта кредитов, производных инструментов и торгового финансирования, по принятой в Банке иерархии связей юридических лиц агрегирует их до уровня группы связанных лиц и формирует реестр экспозиций на одного контрагента с данными об использовании лимитов и отметками о превышении порогов крупного риска. До выпуска отчёта специалист по кредитному риску проверяет отнесение юридических лиц к группам по всем новым структурам контрагентов.
- Критерии приёмки: Специалист по кредитному риску выпускает реестр экспозиций на одного контрагента, агрегированных до уровня группы связанных лиц по кредитам, обязательствам по предоставлению средств, производным инструментам и торговому финансированию, с данными об использовании лимитов и отметками о превышении порогов крупного риска; вручную он проверяет только новые структуры контрагентов, а не сопоставляет все юридические лица.

| Измерение | Ключевой результат |
| --- | --- |
| Внедрение | В первые 6 месяцев после запуска AI-агент формирует реестр экспозиций на одного контрагента не менее чем в 95% отчётных циклов; с момента запуска при каждом расчёте экспозиции по кредитам, производным инструментам и торговому финансированию агрегируются до уровня группы связанных лиц. |
| Принятие | ≥90% реестров, сформированных AI-агентом, специалист по кредитному риску выпускает без исправления отнесения существующих контрагентов к группам; ошибки агрегирования на уровне групп, выявляемые при контроле качества, сокращаются до ≤2% контрагентов. |
| Цикл | Реестр экспозиций доступен специалисту по кредитному риску не позднее 2 часов после среза данных в системах-источниках; при прежнем подходе ручное объединение данных разных систем и отнесение юридических лиц к группам занимали не менее одного рабочего дня. |

### Анализ динамики экспозиций на контрагентов

- URN: urn:financial-services:scenario:risk-control/credit-risk/counterparty-exposure-analytics/counterparty-exposure-trend-analysis
- Аспект: Аналитика
- Сложность: M
- Назначение: AI-агент отслеживает динамику концентрации на отдельных контрагентов и отрасли за скользящие 12 месяцев и выявляет контрагентов, у которых экспозиция растёт всё быстрее по отношению к запасу до лимита, для еженедельного обзора директора по кредитным рискам.
- Решаемая задача: Срезы использования лимитов показывают текущую позицию, но не скорость её изменения. Контрагент, который за несколько месяцев постепенными выборками приближается к лимиту крупного риска, виден на графике динамики, но не в отчёте на дату; внимание кредитного подразделения обычно направлено на уже допущенные превышения, а не на траекторию.
- Решение: AI-агент анализирует ежедневные реестры экспозиций за 12 месяцев, рассчитывает тренд и скорость изменения использования лимитов по каждому контрагенту и отрасли и отмечает тех, у кого траектория указывает на превышение лимита в ближайшие 90 дней. Директор по кредитным рискам еженедельно получает сводку динамики вместе со стандартным отчётом об использовании лимитов.
- Критерии приёмки: Директор по кредитным рискам еженедельно получает вместе со стандартным отчётом об использовании лимитов сводку динамики, в которой названы контрагенты и отрасли, чья траектория экспозиции указывает на превышение лимита в ближайшие 90 дней.

| Измерение | Ключевой результат |
| --- | --- |
| Внедрение | В первые 6 месяцев после запуска AI-агент еженедельно анализирует динамику по ежедневным реестрам экспозиций за 12 месяцев; в первый год сводка динамики поступает директору по кредитным рискам не менее 45 недель подряд. |
| Принятие | ≥75% контрагентов, отмеченных AI-агентом, директор по кредитным рискам признаёт требующими рассмотрения; ≥80% контрагентов, достигших лимита в течение года, AI-агент отметил не менее чем за 30 дней до этого. |
| Цикл | Еженедельная сводка динамики готова не позднее одного рабочего дня после среза данных об экспозициях на конец недели: превышение выявляется не в момент, когда оно произошло, а за срок до 90 дней до него. |

## Концентрация и отраслевой риск {#concentration-sector-risk}

Риск концентрации — дополнительный риск потерь, который возникает, когда значительная часть портфеля приходится на одного контрагента, группу, отрасль, регион или кластер взаимосвязанных заёмщиков. Правила о крупных рисках обычно требуют уведомлять надзорный орган, когда концентрация на одного контрагента превышает 25% капитала первого уровня; отраслевые лимиты концентрации устанавливаются внутренним документом — заявлением о риск-аппетите. Принципы BCBS 239 требуют агрегировать данные о рисках так, чтобы концентрацию можно было своевременно отслеживать, в том числе в стрессовых условиях. Стандартные отчёты о концентрации охватывают привычные измерения; взаимосвязанные концентрации на стыке нескольких измерений требуют отдельной аналитической работы.

### Анализ концентрации портфеля

- URN: urn:financial-services:scenario:risk-control/credit-risk/concentration-sector-risk/portfolio-concentration-analysis
- Аспект: Аналитика
- Сложность: M
- Назначение: AI-агент анализирует кредитный портфель на предмет концентраций по пяти измерениям — отрасли, регионы, отдельные контрагенты, залоги и взаимосвязанные межотраслевые кластеры — и по каждому измерению рассчитывает запас до лимита.
- Решаемая задача: Стандартные отчёты о концентрации охватывают отрасли, регионы и отдельных контрагентов. Взаимосвязанные концентрации — пересечение региона и отрасли, кластеры в цепочках поставок крупнейших заёмщиков, корреляция залогов разных контрагентов — в стандартных отчётах не видны; их приходится анализировать отдельно, и такой анализ заказывают, когда событие в отрасли уже развивается.
- Решение: AI-агент анализирует весь кредитный портфель и распределяет экспозиции по всем пяти измерениям концентрации, включая многомерные взаимосвязанные концентрации. Он рассчитывает запас до лимита по каждому измерению и моделирует влияние концентрации при отраслевом стресс-сценарии. Директор по кредитным рискам еженедельно получает обзор концентраций с отметками об эскалации.
- Критерии приёмки: Директор по кредитным рискам управляет риском кредитной концентрации на основе еженедельного анализа, который AI-агент готовит по пяти измерениям — отрасли, регионы, отдельные контрагенты, залоги и взаимосвязанные межотраслевые кластеры, — с рассчитанным запасом до лимита и отметками об эскалации.

| Измерение | Ключевой результат |
| --- | --- |
| Внедрение | В первые 6 месяцев после запуска AI-агент еженедельно анализирует концентрацию по всем пяти измерениям; в первый год обзор поступает директору по кредитным рискам не менее 45 недель подряд. |
| Принятие | ≥80% отметок об эскалации директор по кредитным рискам при рассмотрении признаёт существенными; взаимосвязанные межотраслевые концентрации, выявленные AI-агентом, приводятся не менее чем в одном обсуждении мер по их снижению на кредитном комитете в квартал. |
| Цикл | Еженедельный анализ концентрации готов не позднее одного рабочего дня после среза данных кредитного портфеля; при прежнем подходе отдельный ручной анализ заказывали уже после событий в отрасли, и он занимал не менее недели. |

### Стресс-сценарий для отраслевой концентрации

- URN: urn:financial-services:scenario:risk-control/credit-risk/concentration-sector-risk/sector-stress-concentration-scenario
- Аспект: Поддержка
- Сложность: M
- Назначение: AI-агент моделирует заданный отраслевой стресс-сценарий — обвал цен на сырьевые товары, коррекцию на рынке недвижимости или понижение суверенного рейтинга — применительно к текущему профилю концентрации портфеля и рассчитывает ожидаемые потери для обсуждения стресс-сценария на кредитном комитете.
- Решаемая задача: Разовый анализ отраслевого стресс-сценария заказывают после события в отрасли. Для него нужно совместить текущие данные об отраслевых экспозициях с историческими уровнями потерь или параметрами надзорного стресс-тестирования; эта работа с несколькими системами занимает у аналитиков несколько дней и обычно завершается уже после соответствующего заседания кредитного комитета.
- Решение: AI-агент считывает текущие отраслевые экспозиции, применяет заданный набор стресс-параметров из библиотеки стресс-тестирования Банка — рост PD, увеличение LGD, допущение о корреляции, — рассчитывает ожидаемые потери по отраслям и влияние на весь портфель и выдаёт результаты сценария не позднее одного рабочего дня после запроса. Кредитный комитет использует их как основу для обсуждения стресс-сценария.
- Критерии приёмки: Кредитный комитет обсуждает отраслевое стрессовое событие, располагая результатами сценария, которые AI-агент подготовил до заседания, а не после него: ожидаемыми потерями по отраслям и влиянием на весь портфель при заданных стресс-параметрах PD, LGD и корреляции.

| Измерение | Ключевой результат |

## Выходные данные моделей PD/LGD/EAD {#pd-lgd-ead-model-outputs}

Если Банк применяет модели на основе внутренних рейтингов (IRB) в рамках Компонента 1 (Pillar 1) Basel III, они дают оценки трёх основных параметров: вероятности дефолта (PD), уровня потерь при дефолте (LGD) и величины кредитного требования на момент дефолта (EAD). От выходных данных PD/LGD/EAD зависят регуляторный капитал (через активы, взвешенные по риску, — RWA), ОКУ по МСФО (IFRS) 9 и цена кредитов. Чтобы надзорный орган одобрил модели IRB, их качество необходимо непрерывно отслеживать; при существенном ухудшении модель перекалибруется, а надзорный орган уведомляется. Выходные данные моделей обновляются ежемесячно и используются подразделениями, отвечающими за капитал, кредитный риск и финансы.

## Поколения кредитов и миграция {#vintage-cohort-migration}

Анализ по поколениям отслеживает качество кредитов, выданных в определённый период: уровни дефолтов и потерь и характер миграции сравниваются между поколениями выдачи, чтобы оценить, как меняется кредитное качество в зависимости от периода андеррайтинга. Анализ миграции показывает, как экспозиции со временем переходят между рейтинговыми категориями или категориями качества активов. Вместе они дают опережающий сигнал о кредитном качестве, которого не дают сами по себе оценки PD на дату и коэффициенты обесценения по остаткам портфеля. Распределение кредитов по стадиям для расчёта ОКУ по МСФО (IFRS) 9 зависит от признаков значительного увеличения кредитного риска, которые определяются с учётом анализа миграции.

- Решение: AI-агент считывает ежемесячные реестры миграции, строит скользящие матрицы миграции по рейтинговым категориям и классам активов, рассчитывает тренд каждой вероятности перехода и отмечает пары категорий, в которых вероятность понижения рейтинга растёт быстрее установленного порога. Директор по рискам и кредитный комитет получают обзор динамики вместе со стандартной матрицей миграции.
- Критерии приёмки: Директор по рискам и кредитный комитет вместе со стандартной ежемесячной матрицей миграции получают обзор динамики миграции за скользящие 12 месяцев по рейтинговым категориям и классам активов с отметками об ускорении потоков понижения рейтинга.

### Анализ признаков значительного увеличения кредитного риска

- Решаемая задача: Чтобы отнести экспозицию к стадии 2 по МСФО (IFRS) 9, нужно установить, что кредитный риск по ней значительно увеличился с момента выдачи. Количественные критерии значительного увеличения кредитного риска — сравнение PD на весь срок кредита, безусловный критерий по количеству дней просрочки (DPD), качественные критерии ручного изменения стадии — применяются ко всему крупному портфелю. Для этого нужны систематическая выгрузка данных и применение правил, а при ручной работе результаты легко оказываются непоследовательными.
- Решение: AI-агент считывает текущие оценки PD, значения PD на дату выдачи, данные о платёжном поведении и отметки о ручном изменении стадии по качественным критериям. Он применяет критерии значительного увеличения кредитного риска, формирует реестр переходов между стадиями с указанием сработавшего критерия по каждой экспозиции и отмечает закономерности миграции на уровне портфеля, чтобы финансовый контролёр проверил их до расчёта резервов под ОКУ.

## Список наблюдения и раннее предупреждение {#watchlist-early-warning}

Система мониторинга портфеля, которая выявляет кредиты с ранними признаками ухудшения ещё до дефолта: напряжённость по финансовым ковенантам, нарушения графика платежей, негативные новости об отрасли, снижение стоимости залога. Ведение списка наблюдения входит в требования и рекомендации регулятора по управлению кредитным риском; по каждому кредиту из списка нужны план усиленного мониторинга и периодическое рассмотрение комитетом. Системы индикаторов раннего предупреждения задают условия включения в список наблюдения и порядок эскалации вплоть до классификации кредита как требующего особого внимания или субстандартного.

### Мониторинг нарушений ковенантов по кредитам из списка наблюдения

- URN: urn:financial-services:scenario:risk-control/credit-risk/watchlist-early-warning/watchlist-covenant-tracker

- Сложность: M

Он определяет статус соблюдения и запас по каждому ковенанту, отмечает нарушения и случаи, когда требуется освобождение от исполнения ковенанта, и формирует реестр статуса ковенантов по всему списку наблюдения. Кредитный аналитик проверяет реестр и выносит подтверждённые нарушения на эскалацию в порядке, установленном кредитной политикой.
- Критерии приёмки: Перед каждым циклом рассмотрения кредитный аналитик проверяет реестр статуса ковенантов, сформированный AI-агентом (статус соблюдения, запас, отметки о нарушениях и необходимые освобождения от исполнения ковенантов по каждому кредиту из списка наблюдения), а не рассчитывает показатели ковенантов вручную по отчётности заёмщиков.

## ОКУ и резервы по МСФО (IFRS) 9 {#ecl-ifrs9-provisions}

Ожидаемые кредитные убытки (ОКУ) по МСФО (IFRS) 9 — прогнозная оценка кредитных убытков, взвешенная по вероятности и распределённая по стадиям в зависимости от ухудшения кредитного качества: стадия 1 (ОКУ за 12 месяцев), стадия 2 (ОКУ за весь срок по кредитам со значительным увеличением кредитного риска) и стадия 3 (ОКУ за весь срок по кредитно-обесценённым экспозициям). При расчёте ОКУ PD, LGD, EAD и прогнозные макроэкономические корректировки объединяются по поколениям выдачи и сегментам портфеля. Обычно ОКУ рассчитываются ежеквартально; остаток резервов отражается в отчётности, представляемой надзорному органу, и раскрывается в финансовой отчётности.

### Пояснительная записка о резервах под ОКУ

- URN: urn:financial-services:scenario:risk-control/credit-risk/ecl-ifrs9-provisions/ecl-provision-narrative
- Аспект: Автоматизация
- Сложность: M
- Назначение: AI-агент готовит ежеквартальную пояснительную записку о резервах под ОКУ по МСФО (IFRS) 9 — переходы между стадиями, обоснование макроэкономической корректировки и изменение по сравнению с прошлым кварталом — для рассмотрения финансовым контролёром и директором по рискам.
- Решаемая задача: Прежде чем начать писать ежеквартальную пояснительную записку об ОКУ по МСФО (IFRS) 9, подразделение кредитных рисков и финансовое подразделение сопоставляют выходные данные моделей, исходные данные макроэкономической корректировки и прежние раскрытия. Пояснения к переходам между стадиями, допущения макроэкономической корректировки и анализ отклонений приходится сверять между разными системами: данные об ОКУ, PD/LGD/EAD и стадиях хранятся в разных хранилищах.
- Решение: AI-агент считывает текущие выходные данные модели ОКУ, данные о переходах между стадиями, допущения макроэкономической корректировки и раскрытия прошлого квартала. Он готовит пояснительную записку о резервах в установленном формате (пояснение переходов между стадиями, обоснование макроэкономической корректировки и анализ отклонений), которую финансовый контролёр и директор по рискам рассматривают и утверждают.
- Критерии приёмки: Финансовый контролёр и директор по рискам рассматривают ежеквартальную пояснительную записку о резервах под ОКУ по МСФО (IFRS) 9, подготовленную AI-агентом по выходным данным моделей в установленном формате: переходы между стадиями, обоснование макроэкономической корректировки и анализ отклонений от прошлого квартала.

| Измерение | Ключевой результат |
| --- | --- |
| Внедрение | В первые 18 месяцев после запуска AI-агент готовит пояснительную записку о резервах под ОКУ не менее четырёх отчётных кварталов подряд; при каждом запуске все предусмотренные разделы (переходы между стадиями, макроэкономическая корректировка, анализ отклонений) заполняются по данным моделей. |
| Принятие | ≥80% записок об ОКУ, подготовленных AI-агентом, финансовый контролёр и директор по рискам принимают лишь с незначительной редакторской правкой; ошибки межсистемной сверки данных о переходах между стадиями, выявляемые при контроле качества, сокращаются до ≤3% пунктов записки. |
| Цикл | Проект пояснительной записки готов не позднее двух рабочих дней после фиксации квартальных выходных данных модели; при прежнем подходе ручная сборка данных из разных систем занимала не менее недели. |

### Подготовка к калибровке макроэкономической корректировки

- URN: urn:financial-services:scenario:risk-control/credit-risk/ecl-ifrs9-provisions/macro-overlay-calibration-support
- Аспект: Поддержка
- Сложность: M
- Назначение: AI-агент считывает текущие макроэкономические прогнозы из утверждённых в Банке сценариев и записи о прежних калибровках корректировки и готовит структурированный документ с исходными данными для ежеквартального пересмотра макроэкономической корректировки подразделением кредитных рисков и финансовым подразделением.
- Решаемая задача: При калибровке макроэкономической корректировки по МСФО (IFRS) 9 подразделение кредитных рисков оценивает, достаточно ли ОКУ, рассчитанные моделью, отражают макроэкономический прогноз, и там, где это не так, применяет управленческое суждение. Материалы к обсуждению калибровки готовит аналитик по кредитному риску на основе нескольких источников макроэкономических данных и истории прежних корректировок; подготовка отнимает время, прежде чем может начаться обсуждение по существу.
- Решение: AI-агент считывает утверждённые в Банке макроэкономические сценарии, прежние решения по корректировке и их обоснование, а также текущие выходные данные модели ОКУ. Он готовит структурированный документ с исходными данными для калибровки (текущие параметры макроэкономического сценария, сравнение с прежними допущениями корректировки, чувствительность ОКУ к изменению сценария и ключевые вопросы, требующие суждения) к ежеквартальному совещанию подразделения кредитных рисков и финансового подразделения по пересмотру корректировки.
- Критерии приёмки: Подразделение кредитных рисков и финансовое подразделение начинают ежеквартальный пересмотр макроэкономической корректировки с документа с исходными данными для калибровки, подготовленного AI-агентом (текущие параметры сценария, сравнение с прежними допущениями корректировки, чувствительность ОКУ к изменению сценария и ключевые вопросы, требующие суждения), и не тратят время аналитиков на подготовку.

| Измерение | Ключевой результат |
| --- | --- |
| Внедрение | В первые 18 месяцев после запуска AI-агент готовит документ с исходными данными для калибровки не менее чем к четырём ежеквартальным пересмотрам корректировки подряд; при каждом запуске он использует утверждённые макроэкономические сценарии, прежние решения по корректировке и текущие выходные данные модели ОКУ. |
| Принятие | ≥80% документов с исходными данными для калибровки подразделение кредитных рисков и финансовое подразделение принимают как основу для обсуждения корректировки без дополнительной подготовки аналитиками; ≥75% поставленных ключевых вопросов участники совещания признают относящимися к делу. |
| Цикл | Документ с исходными данными для калибровки поступает не позднее чем за три рабочих дня до ежеквартального совещания по пересмотру корректировки; при прежнем подходе аналитик по кредитному риску готовил материалы не менее недели. |

### Анализ распределения по стадиям для расчёта ОКУ

- URN: urn:financial-services:scenario:risk-control/credit-risk/ecl-ifrs9-provisions/ecl-staging-distribution-analysis
- Аспект: Аналитика
- Сложность: M
- Назначение: AI-агент ежеквартально отслеживает изменения распределения по стадиям 1, 2 и 3 по портфелям, выявляет тенденции на уровне сегментов, не согласующиеся с макроэкономической обстановкой, и до ежеквартального рассмотрения ОКУ направляет анализ распределения директору по кредитным рискам.
- Решаемая задача: Изменения распределения по стадиям отражаются в ежеквартальной пояснительной записке по МСФО (IFRS) 9, но на согласованность с макроэкономическими сигналами и сигналами портфеля не анализируются. Если объём кредитов в стадии 2 сокращается при ухудшении макроэкономической обстановки или кредиты стадии 2 сосредотачиваются в отдельном сегменте, это может означать, что критерии значительного увеличения кредитного риска нужно перекалибровать; по одной сводной записке такой сигнал не виден.
- Решение: AI-агент считывает ежеквартальные данные о распределении по стадиям по сегментам и продуктам, рассчитывает тенденции изменений и сопоставляет их с макроэкономическими индикаторами и сигналами о кредитном качестве портфеля. Он отмечает распределения, не согласующиеся с макроэкономической обстановкой, и направляет анализ директору по кредитным рискам до ежеквартального рассмотрения модели ОКУ и макроэкономической корректировки.
- Критерии приёмки: До рассмотрения ОКУ директор по кредитным рискам получает ежеквартальный анализ распределения по стадиям — изменения по стадиям 1, 2 и 3 по сегментам и продуктам в сопоставлении с макроэкономическими индикаторами и сигналами о кредитном качестве портфеля — с отметками о распределениях, не согласующихся с макроэкономической обстановкой.

| Измерение | Ключевой результат |
| --- | --- |
| Внедрение | В первые 18 месяцев после запуска AI-агент готовит анализ распределения по стадиям не менее четырёх кварталов подряд; с момента запуска каждый анализ охватывает все сегменты портфеля и продукты. |
| Принятие | ≥70% распределений, отмеченных AI-агентом, директор по кредитным рискам признаёт требующими изучения; по отмеченной AI-агентом закономерности инициируется не менее одного пересмотра критериев значительного увеличения кредитного риска в год. |
| Цикл | Анализ поступает не позднее чем за пять рабочих дней до ежеквартального рассмотрения модели ОКУ и макроэкономической корректировки; при прежнем подходе изменения по стадиям на согласованность не анализировались, была только сводная записка. |
