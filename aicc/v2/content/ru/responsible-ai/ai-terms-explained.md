Здесь простыми словами объяснены технологические термины, которые встречаются в разделе «Ответственный AI». Термины процесса работы Хаба собраны в общем [словаре](page:reference/vocabulary).

## Виды систем {#systems}

| Термин | Что это значит |
| --- | --- |
| Искусственный интеллект, AI | Машинная система, которая по входным данным формирует прогноз, контент, рекомендацию или решение для достижения заданных целей. Такое определение используют ОЭСР и ЕС |
| Модель | Закономерность, найденная при обучении: функция, которая превращает входные данные в результат. И скоринговая карта, и языковая модель — это модели |
| [[machine-learning|Машинное обучение]] | Способ построить модель на примерах, а не прописывать её правила вручную |
| [[llm|Большая языковая модель]] | Модель, которую на очень больших массивах текстов обучили предсказывать следующий фрагмент; основа генеративного AI для работы с языком |
| [[generative-ai|Генеративный AI]] | AI, который создаёт контент — текст, изображения, код, — а не только прогноз или класс |
| Ассистент | Приложение, которое помогает пользователю ответами, предложениями или черновиками, но само не выполняет действий в системах |
| [[ai-agent|AI-агент]] | Система, в которой модель сама выстраивает шаги для достижения цели и действует через инструменты: получает данные, вызывает сервисы, заполняет формы |

## Создание и использование {#building}

| Термин | Что это значит |
| --- | --- |
| [[fine-tuning|Дообучение]] | Дополнительное обучение готовой модели на данных конкретной задачи |
| [[prompt|Запрос к модели]] | Инструкции и контекст, которые модель получает в момент использования; системный запрос — постоянная инструкция от разработчика |
| [[context-window|Контекстное окно]] | Объём текста, который модель учитывает одновременно; того, что не поместилось, она не видит |
| [[token|Токен]] | Единица текста для языковой модели: слово или его часть; в токенах считают затраты и лимиты |
| [[rag|Ответы с опорой на поиск по документам]] | В момент вопроса модель получает подходящие фрагменты проверенных документов и отвечает по ним со ссылками |
| [[grounding|Опора на источники]] | Привязка ответов модели к проверенным источникам, чтобы их можно было перепроверить |
| [[evaluation-set|Оценочный набор]] | Случаи из практики с ожидаемыми результатами; по ним проверяют решение до запуска и после каждого заметного изменения |
| [[guardrails|Защитные механизмы]] | Правила, фильтры и ограничения вокруг модели: на что ей можно отвечать и какие действия ей разрешены |
| [[human-in-the-loop|Человек в контуре]] | Сотрудник проверяет каждый результат, прежде чем его используют |
| [[human-on-the-loop|Человек над контуром]] | Человек наблюдает за системой и может вмешаться и остановить её |
| [[model-gateway|Шлюз доступа к моделям]] | Единая точка доступа к моделям: маршрутизация запросов, учёт затрат, журналы, защита данных |

## Виды сбоев {#failures}

| Термин | Что это значит |
| --- | --- |
| [[hallucination|Галлюцинация]] | Гладкий, уверенный и ошибочный результат: несуществующий факт, число или ссылка на источник |
| [[bias|Предвзятость]] | Систематическая несправедливость результатов, усвоенная из данных или заложенная при проектировании |
| [[model-drift|Дрейф]] | Ухудшение качества модели по мере того, как реальность всё больше расходится с данными, на которых её обучали |
| [[prompt-injection|Промпт-инъекция]] | Текст во входных данных, который модель выполняет как инструкцию: от пользователя напрямую или спрятанный в документе или веб-странице |
| [[jailbreak|Обход защитных ограничений]] | Специально составленный запрос, который заставляет модель забыть о защитных механизмах |
| [[data-leakage|Утечка данных]] | Данные попадают туда, где их быть не должно: к поставщику, в ответ другому пользователю, в журнал |
| [[data-poisoning|Отравление данных]] | Намеренное искажение данных, на которых учится модель, или документов, из которых она берёт сведения |
| [[excessive-agency|Избыточная самостоятельность]] | У AI-агента больше функций, прав доступа или автономности, чем нужно для его задачи |
| [[overreliance|Чрезмерное доверие]] | Люди принимают результаты, не перепроверяя их, потому что система обычно не ошибается |

## Работа с риском {#risk}

| Термин | Что это значит |
| --- | --- |
| [[responsible-ai|Ответственный AI]] | Принципы и практики, благодаря которым тот, кто применяет AI, может отвечать за его результат; подробнее — на странице [Ответственный AI](page:responsible-ai#principles) |
| [[risk-tier|Категория риска]] | Оценка того, насколько серьёзны последствия ошибки решения с AI; её определяют данные, влияние на решение, выход к клиенту и автономность |
| [[risk-based-approach|Риск-ориентированный подход]] | Меры контроля соразмерны риску; на этом построены Акт ЕС об AI, NIST AI RMF и категории риска в наших проектах |
| [[high-risk-ai|AI высокого риска]] | В Акте ЕС об AI — перечисленные в нём виды применения, в том числе кредитный скоринг физических лиц, к которым предъявляется полный набор требований |
| [[model-risk-management|Управление модельным риском]] | Давняя практика проверки, описания и наблюдения за моделями с назначенным владельцем; работа с AI распространяет её на новые системы |
| [[independent-review|Независимая проверка]] | Проверка решения человеком, который не участвовал в разработке; в средней и высокой категориях — вместе со специалистами по рискам, безопасности и правовым вопросам |
| [[explainability|Объяснимость]] | Способность объяснить, почему система выдала такой результат, так, чтобы на объяснение можно было опереться |
| [[impact-assessment|Оценка воздействия]] | Оценка того, как применение с повышенным риском повлияет на людей и их права; её проводят до запуска |
| [[model-card|Карточка модели]] | Короткое описание модели или системы: что это, для чего, как тестировали, где её не стоит применять |
| [[ai-literacy|Грамотность в области AI]] | Понимание того, что AI умеет и чего не умеет; нужна каждому, кто им пользуется |
| [[ai-incident|Инцидент AI]] | Событие, при котором применение AI причиняет или может причинить вред, включая предотвращённый вред |
| [[shadow-ai|Теневой AI]] | Инструменты AI, которыми пользуются в работе в обход инструментов, предназначенных для таких данных |

## Финансовые услуги {#fintech}

| Термин | Что это значит |
| --- | --- |
| [[kyc|Идентификация и проверка клиента]] | Установление личности клиента и оценка связанного с ним риска при оформлении и в ходе обслуживания |
| [[liveness-check|Проверка присутствия живого человека]] | Проверка того, что документ предъявляет человек, который действительно присутствует, а не его фотография или запись |
| [[alternative-data|Альтернативные данные]] | Данные помимо кредитной истории, по которым оценивают клиента: транзакционные, мобильные, поведенческие; с ними связаны вопросы справедливости и согласия |
| [[real-time-scoring|Скоринг в реальном времени]] | Оценка, которую модель выдаёт прямо во время операции, например при выявлении мошенничества |
