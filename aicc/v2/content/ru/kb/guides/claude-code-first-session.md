После этого руководства вы сможете запустить Claude Code в своём репозитории, создать файл `CLAUDE.md` с правилами проекта, дать первую небольшую задачу и проверить результат, прежде чем он попадёт в коммит.

Claude Code — ассистент для работы с кодом, который запускается в терминале прямо в папке проекта. Он читает файлы, вносит изменения, запускает команды и тесты. По сути это [[ai-agent|AI-агент]] для разработки, поэтому правило то же, что для любого агента: он действует, а вы контролируете и отвечаете за результат.

Пользуйтесь им только с одобренным в организации аккаунтом и только в тех репозиториях, где это разрешено.

## Перед первым запуском {#before}

- **Отдельная ветка.** Создайте рабочую ветку, например `git switch -c try-claude-code`. Всё, что сделает Claude, останется в ней, пока вы не проверите.
- **Никаких секретов в рабочей копии.** Claude Code читает файлы проекта, и прочитанное уходит модели вместе с запросом. Если в папке лежит, например, `.env` с настоящими паролями, сначала уберите его или закройте от чтения — как это сделать, описано в разделе [Разрешения](page:kb/guides/claude-code-setup#permissions).

## Первый запуск {#start}

1. Откройте терминал в папке репозитория.
2. Запустите `claude` и войдите под рабочим аккаунтом. Если команда не найдена, Claude Code ещё не установлен: установите его способом, одобренным в организации (официальная инструкция — в [документации на русском](https://code.claude.com/docs/ru/overview)).
3. Проверьте режим разрешений (см. «Контроль» ниже). В чувствительном репозитории сразу переключитесь в ручной режим.
4. Начните с вопроса, а не с изменения: «Расскажи, как устроен этот проект и где точка входа».
5. Выполните `/init`. Claude создаст `CLAUDE.md` — короткую памятку о проекте, которую он читает в начале каждого сеанса. Прочитайте заготовку, уберите лишнее и допишите своё: как собирать, как запускать тесты, что не трогать. Что ещё стоит туда положить — в [Настроить Claude Code под проект](page:kb/guides/claude-code-setup).

## Как давать задачу {#task}

- **Одна задача — один шаг.** «Добавь проверку пустого значения в функцию X и тест на это».
- **Говорите, как проверить.** «Запусти тесты и покажи результат».
- **Ссылайтесь на файлы.** Укажите путь к файлу или функции, о которой речь.
- **Для большого — сначала план.** «Сначала предложи план, ничего не меняя».

## Контроль {#control}

- **Режим разрешений.** Он определяет, спрашивает ли Claude перед действием; переключается клавишами Shift+Tab. В ручном режиме (Manual) Claude спрашивает перед каждой правкой и командой — читайте, что он собирается сделать, прежде чем согласиться. В новых версиях сеанс по умолчанию начинается в автоматическом режиме (Auto): действия проверяет отдельная модель и останавливает рискованные, но правильность кода она не оценивает. **Для чувствительных репозиториев выбирайте ручной режим.** Все режимы — в [Как работает Claude Code](page:kb/guides/claude-code-how-it-works#safety).
- **Ветка и diff.** Смотрите `git diff` перед каждым коммитом. Коммит и отправку делайте сами, по обычному процессу ревью кода.
- **Секреты.** Пароли, ключи и токены не должны попадать ни в запросы, ни в файлы проекта.
- **Данные клиентов.** Не вставляйте их в запросы и не используйте в тестах — тестовые данные должны быть вымышленными.
- **Ответственность.** Результат — ваш код: вы его проверяете, вы за него отвечаете.

## Попробуйте сейчас {#try}

1. В своей ветке запустите `claude` и задайте вопрос об устройстве проекта.
2. Выполните `/init`, прочитайте `CLAUDE.md` и впишите команду запуска тестов.
3. Дайте небольшую задачу с проверкой: «Добавь проверку пустого значения в функцию X, напиши на это тест и запусти тесты».
4. Посмотрите `git diff`: изменено только то, что вы просили? Тест действительно что-то проверяет?
