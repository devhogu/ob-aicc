После этого руководства вы сможете превратить обязательное правило — «не трогать `.env`», «форматировать после правки», «сообщить, когда нужен мой ответ» — в хук, который срабатывает всегда, и проверить, что он работает.

Указание в `CLAUDE.md` — это просьба: Claude обычно её выполняет, но может и упустить. Хук — это гарантия: ваша команда (обычно небольшой скрипт), которую Claude Code сам запускает в определённый момент работы, без исключений.

## Главные моменты для хуков {#events}

Событий, к которым можно привязать хук, много; вот главные:

| Момент | Когда срабатывает |
| --- | --- |
| `SessionStart` | начало или возобновление сеанса |
| `UserPromptSubmit` | вы отправили запрос, Claude его ещё не обработал |
| `PreToolUse` | перед действием Claude — может его заблокировать |
| `PostToolUse` | после успешного действия |
| `Notification` | Claude ждёт вашего ответа или разрешения |
| `Stop` | Claude закончил ответ |
| `PreCompact` / `PostCompact` | до и после сжатия контекста |

## Как настроить {#setup}

Проще всего попросить Claude: «Напиши хук, который запускает форматирование после каждой правки» или «Напиши хук, который запрещает запись в папку migrations». Хуки хранятся в файлах настроек: `~/.claude/settings.json` — ваши личные, `.claude/settings.json` — общие для проекта (в git). Команда `/hooks` показывает все настроенные хуки.

Хук получает описание события в формате JSON, а отвечает кодом выхода:

- `0` — возражений нет, работа идёт дальше;
- `2` — заблокировать действие; причину хук пишет в поток ошибок, и для многих событий она уходит Claude, чтобы он поправился;
- любой другой код — ошибка самого хука, которая **не блокирует**: действие выполнится.

Слабые места хуков при долгой работе — в [Claude Code в действии](page:kb/guides/claude-code-in-action#hook-gaps).

## Предосторожности {#safety}

- Хук — это команда на вашей машине с вашими правами. Читайте каждый хук, прежде чем включать, особенно чужой.
- Хуки из `.claude/settings.json` репозитория тоже выполняются у вас. В обычном сеансе Claude Code сначала спрашивает, доверяете ли вы папке; при запуске `claude -p` без флага `--bare` такого вопроса нет — хуки репозитория сработают сразу.
- Проверяйте пути и экранируйте входные данные: хук получает то, что прислал Claude.
- Если хук должен видеть *все* изменения файлов, учтите, что Claude может менять файлы и через команды оболочки, а не только правками. Для этого есть событие `FileChanged`.

## Попробуйте сейчас {#try}

Попросите Claude: «Напиши хук `PreToolUse` для этого проекта, который запрещает правку `.env` и файлов в `migrations/`: код выхода 2 и понятное сообщение». Прочитайте получившийся скрипт, убедитесь через `/hooks`, что хук на месте, затем попросите Claude изменить `.env` — правка должна быть заблокирована.
