Банковские данные и аналитика

Банковские данные и аналитика — управляемый слой эталонных, клиентских, транзакционных, рыночных, кредитных, риск- и регуляторных данных, которые потребляют все бизнес-функции банка. В соответствии с принципами управления данными DAMA-DMBOK, требованиями BCBS 239 к агрегированию риск-данных и отраслевой онтологией FIBO, домен определяет порядок получения, управления и предоставления авторитетных данных в масштабах предприятия. Измерения качества данных — полнота, точность, своевременность, согласованность, достоверность и уникальность — и ключевые элементы данных (CDE) с задокументированным происхождением данных лежат в основе каждого последующего решения. Возможности ИИ: автоматизация мониторинга качества данных по CDE, обогащение активов данных посредством NLP-каталогизации и картирования происхождения данных, а также предоставление самостоятельной аналитики потребителям данных — сокращение цикла от события по качеству данных до устранения, и от запроса данных до получения аналитики — с дней до часов.

Аналитика НСИ клиентов, транзакционные и рыночные данные мониторируются каждый в рамках собственного цикла доменной отчётности. Директор по данным лишён консолидированного представления об оценках качества по измерениям — полноте, точности, своевременности — по всему операционному информационному хозяйству; деградация CDE проявляется только при сбое нижестоящего аналитического процесса или при запросе о регуляторном представлении. Кросс-доменные паттерны качества, такие как дублирование НСИ клиентов, усиливающее ошибки обогащения транзакций, не обнаруживаются систематически.
Поддержка Потребители данных в командах по рискам, финансам и клиентской аналитике собирают собственные рабочие наборы данных из выгрузок систем-источников. Каталог данных банка охватывает незначительную часть производственного информационного хозяйства; недокументированные поля, неизвестное происхождение и устаревшие бизнес-определения вынуждают аналитиков восстанавливать семантику данных методом обратной инженерии до начала содержательного анализа.
Автоматизация Дедупликация золотых записей, циклы обновления справочных данных, обогащение транзакций и проверки качества рыночных данных выполняются по фиксированным, запускаемым вручную циклам. Каждый процесс следует определённому набору правил, применяемых к структурированным входным данным — паттерн повторяем и требует больших объёмов данных, что делает каждый из них кандидатом для непрерывного исполнения агентом.
Новые возможности Непрерывно управляемое операционное информационное хозяйство — золотые записи, поддерживаемые в режиме, близком к реальному времени, обогащённые транзакции, поступающие в аналитику в течение нескольких часов, оповещения о качестве рыночных данных, срабатывающие до того, как ошибки потребляются нижестоящими системами, — создаёт аналитическую инфраструктуру, позволяющую принимать более быстрые продуктовые решения, проводить более качественный кредитный андеррайтинг и предлагать более богатую клиентскую аналитику, недоступные конкурентам, работающим на пакетных циклах данных.

Рабочий процесс устранения нарушений качества данных

Агент выявляет сбои качества CDE в корпоративном каталоге данных, направляет каждый сбой ответственному стюарду данных с предзаполненным тикетом на исправление и отслеживает статус устранения для совета по управлению данными. Стюард данных устраняет первопричину проблемы; агент обеспечивает маршрутизацию, отслеживание и эскалацию при нарушении SLA. Совет по управлению данными еженедельно получает сводку открытых вопросов в разбивке по стюардам и доменам.

S
Решаемая задача

Сбои качества CDE выявляются правилами мониторинга и фиксируются в платформе качества данных, однако маршрутизация каждого сбоя ответственному стюарду и отслеживание его устранения до закрытия — это ручные операции. При задержке маршрутизации сбои накапливаются нерешёнными. Совет по управлению данными не имеет автоматического представления об открытых задачах по исправлению в промежутках между плановыми заседаниями.

Решение

Агент считывает открытые сбои качества из платформы качества данных, сопоставляет каждый сбой с ответственным стюардом из реестра CDE и создаёт предзаполненный тикет на исправление с описанием сбоя, перечнем затронутых нижестоящих отчётов и сроком по SLA. Агент отслеживает каждый тикет до закрытия и эскалирует при нарушении SLA. Еженедельная сводка открытых вопросов для совета по управлению данными формируется из того же состояния трекинга.

Критерии приёмки

Сбои качества CDE направляются ответственным стюардам данных с предзаполненными тикетами на исправление, отслеживаются до закрытия с автоматической эскалацией по SLA и еженедельно докладываются совету по управлению данными.

Внедрение

Агент направляет ≥ 95% выявленных сбоев качества правильному стюарду в течение 1 рабочего дня с момента обнаружения; еженедельная сводка открытых вопросов доставляется совету по управлению данными на протяжении ≥ 50 последовательных недель в первые 12 месяцев.

Принятие

Не менее 90% маршрутизаций тикетов подтверждены получившими стюардами как корректные; эскалации при нарушении SLA срабатывали точно в ≥ 95% случаев по итогам квартальных проверок совета по управлению данными.

Цикл

Среднее время от выявления сбоя качества до получения стюардом тикета сокращено: вместо ручных агрегационных циклов (как правило, несколько дней) — ≤ 1 рабочего дня на каждый инцидент.

Кросс-доменная позиция по качеству данных

Агент синтезирует состояние качества CDE по всем семи доменам данных — нормативно-справочные, клиентские, транзакционные, рыночные, кредитных экспозиций, риск-позиций и регуляторные — в единую исполнительную систему показателей для Директора по данным и совета по управлению данными. Деградация качества в одном домене может распространяться в нижестоящие регуляторные и риск-процессы до привлечения внимания Директора по данным к кросс-доменной картине. Директор по данным использует систему показателей для управленческой отчётности и распределения бюджета на устранение.

S
Решаемая задача

Мониторинг качества CDE работает независимо внутри каждого домена данных; у Директора по данным нет консолидированного представления по всему информационному хозяйству. Отчётность для совета директоров по качеству данных опирается на ручное агрегирование из доменных отчётов без единой базы оценки, а агрегирование проводится ретроспективно, а не в непрерывном режиме. Отсутствие кросс-доменного представления задерживает выявление Директором по данным системной деградации качества.

Решение

Агент считывает метрики качества CDE со всех платформ доменного мониторинга — оценки полноты, точности, своевременности и согласованности по доменам — и формирует кросс-доменную систему показателей позиции качества. Он ранжирует домены по общему состоянию CDE, выявляет наиболее серьёзные деградации по всему хозяйству и формирует нарратив по качеству данных для совета директоров с трендовым анализом за три предшествующих цикла. Директор по данным представляет систему показателей на совете по управлению данными и использует её как основу для распределения бюджета на устранение.

Критерии приёмки

Директор по данным и совет по управлению данными располагают консолидированным, непрерывно обновляемым представлением о позиции качества по всем семи доменам данных, обеспечивая распределение бюджета на устранение и отчётность для совета директоров из единого оценённого источника.

Внедрение

Агент формирует кросс-доменную систему показателей качества для ≥ 12 последовательных ежемесячных циклов совета по управлению в первый год; все семь доменов данных включены в каждый цикл.

Принятие

≥ 85% наиболее серьёзных деградаций доменов, отмеченных агентом, оценены Директором по данным как требующие приоритетного устранения; нарративы по качеству данных для совета директоров приняты без существенной правки в ≥ 80% циклов.

Цикл

Время подготовки кросс-доменной системы показателей сокращено с ручного многодоменного агрегирования (обычно 1–2 недели) до ≤ 1 рабочего дня в ежемесячный цикл.

Кросс-функциональная таксономия обращений

Агент сопоставляет метки обращений из систем клиентского обслуживания, операционного блока, риск-менеджмента и работы с претензиями с унифицированной таксономией посредством семантического анализа, позволяя менеджменту запрашивать кросс-функциональные паттерны проблем без ручных упражнений по согласованию. CDO и COO используют кросс-функциональный дашборд для принятия операционных решений. Команда управления данными поддерживает унифицированную таксономию как каноническое справочное руководство.

M
Решаемая задача

Каждая бизнес-функция маркирует обращения в рамках собственной таксономии: отказ авторизации регистрируется как «Отклонение карты» в клиентском обслуживании, «Ошибка авторизации» в операционном блоке, «Требуется расследование мошенничества» в риск-менеджменте и «Проблема с карточным обслуживанием» в службе работы с претензиями. Кросс-функциональный анализ общеорганизационных паттернов проблем требует периодических ручных упражнений по согласованию. У менеджмента нет непрерывного представления о паттернах обращений в разрезе функций.

Решение

Агент читает данные об обращениях из систем клиентского обслуживания, операционного блока, риск-менеджмента и работы с претензиями и сопоставляет каждую метку с унифицированной таксономией посредством семантического анализа текста метки и описаний обращений. Формируется кросс-функциональный дашборд с частотой проблем и паттернами урегулирования по унифицированным категориям. Команда управления данными поддерживает таксономию; дашборд обновляется на непрерывной основе по мере классификации новых обращений.

Критерии приёмки

CDO и COO получают доступ к кросс-функциональному дашборду обращений, который с помощью агентного семантического анализа сопоставляет метки клиентского обслуживания, операционного блока, риск-менеджмента и работы с претензиями с унифицированной таксономией, обеспечивая мониторинг паттернов проблем в масштабе всей организации без ручного согласования.

Внедрение

Агент непрерывно сопоставляет метки обращений с унифицированной таксономией, охватывая все четыре функции-источника с момента запуска; дашборд обновляется в течение 24 часов после новой классификации обращений для ≥ 95% объёма обращений в течение 12 месяцев.

Принятие

≥ 85% кросс-функциональных сопоставлений таксономии подтверждены командой управления данными как точные при ежеквартальной валидации таксономии; запросы менеджмента по кросс-функциональным паттернам выполняются без дополнительного ручного согласования в ≥ 80% случаев.

Цикл

Цикл анализа кросс-функциональных паттернов проблем сокращён с периодических ручных упражнений по согласованию (как правило, ежемесячных или ежеквартальных) до непрерывного дашборда, обновляемого в течение 24 часов.

Реестр API доменов data mesh

Агент ведёт поисковый реестр API продуктов данных, публикуемых доменными командами, формируя описания интерфейсов, руководства по использованию и сводки SLA на основе API-схем и телеметрии использования. Потребители данных по всему банку обращаются к реестру на естественном языке для выбора подходящего продукта данных под конкретный сценарий. CDO отслеживает зрелость и уровень использования доменных продуктов данных через реестр.

M
Решаемая задача

По мере публикации доменными командами продуктов данных через API у потребителей нет надёжного способа обнаружить доступные продукты, понять смысл их схем или выяснить взятые на себя обязательства по качеству. Обнаружение опирается на экспертные сети и ситуативные знания, что ограничивает внедрение доменных продуктов данных за пределами команды-создателя. У директора по данным (CDO) нет консолидированного представления о зрелости продуктов данных в разрезе доменного ландшафта.

Решение

Агент читает определения API-схем, телеметрию конечных точек и журналы SLA, публикуемые доменными командами, и формирует человекочитаемую запись реестра для каждого продукта данных: доступные конечные точки, определения полей, гарантии актуальности и исторические показатели соблюдения SLA. Потребители направляют запросы к реестру на естественном языке; CDO использует его для оценки уровня внедрения и зрелости доменных продуктов данных. Записи реестра обновляются по мере изменения схем и телеметрических данных.

Критерии приёмки

Потребители данных по всему банку находят и оценивают доменные продукты данных через поисковый реестр, который агент поддерживает на основе API-схем и телеметрии использования; описания интерфейсов, рекомендации по применению и сводки SLA доступны через запросы на естественном языке.

Внедрение

Реестр охватывает ≥ 90% опубликованных API доменных продуктов данных в течение 12 месяцев; записи реестра обновляются в течение 48 часов после изменения схемы или телеметрии для ≥ 95% продуктов.

Принятие

≥ 80% запросов на естественном языке возвращают корректную ссылку на продукт данных по оценке команды управления данными CDO; сводки SLA валидированы по данным телеметрии поставщика в ≥ 90% записей.

Цикл

Самообслуживание корпоративных данных

Агент отвечает на вопросы руководства и аналитиков на естественном языке, обращаясь к массиву данных банка — слоям хранилища BI и записям операционных систем. Каждый ответ подкреплён источниками и воспроизводим; к ответу прилагаются определения метрик и родословная данных. CDO управляет областью охвата, контролем доступа и семантическим слоем, стандартизирующим определения метрик в масштабе всего массива данных.

L
Решаемая задача

Топ-менеджеры и аналитики направляют структурированные и разовые запросы, требующие выборки из нескольких систем; ответ поступает через несколько дней в виде отчёта или единоразовой выгрузки. Стратегические решения принимаются на неполных данных, когда цикл получения данных превышает окно принятия решения. Мощности команды данных расходуются на задачи получения информации, не требующие профессиональных суждений.

Решение

Агент принимает вопрос на естественном языке, выбирает подходящий источник — хранилище BI для стандартных метрик, API операционных систем для актуальных позиций и рисков — и выполняет запрос в режиме одобренного доступа только на чтение. Многоэтапные вопросы декомпозируются и разрешаются через несколько систем в рамках одного сеанса взаимодействия. Ответ включает применённую логику запроса, определения метрик и ссылку на родословную данных.

Критерии приёмки

Руководители и аналитики получают ответы на вопросы к массиву данных банка в рамках одной рабочей сессии; каждый ответ подкреплён источниками, воспроизводим и привязан к определениям метрик и родословной данных в рамках контроля доступа, управляемого CDO.

Внедрение

Агент обрабатывает ≥ 200 запросов руководителей и аналитиков в месяц в течение 12 месяцев после запуска; источники из хранилища BI и API операционных систем оба активны в промышленной эксплуатации.

Принятие

Не менее 85% ответов на запросы приняты пользователями как аналитически корректные без ручного пересчёта; ссылки на определения метрик и родословную данных признаны верными в ≥ 90% выборочных ответов.

Цикл

Время от подачи вопроса до получения ответа сокращено: вместо нескольких дней (цикл заявки в команду данных) — ≤ 30 минут на запрос в рамках одной рабочей сессии.
