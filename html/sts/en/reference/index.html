ITIL 4

ITIL Service Value System

Model
service-value-system
Behavior
system-map

System-level ITIL 4 reference model. Component names are represented; approved descriptions are not loaded.

  1. 01 Opportunity and Demand input

    The outside pull on the service system: business opportunities, customer needs, user demand, incidents, requests, risks, and improvement signals that require a response.

  2. 02 Guiding Principles component

    Decision principles that help teams adapt service management without losing alignment, value focus, or practical judgment.

  3. 03 Governance component

    Direction and control over the service system: who sets objectives, evaluates performance, manages risk, and ensures accountability.

  4. 04 Service Value Chain component

    The operating activity model inside the service system where plans, engagement, design, build, delivery, support, and improvement combine to create value.

  5. 05 Practices component

    Reusable management capabilities that contribute to the service value chain, not isolated documents or standalone departments.

  6. 06 Continual Improvement component

    The feedback and learning loop that keeps services, practices, and operating methods aligned with changing needs.

  7. 07 Value output

    The useful outcome created for stakeholders when the service system works: better results, lower risk, improved experience, or enabled business capability.

ITIL 4

ITIL Service Value Chain

Model
service-value-chain
Behavior
non-linear-value-chain-activity-model

ITIL 4 value-chain activity model. Activities can combine differently in specific value streams; do not treat the displayed order as a mandatory workflow.

  1. 01 Plan activity

    Create shared direction for services, products, practices, resources, and improvement priorities.

  2. 02 Improve activity

    Turn feedback, evidence, incidents, risks, and changing needs into prioritized improvements.

  3. 03 Engage activity

    Understand stakeholders, demand, expectations, service relationships, and communication needs.

  4. 04 Design and Transition activity

    Shape new or changed services so they are fit to operate, support, secure, and improve.

  5. 05 Obtain/Build activity

    Acquire, build, configure, or integrate the components needed for services and products.

  6. 06 Deliver and Support activity

    Run services in use, support users, handle requests and incidents, and maintain agreed service experience.

Reference relationships

No explicit edge has been loaded for this model yet.

Value streams

IT4IT Digital Product Lifecycle

Model
digital-product-lifecycle
Behavior
value-stream-model

IT4IT 3.x value-stream model represented as the current digital product lifecycle view.

  1. 01 Evaluate Evaluate

    Assess the digital product portfolio, investment choices, performance, value, and rationalization needs so portfolio decisions stay aligned to strategy and outcomes.

  2. 02 Explore Explore

    Shape new or changed digital product ideas into product direction, design intent, backlog context, and options for delivery or optimization.

  3. 03 Integrate Integrate

    Design, build, test, configure, and integrate product changes into a releasable product release with traceable quality and control evidence.

  4. 04 Deploy Deploy

    Instantiate a product release into operating environments and maintain traceability from product release to desired and actual product instances.

  5. 05 Release Release

    Publish new or changed service offers so consumers can understand, request, subscribe to, and use the digital product capability.

  6. 06 Consume Consume

    Enable consumers to order, receive, access, and use service offers through fulfilled requests, subscriptions, service contracts, and consumption records.

  7. 07 Operate Operate

    Run actual product instances within agreed expectations by monitoring health, handling events and incidents, maintaining service performance, and feeding improvement.

Capabilities behind the journey

Practice Catalogue

Use the catalogue as the recognized ITIL vocabulary for capabilities that participate in the service journey. It is not a process sequence by itself.

Practice group

General Management Practices

Enterprise management capabilities that shape direction, risk, people, suppliers, information, money, and relationships around services.

Practice group

Service Management Practices

Service-specific capabilities used to design, operate, support, improve, and control the services consumed by users and customers.

Practice group

Technical Management Practices

Technology delivery and platform capabilities that build, deploy, operate, and sustain the technical components behind services.

Model Construct

Guidance Questions

The questions that turn the database into a guiding system rather than passive storage.

Operating model

Framework

The top-level operating-model frame that explains the purpose, scope, and navigation logic of STS.

Define what operating model is being explored, why it exists, and what learning path it gives to the reader.

  • What operating model is being defined and what is intentionally outside its scope?
  • What learning path should a reader follow from high-level concept to practical artifact?

Navigation root

Model Root

Top-level STS model entry point.

Use model roots to separate the outer operating model from the inner managed service model.

  • Does this root explain the STS ecosystem or the internal structure of one service?
  • How does this root connect to ITIL practices, IT4IT value streams, SRE, DevSecOps, and tooling views?

Model domain

Model Domain

A major domain inside a model root.

Use model domains to give each root a practical drill-down structure before detailed workflows are modeled.

  • Which operating concern or managed service anatomy area does this domain organize?
  • Which services, managed elements, cycles, artifacts, evidence, metrics, or owners belong under this domain?

ITIL grouping

Practice Group

A recognized family of practices used to organize ITSM concerns at the highest level.

Use practice groups to orient readers before they drill into individual practices.

  • What family of operating concerns does this group hold?

ITSM practice

Practice

A recognized management concern such as Change Enablement, Incident Management, or Service Catalogue Management.

Each practice can later decompose into workflow variants, buckets, artifacts, discipline mappings, and maturity targets, but the current reference node must preserve the external practice meaning.

  • What outcome must this practice achieve in the service-management reference context?
  • Which workflow variants, buckets, artifacts, and decisions are required to make this practice real?

Behavior model

Flow Model

A lifecycle, value-chain, value-stream, or system model that explains runtime behavior beyond a catalogue list.

Check whether the model is a strict workflow, a value stream, a system map, or a non-linear activity model before drawing sequence arrows.

  • Which reference model defines this flow model?
  • Is this a workflow, lifecycle, value chain, value stream, system map, or state model?

System component

Flow Component

A structural component inside a system-level model.

Use for system positioning, inputs, outputs, governance components, or reference components that are not workflow activities.

  • What role does this component play in the reference system model?

Activity

Flow Activity

An activity inside a lifecycle or value-chain model.

Use for named activities where the reference framework defines behavior, not just taxonomy.

  • Is this activity ordered, iterative, optional, or combined differently per value stream?

Value stream

Value Stream

A named stream of work, information, or value movement across a management lifecycle.

Use for externally defined value streams. Local value streams are deferred and must be explicitly labeled when introduced.

  • What value or information movement does this stream represent?
