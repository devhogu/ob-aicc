Model Roots

Start with the STS Operating Model for the shared-services ecosystem, then use the STS Managed Service Model to look inside one service.

Outer model

STS Operating Model

How STS is run across the ecosystem of shared technology services.

The operating model treats each shared service as a portfolio and governance unit. It defines scope, ownership, standards, tooling, service onboarding, funding, assurance, and improvement across many services.

  1. 01 Service Portfolio And Adoption

    Defines service intake, onboarding, catalog inclusion, lifecycle status, adoption signal, and cross-service visibility.

  2. 02 Ownership, Governance, And Standards

    Defines common decision rights, service ownership expectations, standards, exception handling, assurance needs, and operating guardrails.

  3. 03 Platform And Automation Enablement

    Defines catalog, templates, CI/CD, infrastructure automation, observability links, policy checks, evidence capture, and reusable standard paths.

  4. 04 Operations, Reliability, And Assurance

    Defines support paths, SLO expectations, incident and problem loops, continuity expectations, operational evidence, and service review cadence.

  5. 05 Portfolio Economics And Improvement

    Defines budget signals, cost drivers, usage, capacity, value evidence, improvement backlog, and investment prioritization across the STS portfolio.

Inner model

STS Managed Service Model

How one shared service is decomposed, understood, and managed.

The managed service model decomposes one service into managed service elements, then maps operating cycles, ITIL practices, artifacts, evidence, ownership, metrics, and maturity to those elements.

  1. 01 Service Definition

    Groups service identity, purpose, owner, criticality, tier, status, consumers, scope, and service expectations.

  2. 02 Consumer Interface

    Groups service offerings, request types, consumers, subscriptions, provisioned instances, support entry points, and usage expectations.

  3. 03 Delivery Structure

    Groups components, repositories, deployment units, releases, versions, configurations, templates, pipelines, and deployment evidence.

  4. 04 Runtime Structure

    Groups runtime instances, environments, dependencies, health signals, capacity signals, alerts, incidents, problems, and recovery context.

  5. 05 Control And Learning

    Groups controls, risks, exceptions, evidence, knowledge items, cost signals, improvement items, deprecation, migration, and retirement targets.
