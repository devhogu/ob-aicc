Нормативно-справочные данные — это эталонный общебанковский слой общих записей о сущностях: золотые записи о клиентах, контрагентах, продуктах и счетах, а также таблицы кодов и иерархии справочников, благодаря которым эти записи одинаково понимаются во всех системах. Работа с ними ведётся в рамках программы управления основными данными (MDM), выстроенной в соответствии с DAMA-DMBOK и отраслевой онтологией финансовых услуг FIBO. Эта область определяет эталонную версию каждой сущности: кто является клиентом, к какому юридическому лицу относится контрагент, какой регуляторной классификации соответствует код продукта. Надзорные ожидания в области управления данными предполагают, что у критически важных элементов данных (CDE) в основных и справочных данных есть задокументированное происхождение, правила качества и ответственный ответственный за данные. Генеративный AI позволяет автоматизировать устранение дублей в золотых записях, непрерывно отслеживать показатели качества CDE и вести каталог данных с автоматическим обогащением средствами обработки естественного языка (NLP) — и тем самым поддерживать точность и полноту основных данных между плановыми циклами работ по управлению данными.

Проблемы

Основные данные клиентов и продуктов

Аспект Проблема
Аналитика Полноту золотых записей и долю неустранённых дублей измеряют в ходе периодических кампаний по качеству данных, которые проводит подразделение управления данными. Между кампаниями директор по данным не видит, как в основных данных клиентов и контрагентов накапливаются дубли и ухудшается качество полей. Надёжность слоя основных данных оценивается задним числом, когда одна из последующих систем сообщает о несогласованных данных.
Поддержка Ответственные за данные, отвечающие за основные данные клиентов, контрагентов и продуктов, тратят значительную часть времени на ручное устранение дублей: просматривают пары кандидатов на совпадение, которые формируют инструменты вероятностного сопоставления, разбирают пограничные случаи и документируют, какие записи объединены и почему. Нагрузку увеличивают объём новых записей, поступающих по всем каналам, и разнообразие транслитераций имён между системами письма, например кириллицей и латиницей.
Автоматизация Формирование кандидатов на устранение дублей, применение правил качества CDE и обновление справочных таблиц подчиняются заданной логике, которая применяется к структурированным основным данным. Каждый из этих процессов повторяется, основан на правилах и связан с большими объёмами, поэтому его можно поручить AI, оставив ответственному за данные разбор исключений.
Новые возможности Постоянно точные основные данные клиентов и контрагентов снижают затраты на повторную проверку идентификации и проверки клиента (KYC), устраняют риск потери выручки из-за исключения дублирующихся счетов из маркетинговых кампаний и повышают точность кредитных решений, поскольку агрегирование рисков по связанным лицам опирается на выверенную иерархию сущностей.

Ведение золотых записей

Единая эталонная запись о каждом клиенте, контрагенте, юридическом лице и продукте. Её ведут процессами MDM: записи из нескольких систем-источников идентифицируются, сопоставляются, объединяются и по правилам приоритета источников сводятся в эталонную основную запись. На золотую запись опираются соблюдение требований идентификации и проверки клиента (KYC), агрегирование кредитных рисков и клиентская аналитика. Там, где имена пишутся в нескольких системах письма, например кириллицей и латиницей, транслитерации, частое использование альтернативных имён и большое число каналов оформления клиентов создают структурно высокую нагрузку по устранению дублей, с которой периодические ручные кампании полностью не справляются.

Аудит соблюдения правил приоритета источников

  • Аспект: Аналитика
  • Сложность: S
  • Назначение: AI-агент проводит аудит золотых записей в системе управления основными данными (MDM-системе) и находит записи, в которых применённая логика приоритета источников дала результат, расходящийся с задокументированными правилами: например, система-источник с меньшим приоритетом заполнила критически важный элемент данных (CDE), хотя в источнике с большим приоритетом было непустое значение. По отчёту аудита подразделение управления данными выявляет отклонения от правил, исправляет затронутые золотые записи и корректирует настройки MDM-системы там, где правила применялись неверно.
  • Решаемая задача: Правила приоритета источников определяют, значение какой системы-источника принимается для каждого CDE, когда данные в золотую запись поступают из нескольких систем. На практике применение этих правил в MDM-системе может отклоняться от задокументированной политики из-за изменений настроек, подключения новых систем-источников или нарушения порядка загрузки данных. Систематически такое расхождение не выявляется: аудиторы и пользователи данных обнаруживают его, когда значение CDE в золотой записи отличается от ожидаемого значения из приоритетного источника.
  • Решение: AI-агент считывает золотые записи из MDM-системы, получает значения каждого CDE из всех систем-источников и сравнивает значение в золотой записи с результатом, который должен получиться по задокументированной иерархии приоритета источников. Записи, где фактический результат расходится с правилом, отмечаются с указанием затронутого CDE, значения в золотой записи, значения из источника, которому правило отдаёт приоритет, и величины расхождения. Подразделение управления данными ежеквартально рассматривает результаты аудита, исправляет затронутые золотые записи и корректирует настройки MDM-системы, если выявлено систематическое отклонение от правил.
  • Критерии приёмки: Золотые записи в MDM-системе соответствуют задокументированным правилам приоритета источников; отклонения от правил и ошибки настройки выявляются регулярным аудитом и исправляются в рамках цикла управления основными данными.
Измерение Ключевой результат
Внедрение В первый год AI-агент не менее четырёх кварталов подряд готовит ежеквартальные отчёты аудита правил приоритета источников, охватывающие 100% действующих золотых записей и CDE; схему иерархии приоритета источников подразделение управления данными утверждает не позднее 60 дней с даты запуска.
Принятие ≥80% отметок о расхождении подразделение управления данными подтверждает как реальные отклонения от правил или ошибки настройки; в ≥85% случаев золотые записи исправляются не позднее двух недель с даты передачи отчёта аудита.
Цикл Вместо разовых проверок, к которым приводили замечания аудита, соблюдение правил приоритета источников ежеквартально контролируется по единой схеме; систематические отклонения в настройках MDM-системы выявляются и исправляются в том же квартале, в котором возникли.

Сверка иерархии юридических лиц

  • Аспект: Поддержка
  • Сложность: S
  • Назначение: AI-агент сверяет иерархию юридических лиц в MDM-системе с доступными внешними источниками — записями реестров юридических лиц и регуляторной отчётностью компаний, классифицируя связи по типам отношений FIBO, — и находит юридические лица без указанной материнской компании, с неверной классификацией владения или со связями, которые противоречат данным внешних реестров. По отчёту о сверке подразделение управления данными исправляет иерархию до следующего цикла агрегирования рисков по группам связанных контрагентов.
  • Решаемая задача: Иерархии юридических лиц в MDM-системе строятся по данным идентификации и проверки клиента (KYC), собранным при оформлении клиентов, и поддерживаются периодическими ручными пересмотрами. Вновь созданные дочерние компании, реорганизация групп и изменения бенефициарного владения могут не отражаться в дереве юридических лиц до следующего ручного пересмотра. Требования по крупным рискам опираются на актуальные иерархии групп связанных лиц: устаревшая или неполная иерархия в MDM-системе напрямую переходит в агрегирование рисков по группе и может занижать использование лимитов крупных рисков.
  • Решение: AI-агент считывает иерархию юридических лиц из MDM-системы и сверяет связи материнских и дочерних компаний и сведения о владении с данными реестров компаний (официальных реестров юридических лиц) и доступной регуляторной отчётностью, классифицируя каждую связь по типам отношений FIBO. Юридические лица, иерархия которых в MDM-системе расходится с данными внешних реестров (нет дочерней компании, устарела доля владения или указанная материнская компания противоречит записям реестра), отмечаются с указанием конкретного расхождения и внешнего источника. Подразделение управления данными рассматривает результаты сверки и обновляет иерархию в MDM-системе до следующего расчёта агрегированных рисков по группам.
  • Критерии приёмки: Иерархия юридических лиц в MDM-системе соответствует актуальным данным внешних реестров; расхождения выявляются и исправляются до каждого цикла агрегирования рисков по группам связанных контрагентов.
Измерение Ключевой результат
Внедрение В первый год AI-агент не менее 12 месяцев подряд готовит ежемесячные отчёты о сверке иерархии юридических лиц; внешние реестры подключаются как источники данных не позднее 60 дней с даты запуска.
Принятие ≥80% отмеченных расхождений в иерархии подразделение управления данными подтверждает как требующие исправления; в ≥85% случаев иерархия в MDM-системе исправляется до следующего агрегирования рисков по группам.
Цикл Вместо периодических ручных пересмотров иерархия юридических лиц ежемесячно сверяется автоматически; с момента запуска риски по группам агрегируются по актуальной иерархии.

Устранение дублей в золотых записях MDM

  • Аспект: Автоматизация
  • Сложность: M
  • Назначение: AI-агент находит дублирующиеся записи о клиентах и юридических лицах в системах-источниках с помощью вероятностного сопоставления средствами NLP по вариантам написания имён, транслитерациям и пропускам в идентификаторах и еженедельно передаёт ответственному за данные кандидатов на объединение. Там, где имена пишутся в нескольких системах письма, например кириллицей и латиницей, из-за вариантов транслитерации и частых альтернативных имён периодических кампаний по устранению дублей недостаточно. Золотая запись в MDM-системе обновляется после одобрения ответственного за данные.
  • Решаемая задача: В основных данных клиентов в автоматизированной банковской системе (АБС), CRM и системе идентификации и проверки клиента (KYC) накапливаются дублирующиеся и несогласованные записи по мере того, как клиентов и контрагентов оформляют через разные каналы и продукты. Ответственные за данные устраняют дубли в ходе периодических кампаний по качеству данных, и между циклами золотая запись устаревает. Там, где это встречается, транслитерации между системами письма, практика использования альтернативных имён и неполный охват налоговыми идентификаторами увеличивают объём работы сверх того, с чем справляются кампании.
  • Решение: AI-агент считывает записи о сущностях из всех систем-источников и выполняет вероятностное сопоставление по вариантам написания имён, транслитерациям, налоговым идентификаторам и адресным полям, формируя кандидатов на объединение с оценкой достоверности. Ответственный за данные рассматривает совпадения с высокой оценкой и разбирает пограничные случаи; золотая запись в MDM-системе обновляется еженедельно. Кандидаты с более низкой оценкой не объединяются автоматически, а ставятся в очередь на рассмотрение ответственного за данные.
  • Критерии приёмки: Золотые записи о клиентах и юридических лицах в MDM-системе еженедельно поддерживаются в точном состоянии: AI выполняет вероятностное устранение дублей по вариантам имён, транслитерациям и пропускам в идентификаторах, записи объединяются с одобрения ответственного за данные, а кандидаты с более низкой оценкой достоверности рассматриваются в отдельной очереди.
Измерение Ключевой результат
Внедрение В первые 12 месяцев AI-агент не менее 48 недель еженедельно формирует кандидатов на устранение дублей по всем системам-источникам; сопоставление по транслитерациям и альтернативным именам работает с момента запуска для всех клиентов и юридических лиц.
Принятие ≥80% кандидатов с высокой оценкой достоверности объединяются с одобрения ответственного за данные в том же еженедельном цикле; точность золотых записей после объединения подтверждается на уровне ≥95% при оценке качества основных данных, которая проводится раз в полгода.
Цикл Вместо периодических кампаний (раз в квартал или реже) дубли устраняются в непрерывном еженедельном цикле; не позднее шести месяцев с даты запуска в очереди остаются только кандидаты, накопленные не более чем за две недели.

Справочники и таблицы кодов

Общие иерархии справочников и таблицы кодов — коды стран и валют, иерархии классификации продуктов, отраслевые коды, типы инструментов по регуляторной классификации и внутренние организационные иерархии, — благодаря которым атрибуты сущностей одинаково понимаются во всех системах. Справочные данные используются в каждом процессе отчётности и аналитики. Когда меняется регуляторная таксономия (появляется новый код продукта или меняется отраслевая классификация), влияние изменения на последующие системы нужно проследить и одинаково отразить во всех системах, использующих справочник, до следующего отчётного цикла.

Распространение изменений справочной таксономии

  • Аспект: Оптимизация
  • Сложность: S
  • Назначение: Когда публикуется изменение регуляторной таксономии — новый код продукта или изменение отраслевой классификации, — AI-агент прослеживает его влияние на все системы и процессы отчётности, использующие справочник, и до следующего цикла представления отчётности готовит карту влияния с приоритетами. По карте влияния подразделение управления данными координирует спринт по внесению изменений. Каждая система получает описание преобразования данных с соответствием старого и нового кода.

Мониторинг состояния управления CDE

  • Аспект: Аналитика
  • Сложность: S
  • Назначение: AI-агент оценивает, насколько критически важные элементы данных (CDE) во всех основных данных охвачены управлением: назначены ли ответственные за данные, утверждены ли правила качества, соблюдаются ли сроки исправления по SLA, — и ежемесячно готовит оценочную карту для директора по данным и совета по управлению данными. В оценочной карте отмечаются CDE без необходимых атрибутов управления и CDE, по которым назначения ответственных за данные или правила качества не пересматривались дольше установленного цикла. Директор по данным использует оценочную карту как основу отчётности по программе управления данными и для определения приоритетов исправления.
  • Решаемая задача: Охват CDE управлением оценивается при ежегодном обзоре программы управления данными. Между обзорами пробелы накапливаются: новые CDE добавляются без завершения регистрации в системе управления, а назначения ответственных за данные устаревают при смене ролей. У совета по управлению данными нет постоянной картины того, как ухудшается охват. Отчётность по программе для директора по данным собирается вручную из выгрузок реестра без единого показателя охвата.
  • Решение: AI-агент сверяет реестр CDE с требованиями системы управления — назначенный ответственный за данные, утверждённое правило качества, установленный SLA на исправление и дата последнего пересмотра — и ежемесячно готовит оценочную карту состояния управления по каждой предметной области CDE. CDE без необходимых атрибутов и CDE с просроченным пересмотром назначений ответственных за данные или правил качества отмечаются по предметным областям. Директор по данным представляет оценочную карту совету по управлению данными.
  • Критерии приёмки: Директор по данным и совет по управлению данными постоянно видят оценку охвата CDE управлением во всех основных данных; пробелы в назначении ответственных за данные, просроченные правила качества и нарушения SLA ежемесячно отмечаются по предметным областям.

Маршрутизация заявок на исправление CDE

  • Аспект: Автоматизация
  • Сложность: S
  • Назначение: AI-агент получает от платформы мониторинга качества данных предупреждения о нарушениях качества критически важных элементов данных (CDE), по реестру CDE определяет ответственного ответственного за данные, создаёт заранее заполненную заявку на исправление с описанием нарушения и сроком по SLA и отслеживает её до закрытия.   • Сложность: S
