Банковские данные и аналитика

ID: STF5V

Банковские данные и аналитика — это основа данных Банка: управляемый слой нормативно-справочных, клиентских, транзакционных, рыночных, кредитных, риск- и регуляторных данных, которыми пользуются все подразделения.

Банковские данные и аналитика — это основа данных Банка: управляемый слой нормативно-справочных, клиентских, транзакционных, рыночных, кредитных, риск- и регуляторных данных, которыми пользуются все подразделения. Опираясь на принципы управления данными DAMA-DMBOK, принципы BCBS 239 по агрегированию данных о рисках и отраслевую онтологию финансовых услуг FIBO, это направление определяет, как Банк получает достоверные данные, управляет ими и предоставляет их всем подразделениям. В основе каждого последующего решения лежат показатели качества данных — полнота, точность, своевременность, согласованность, допустимость и уникальность — и критически важные элементы данных (CDE) с задокументированным происхождением. Генеративный AI позволяет автоматизировать мониторинг качества CDE, обогащать информационные активы за счёт каталогизации и построения карт происхождения данных с применением обработки естественного языка (NLP) и предоставлять потребителям данных аналитику в режиме самообслуживания — так путь от выявления проблемы с качеством данных до её устранения и от запроса данных до готового вывода сокращается с нескольких дней до нескольких часов.

Проблемы

Операционные данные

Аспект Проблема
Аналитика Качество нормативно-справочных, клиентских, транзакционных и рыночных данных отслеживается в отчётном цикле каждого домена по отдельности. У директора по данным нет сводной картины оценок качества по полноте, точности и своевременности для всей совокупности операционных данных: ухудшение CDE обнаруживается, только когда даёт сбой последующий аналитический процесс или возникает вопрос к представленной регуляторной отчётности. Закономерности, охватывающие несколько доменов, например дубли в основных данных о клиентах, которые усиливают ошибки обогащения транзакций, систематически не выявляются.
Поддержка Потребители данных в подразделениях рисков, финансов и клиентской аналитики сами собирают рабочие наборы данных из выгрузок систем-источников. Каталог данных Банка охватывает лишь часть промышленных данных: из-за недокументированных полей, неизвестного происхождения и устаревших бизнес-определений аналитикам приходится восстанавливать смысл данных, прежде чем приступить к содержательному анализу.
Автоматизация Устранение дублей в золотых записях, обновление справочных данных, обогащение транзакций и проверки качества рыночных данных выполняются по фиксированному графику и запускаются вручную. Каждый из этих процессов применяет заданный набор правил к структурированным входным данным: работа повторяется и связана с большими объёмами, поэтому её можно перевести на непрерывное выполнение с применением AI.
Новые возможности Непрерывно управляемая совокупность операционных данных — золотые записи, которые обновляются почти в реальном времени, обогащённые транзакции, которые попадают в аналитику в течение нескольких часов, и предупреждения о качестве рыночных данных, которые срабатывают до того, как ошибки дойдут до последующих систем, — создаёт аналитическую инфраструктуру. С ней Банк быстрее принимает продуктовые решения, точнее проводит андеррайтинг кредитов и глубже анализирует клиентов, чем конкуренты, работающие с пакетной обработкой данных.

Сценарии

Маршрутизация нарушений качества данных и контроль их устранения

  • Аспект: Автоматизация
  • Сложность: S
  • Назначение: AI-агент получает нарушения качества CDE, которые платформа качества данных фиксирует по всему корпоративному каталогу данных, направляет каждое ответственному ответственному за данные вместе с заранее заполненной заявкой на устранение и отслеживает ход устранения для совета по управлению данными. Ответственный за данные устраняет саму проблему в данных, а AI-агент выполняет маршрутизацию, отслеживание и эскалацию при нарушении SLA. Совет по управлению данными еженедельно получает сводку открытых вопросов в разбивке по ответственным за данные и доменам.
  • Решаемая задача: Нарушения качества CDE выявляются правилами мониторинга и регистрируются в платформе качества данных, но направление каждого нарушения ответственному ответственному за данные и контроль его устранения до закрытия выполняются вручную. Если маршрутизация задерживается, неустранённые нарушения накапливаются. Между плановыми заседаниями у совета по управлению данными нет автоматически формируемой картины открытых задач по устранению.
  • Решение: AI-агент считывает открытые нарушения качества из платформы качества данных, по реестру CDE определяет ответственного ответственного за данные для каждого нарушения и создаёт заранее заполненную заявку на устранение: описание нарушения, затронутые отчёты последующих систем и срок по SLA. Ответственный за данные устраняет проблему в данных, а AI-агент отслеживает каждую заявку до закрытия и эскалирует её при нарушении SLA. Еженедельная сводка открытых вопросов для совета по управлению данными формируется по тем же данным отслеживания.
  • Критерии приёмки: Нарушения качества CDE направляются ответственным ответственным за данные с заранее заполненными заявками на устранение, отслеживаются до закрытия с автоматической эскалацией по SLA и еженедельно докладываются совету по управлению данными.
Измерение Ключевой результат
Внедрение AI-агент направляет ≥95% выявленных нарушений качества нужному ответственному за данные не позднее одного рабочего дня с даты выявления; в первые 12 месяцев еженедельная сводка открытых вопросов представляется совету по управлению данными не менее 50 недель подряд.
Принятие ≥90% заявок получившие их ответственные за данные подтверждают как назначенные верно; по итогам ежеквартального рассмотрения советом по управлению данными эскалация по SLA сработала правильно в ≥95% случаев нарушения.
Цикл Среднее время от выявления нарушения качества до получения заявки ответственным за данные — не более одного рабочего дня вместо нескольких дней при ручной маршрутизации.

Сводная оценка качества данных по всем доменам

  • Аспект: Аналитика
  • Сложность: S
  • Назначение: AI-агент сводит оценки состояния CDE по всем семи доменам данных — нормативно-справочные, клиентские, транзакционные, рыночные данные, данные о кредитных экспозициях, о рисках и позициях и регуляторные данные — в единую оценочную карту для директора по данным и совета по управлению данными. Ухудшение качества в одном домене может распространиться на последующие регуляторные процессы и процессы управления рисками раньше, чем директор по данным увидит общую картину по всем доменам. Директор по данным использует оценочную карту в отчётности о состоянии управления данными и при распределении бюджета на устранение нарушений.
  • Решаемая задача: Мониторинг качества CDE ведётся отдельно в каждом домене данных, и сводной картины по всей совокупности данных у директора по данным нет. Отчётность для Совета директоров о качестве данных собирается вручную из отчётов доменов без единой шкалы оценки, причём постфактум, а не с регулярной периодичностью. Без сводной картины по доменам директор по данным позже замечает системное ухудшение качества.
  • Решение: AI-агент считывает показатели качества CDE со всех платформ мониторинга доменов — оценки полноты, точности, своевременности и согласованности по каждому домену — и ежемесячно формирует сводную оценочную карту качества данных. Он ранжирует домены по общему состоянию CDE, выделяет наиболее серьёзные ухудшения во всей совокупности данных и готовит для Совета директоров пояснительную записку о качестве данных с анализом динамики за три предыдущих цикла. Директор по данным представляет оценочную карту совету по управлению данными и использует её как основу для распределения бюджета на устранение нарушений.
  • Критерии приёмки: Директор по данным и совет по управлению данными располагают ежемесячно обновляемой сводной оценкой качества по всем семи доменам данных и по единому источнику оценок распределяют бюджет на устранение нарушений и готовят отчётность для Совета директоров.
Измерение Ключевой результат
Внедрение В первый год AI-агент формирует сводную оценочную карту качества не менее чем для 12 ежемесячных циклов совета по управлению данными подряд; в каждый цикл включены все семь доменов данных.
Принятие ≥85% наиболее серьёзных ухудшений, отмеченных AI-агентом, директор по данным признаёт требующими первоочередного устранения; в ≥80% циклов пояснительные записки о качестве данных для Совета директоров принимаются без существенных исправлений.
Цикл Подготовка сводной оценочной карты занимает не более одного рабочего дня в ежемесячном цикле вместо ручного сведения данных по доменам, на которое обычно уходило 1–2 недели.

Единый классификатор обращений для всех подразделений

  • Аспект: Аналитика
  • Сложность: M
  • Назначение: AI-агент на основе семантического анализа сопоставляет категории обращений клиентского обслуживания, операционного блока, блока рисков и службы работы с жалобами с единым классификатором, и руководство может анализировать проблемы в масштабе всех подразделений без ручной сверки. Директор по данным и операционный директор принимают операционные решения по общему дашборду. Группа управления данными ведёт единый классификатор как основной справочник.
  • Решаемая задача: Каждое подразделение классифицирует обращения по собственной системе: один и тот же отказ в авторизации регистрируется в клиентском обслуживании как «Отклонение операции по карте», в операционном блоке — как «Сбой авторизации», в блоке рисков — как «Требуется расследование мошенничества», а в службе работы с жалобами — как «Проблема с обслуживанием карты». Чтобы проанализировать проблемы в масштабе всего Банка, категории приходится периодически сверять вручную. Постоянной картины обращений по всем подразделениям у руководства нет.
  • Решение: AI-агент считывает данные об обращениях из систем клиентского обслуживания, операционного блока, блока рисков и службы работы с жалобами и сопоставляет каждую категорию с единым классификатором на основе семантического анализа названия категории и описания обращения. Он формирует общий дашборд с частотой проблем и способами их решения по категориям единого классификатора. Группа управления данными ведёт классификатор и ежеквартально выверяет сопоставления; дашборд обновляется непрерывно по мере классификации новых обращений.
  • Критерии приёмки: Директор по данным и операционный директор пользуются общим дашбордом обращений, где категории клиентского обслуживания, операционного блока, блока рисков и службы работы с жалобами сопоставлены с единым классификатором с применением семантического анализа на основе AI, и отслеживают проблемы в масштабе всего Банка без ручной сверки.
Измерение Ключевой результат
Внедрение С момента запуска AI-агент непрерывно сопоставляет категории обращений с единым классификатором по всем четырём подразделениям-источникам; в течение 12 месяцев дашборд обновляется не позднее чем через 24 часа после классификации новых обращений для ≥95% их объёма.
Принятие ≥85% сопоставлений группа управления данными подтверждает как точные при ежеквартальной выверке классификатора; в ≥80% случаев запросы руководства о проблемах в разных подразделениях выполняются без дополнительной ручной сверки.
Цикл Вместо периодической ручной сверки (обычно ежемесячной или ежеквартальной) проблемы во всех подразделениях анализируются по непрерывно обновляемому дашборду с задержкой не более 24 часов.

Реестр API продуктов данных доменов (data mesh)

  • Аспект: Новые возможности
  • Сложность: M
  • Назначение: AI-агент ведёт реестр API продуктов данных, которые публикуют доменные команды, с поиском по нему и на основе схем API и телеметрии использования готовит описания интерфейсов, рекомендации по использованию и сводки SLA. Потребители данных во всём Банке обращаются к реестру на естественном языке, чтобы найти продукт данных под свою задачу. Директор по данным по реестру отслеживает зрелость продуктов данных доменов и их использование.
  • Решаемая задача: Доменные команды публикуют продукты данных через API, но у потребителей нет надёжного способа узнать, какие продукты существуют, что означают их схемы и какие обязательства по качеству за ними стоят. Продукты ищут через знакомых и по неписаному опыту коллег, поэтому за пределами команды-создателя ими пользуются мало. Сводной картины зрелости продуктов данных по всем доменам у директора по данным нет.
  • Решение: AI-агент считывает определения схем API, телеметрию конечных точек и журналы SLA, которые публикуют доменные команды, и для каждого продукта данных готовит понятную запись реестра: доступные конечные точки, определения полей, гарантии актуальности данных и история соблюдения SLA. Потребители обращаются к реестру на естественном языке; директор по данным по нему оценивает использование и зрелость продуктов данных доменов. Записи реестра обновляются при изменении схем и телеметрии, а группа управления данными директора по данным выверяет результаты запросов и сводки SLA.
  • Критерии приёмки: Потребители данных во всём Банке находят и оценивают продукты данных доменов по реестру с поиском, который AI-агент ведёт на основе схем API и телеметрии использования; описания интерфейсов, рекомендации по использованию и сводки SLA доступны по запросам на естественном языке.
Измерение Ключевой результат
Внедрение В течение 12 месяцев реестр охватывает ≥90% опубликованных API продуктов данных доменов; для ≥95% продуктов записи обновляются не позднее чем через 48 часов после изменения схемы или телеметрии.
Принятие ≥80% запросов на естественном языке, по оценке группы управления данными директора по данным, приводят к нужному продукту данных; в ≥90% записей сводки SLA сверены с телеметрией конечных точек и журналами SLA.
Цикл Поиск продукта данных занимает не более 5 минут в одном сеансе работы с реестром вместо расспросов коллег, на которые обычно уходило 1–3 дня.

Самостоятельный доступ к данным Банка

  • Аспект: Поддержка
  • Сложность: L
  • Назначение: AI-агент отвечает на вопросы руководителей и аналитиков, заданные на естественном языке, по всей совокупности данных Банка — от слоёв хранилища данных BI до записей операционных систем. Каждый ответ содержит ссылки на источники и воспроизводим; к нему прилагаются определения показателей и происхождение данных. Директор по данным определяет охват, права доступа и семантический слой, который унифицирует определения показателей для всей совокупности данных.
  • Решаемая задача: Руководители и аналитики задают плановые и разовые вопросы, для ответа на которые нужны данные из нескольких систем; ответ приходит через несколько дней в виде отчёта или разовой выгрузки. Если получение данных занимает больше времени, чем отведено на решение, стратегические решения принимаются на неполной информации. Время команды данных уходит на выборку данных, которая не требует профессионального суждения.
  • Решение: AI-агент принимает вопрос на естественном языке, выбирает подходящий источник — хранилище данных BI для стандартных показателей, API операционных систем для текущих позиций и экспозиций — и выполняет запрос с правами только на чтение, утверждёнными директором по данным. Сложные вопросы он разбивает на шаги и отвечает на них, обращаясь к нескольким системам в рамках одного диалога. В ответе приводятся применённая логика запроса, определения показателей и ссылка на происхождение данных, чтобы пользователь мог их проверить.
  • Критерии приёмки: Руководители и аналитики получают ответы на вопросы к данным Банка в течение того же рабочего сеанса; каждый ответ содержит ссылки на источники, воспроизводим и связан с определениями показателей и происхождением данных в рамках прав доступа, установленных директором по данным.
Измерение Ключевой результат
Внедрение В течение 12 месяцев после запуска AI-агент обрабатывает ≥200 запросов руководителей и аналитиков в месяц; в промышленной эксплуатации подключены оба источника — хранилище данных BI и API операционных систем.
Принятие ≥85% ответов запросившие их пользователи принимают как аналитически точные без ручного пересчёта; в ≥90% ответов выборки ссылки на определения показателей и происхождение данных признаны верными.
Цикл Ответ на вопрос поступает не позднее чем через 30 минут в рамках одного рабочего сеанса вместо нескольких дней ожидания по заявке в команду данных.
