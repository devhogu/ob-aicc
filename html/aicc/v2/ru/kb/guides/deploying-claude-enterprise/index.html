Внедрение Claude в организации: пять решений — полное руководство

← Все руководстваДля руководителейполное руководство35 мин

Это руководство для тех, кто решает, как Claude появится в организации: владельцев аккаунта организации, ИТ, информационной безопасности, финансов и руководителей подразделений. Оно пересказывает курс Anthropic о внедрении Claude Enterprise и сверено со Справочным центром.

Курс учит не нажатию кнопок, а суждению: какие решения принять, в каком порядке и кто их принимает. Сквозной пример курса — финтех-компания с пятью подразделениями, одно из которых работает под финансовым регулированием. Это почти наш случай.

1. Рамка: пять решений по порядку

  1. Структураорганизации, группы, удостоверения
  2. Доступкакие возможности и подключения у каких групп
  3. Управлениенавыки, плагины, проекты, инструкции
  4. Расходылимиты, модели, порядок увеличения
  5. Прозрачностьзапись, хранение, аудит, сигналы внедрения

Порядок строгий: каждое решение задаёт рамки следующим, а прозрачность измеряет результат всех четырёх.

Четыре настройки, которые трудно отменить

  • Закрепление домена (domain claiming) — необратимо.
  • Число организаций — слияние или разделение означает повторное подключение всех затронутых сотрудников.
  • Сопоставление групп каталога с ролями — изменение сразу меняет доступ всем, кого оно касается.
  • Срок хранения данных — его можно поменять, но удалённое при коротком сроке не вернуть.

Цель внедрения

Одна цель на всю организацию из двух половин: как выглядит успех и какие ограничения нельзя нарушать. В примере курса: «все пять подразделений пользуются Claude ежедневно к концу квартала — без единой эскалации по безопасности от регулируемого подразделения». И правило: если выбор ускоряет внедрение, но рискует такой эскалацией, выбирают медленный путь.

Дальше: Владельцы и подготовка →

2. Владельцы и подготовка

«Решение без владельца — один из самых быстрых способов остановить внедрение». Владельца выбирают по ответственности, а не по должности.

Решение Кто обычно решает
Структура владелец организации в Claude, команда каталога пользователей, ИТ
Доступ владелец, руководители команд; подключения с правом записи подписывает владелец риска данных
Управление владелец, команда внедрения (центр компетенций), безопасность
Расходы владелец и тот, кто распоряжается бюджетом
Прозрачность владелец и владелец риска данных (безопасность, юристы, комплаенс)

Два решения обычно выходят за пределы ИТ: расходы — к владельцу бюджета, прозрачность — к владельцу риска данных.

Обязательная подготовка

  1. Два владельца, назначенных напрямуюДо настройки единого входа — страховка от потери доступа. Основного владельца держат вне ежедневного администрирования.
  2. Единый вход включён принудительноПодключён каталог пользователей организации.
  3. Автоматическое подключение пользователейСотрудники и их группы приходят из каталога.
  4. Домен подтверждён и закреплён — последнимПосле всего остального. Даётся 30 дней на переход личных аккаунтов на корпоративном домене; сотрудников предупредить заранее.

Каждому администратору — наименее мощная роль, достаточная для его работы.

Дальше: Структура: одна организация, продуманные группы →

3. Структура: одна организация, продуманные группы

По умолчанию — одна организация. Делить стоит только если: отдельный договор с Anthropic; каталоги пользователей, которые нельзя объединить; или данные, которые по требованию регулятора или договора нужно доказуемо изолировать — и только после того, как комплаенс подтвердил, что граница организации этому требованию отвечает. Отдельные лимиты или более строгий режим для одного подразделения решаются группами, а не новой организацией.

Группы

Почти все настройки привязываются к группам, а не к людям. Хочется настройку «только для этих троих» — значит, нужна ещё одна группа.

  • Правило объединения: если человек в нескольких группах, его права суммируются; узкая группа не может отнять то, что даёт широкая.
  • Поэтому для жёсткой границы нужна отдельная группа, участники которой не входят в широкую.
  • Типичный выбор — смешанная схема: группы по подразделениям плюс отдельные группы для регулируемых функций.

Дальше: Доступ: возможности и подключения →

4. Доступ: возможности и подключения

Возможности

Чат, Cowork, Claude Code, Claude в Office — у каждой группы свой набор. Решают два уровня: переключатель организации (потолок) и права роли. Модель по умолчанию можно задать для организации и для роли.

  • Варианты: широко сначала, специализированное — по потребности; пилот, потом расширение; поэтапно после проверки.
  • В примере курса регулируемое подразделение получило Claude Code только после того, как была готова запись сессий.
  • Добавить возможность — дёшево, отобрать — дорого: у людей ломается работа.

Подключения

Три уровня разрешения: организация включает подключение, роль его получает, сотрудник подключает свой аккаунт. Claude получает права сотрудника в этой системе.

  • По умолчанию — только чтение, и только тем группам, чья работа живёт в этой системе.
  • Право записи — поэтапно и с подписью владельца риска данных. Для каждой операции записи: всегда разрешать, спрашивать или запрещать.
  • Каждое подключение объявлять при запуске; запросы на новые — владельцу доступа.

Дальше: Управление: навыки, плагины, проекты →

5. Управление: навыки, плагины, проекты

Риск — разрастание: десятки почти одинаковых навыков, непроверенные процедуры, которые все считают проверенными, проекты с чувствительными данными, открытые всей организации.

Позиция Как устроена Когда
Свободно создавать, распространять после проверки обмен внутри групп включён, публикация — через проверяющего большинство организаций
Централизованно обмен выключен, навыки раздаёт только владелец строгая среда
Полностью открыто всё включено редко
  • Для регулируемых групп — сначала одобрение, потом использование.
  • Общие инструкции организации — две-три строки о стиле и правилах: они действуют во всех разговорах.
  • Ослабить политику можно в любой момент; ужесточение не удаляет уже опубликованное — придётся пересмотреть.

Подробно о навыках и их проверке — Навыки Claude: полное руководство.

Дальше: Расходы: лимиты и рычаги →

6. Расходы: лимиты и рычаги

Три уровня лимитов: потолок организации, лимит на участника группы, личные исключения. Если человек в двух группах, настройка определяет, какой лимит действует — больший или меньший.

  • Достигнутый лимит — это пауза, а не сбой: сотрудник отправляет запрос на увеличение. Одобряют владельцы организации, а бюджетом распоряжается кто-то другой — порядок эскалации определите заранее.
  • Неизвестен профиль использования — начинайте со строгого лимита и пересчитайте по данным первого месяца, а не поднимайте мелкими шагами.
  • Исключений становится много — этим людям нужна своя группа.
  • Чат расходует мало; Claude Code и Cowork — больше на задачу.

Рычаги без изменения лимитов

  • Модель по умолчанию и уровень усилия влияют на расходы сильнее большинства изменений лимитов. Пример из курса: подразделение упёрлось в лимит, потому что самая мощная модель делала рутинные сводки; модель по умолчанию понизили — тот же объём работы уложился в прежний лимит.
  • Инструкции организации: короткие ответы, только нужные файлы, высокий уровень усилия — когда действительно нужно.
  • Навыки и проекты для повторного использования.

Обзор расходов — ежемесячно, на старте — чаще. Для регулируемой группы — отдельный обзор со своими владельцами.

Дальше: Прозрачность: запись, хранение, аудит →

7. Прозрачность: запись, хранение, аудит

Настраивается до того, как люди получат доступ. Период без записи — это время, за которое записи не будет: включение задним числом не работает.

  • Compliance API — содержимое разговоров и файлов и события аудита; включает основной владелец. Подходит ли он под конкретное регуляторное требование, решают юристы и комплаенс. Поток направляют в существующий процесс проверки безопасности с назначенным читателем: «запись, которую никто не читает, — не контроль».
  • Журналы аудита — только метаданные, без текста запросов.
  • Срок хранения — по умолчанию бессрочно; минимальный свой срок — 30 дней; настройка на всю организацию. Сократить срок — значит стереть историю, поэтому договоритесь о сроке один раз и заранее.
  • Проверка запросов (inference hooks, бета, Enterprise) — каждый запрос перед ответом уходит на сервер безопасности организации, например для защиты от утечек.

Чего нет в курсе, но есть в Справочном центре: собственный срок хранения не применяется к Claude Tag, Claude Design, управляемым агентам и облачным функциям Claude Code; Compliance API не охватывает облачные сессии Claude Code и доступ через облачных провайдеров. Это нужно учитывать при оценке.

Дальше: Сигналы внедрения →

8. Сигналы внедрения

Охват и глубина — опережающие индикаторы, диагностика, а не план: как только сигнал превращается в норму, люди начинают работать на число, а не на результат.

Сигнал Если низкий — смотреть на
Активные по группам доступ и осведомлённость
Возвращаются каждую неделю обучение и ожидания
Разговоров на человека подходят ли возможности и подключения к работе
Навыки и проекты в работе позиция по управлению
Использование подключений набор подключений

Цель темпа — конкретная: «каждая группа с доступом возвращается еженедельно в течение восьми недель», а не «хорошее внедрение скоро». Пример из курса: подразделение держалось на 10%, потому что сотрудники не прошли обучение, — лечится обучением, а не настройками.

Дальше: Регулируемое подразделение: одна позиция →

9. Регулируемое подразделение: одна позиция

Курс предлагает для регулируемой функции одну согласованную позицию, а не пять исключений:

  1. Отдельная группаЕё участники не входят в широкие группы — правило объединения ничего не добавит.
  2. Те же возможности, кроме разработкиClaude Code — только когда готова запись сессий.
  3. Подключения только на чтениеОстальные для группы выключены.
  4. Сначала одобрениеНавыки и плагины — после проверки.
  5. Обычный лимит, проверка каждого увеличенияС отдельным владельцем бюджета.
  6. Срок хранения по регуляторным требованиямДля всей организации, с Compliance API и назначенным читателем.

«Если регулируется вся организация — этот набор и есть ваша базовая настройка».

Итоговые шаги курса: подтвердить четыре трудно отменяемые настройки (или передать их владельцу с датой решения); по каждому открытому вопросу записать, что блокирует, что нужно для разблокировки и дату решения — «имя владельца само по себе не план»; затем запускать по группам в порядке структура → доступ → управление → расходы → включение записи → запуск.

Когда появляется новый продукт

Три вопроса к любой новой возможности: кому её дать? что через неё пройдёт? меняет ли она риск — новый класс данных, новая степень самостоятельности, новые люди? При любом «да» — к владельцу риска данных. В примере курса Claude Tag (Claude в Slack) для регулируемого подразделения выключили, и владелец риска подписал это решение.

Как устроена совместная работа людей и агентов внутри команд — Люди и агенты в одной команде. Ссылки на курс и Справочный центр — в Справочнике: Обучение Anthropic.
