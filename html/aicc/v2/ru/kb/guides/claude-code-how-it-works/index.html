После этого руководства вы сможете объяснить, что Claude Code делает между вашим запросом и ответом, какими инструментами пользуется, что видит, как устроены сеансы и как режимы разрешений определяют, что он может делать без вашего согласия.

Claude Code — не чат с подсказками по коду, а помощник, который сам действует: читает файлы, правит их, запускает команды. Хотя он создан для разработки, ему можно поручить почти всё, что делается из командной строки: документацию, сборки, поиск по файлам.

Агентный цикл

Работа идёт по кругу из трёх шагов — его называют агентным циклом:

  1. Собрать контекстнайти и прочитать нужные файлы, понять задачу
  2. Действоватьправить код, запускать команды и тесты
  3. Проверитьпосмотреть результат и, если нужно, повторить

Цикл подстраивается под задачу: на вопрос хватит чтения, на исправление ошибки — нескольких кругов. Вы — часть цикла: можно прервать (Esc) и направить в любой момент.

Отсюда главный совет: делегируйте, а не диктуйте. Дайте контекст и цель, как способному коллеге, — какие файлы важны и что считать результатом; дальше Claude разберётся сам.

Инструменты

Файлы (читать, править, создавать), поиск (по именам и содержимому), выполнение (команды, тесты, git), веб (документация, поиск), а также подсказки редактора кода при установленных плагинах.

Поверх этого можно добавить расширения — о каждом есть отдельное руководство:

  • навыки — готовые инструкции под тип задачи;
  • подключения MCP — доступ к внешним системам: трекеру, базе данных, документации;
  • хуки — ваши команды, которые запускаются автоматически в определённые моменты;
  • помощники (subagents) — отдельные исполнители со своим контекстом.

Что видит Claude

Ваш проект, ваш терминал (всё, что можете запустить вы), состояние git, файл CLAUDE.md, автоматическую память (заметки, которые Claude сам сохраняет между сеансами), а также настроенные вами расширения.

Всё, что Claude прочитал, уходит модели как часть запроса. Поэтому секреты и данные клиентов не должны лежать там, куда он может заглянуть.

Сеансы и контекст

Всё, что Claude видел за сеанс — ваши сообщения, прочитанные файлы, вывод команд, — хранится в его рабочей памяти, контекстном окне (context window). Оно ограничено, и это объясняет большинство советов в следующих руководствах.

  • Каждый сеанс начинается с чистого контекста; постоянные правила кладите в CLAUDE.md.
  • claude --continue продолжает последний сеанс, claude --resume — выбрать из списка.
  • Когда контекст заполняется, Claude сжимает историю — ранние подробные указания могут потеряться. /context показывает, что занимает место.

Безопасность

Откат

Перед каждой правкой Claude сохраняет снимок файла. Esc дважды — вернуться назад. То, что сделано командами оболочки, и внешние действия — базы, API, развёртывание — так не откатить: для этого есть только git и ваша осторожность.

Режимы разрешений

Переключаются Shift+Tab: Auto — рискованное блокирует проверяющая модель (в новых версиях сеанс начинается в нём); Manual — спрашивает перед правками и командами; Accept edits — правит файлы без вопросов; Plan — только изучает и предлагает план. Для чувствительного кода — Manual.

Есть ещё режимы для запусков без человека — они описаны в Claude Code в действии.

Не знаете, как что-то сделать? Спросите самого Claude Code: «как настроить хуки?» — он отвечает по своей документации. /init создаёт CLAUDE.md, /doctor проверяет установку.

Попробуйте: нажмите Shift+Tab несколько раз и посмотрите, как меняется режим; задайте вопрос о проекте и выполните /context — увидите, сколько места уже занято.
