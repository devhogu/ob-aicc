Claude Code: приёмы, которые работают

После этого руководства вы сможете давать Claude способ проверить свою работу, вести сложную задачу через план и держать сеанс чистым — три привычки, от которых зависит качество почти любой работы в Claude Code.

Почти все советы по Claude Code вытекают из одного ограничения: контекстное окно (context window) заполняется быстро — каждое сообщение, каждый прочитанный файл, каждый вывод команды. Чем оно полнее, тем чаще модель забывает ранние указания и ошибается. Контекст — главный ресурс, которым нужно управлять.

1. Дайте способ проверить работу

Claude останавливается, когда работа выглядит готовой. Дайте ему проверку, которая отвечает «да/нет»: тесты, сборку, линтер, скриншот для сравнения. Тогда он сам доводит работу до результата.

Слабее Сильнее
«напиши проверку email» «напиши validateEmail; примеры: user@example.com — верно, user@.com — неверно; запусти тесты после реализации»
«сборка падает» «сборка падает с этой ошибкой: […]. Исправь причину, а не подавляй ошибку, и проверь, что сборка проходит»

Просите показывать доказательства: вывод тестов, команду и её результат. И смотрите сами, не ослабил ли Claude существующие тесты, чтобы они прошли.

2. Сначала разобраться, потом план, потом код

Режим планирования (Plan mode, переключается Shift+Tab) позволяет Claude читать и отвечать, ничего не меняя. Порядок: изучить код → составить план → реализовать → закоммитить. Для мелочей вроде опечатки план не нужен: если изменение описывается одним предложением — просто попросите его сделать. Для изменений в чувствительном коде план полезен вдвойне: подход можно обсудить с коллегой до того, как появится первая правка.

3. Точный контекст в запросе

Назовите файл, сценарий и способ проверки; укажите на похожий код как образец; опишите симптом, вероятное место и что значит «исправлено». Файлы можно указывать через @, скриншоты — вставлять прямо в запрос.

4. Держите сеанс чистым

  • Esc — остановить Claude и поправить курс; Esc Esc или /rewind — откатиться к прошлой точке.
  • /clear — между несвязанными задачами.
  • Поправили дважды, а всё не то? /clear и новый, более точный запрос — почти всегда лучше длинного сеанса с исправлениями.
  • Большие исследования поручайте помощникам (subagents): они читают файлы в своём контексте и приносят только выводы. Подробно — в Помощники в Claude Code.

Пять типичных ошибок

Сеанс «обо всём»

Разные задачи в одном разговоре засоряют контекст. Лечится /clear.

Исправления по кругу

После двух неудачных правок — чистый лист и лучший запрос.

Раздутый CLAUDE.md

Слишком длинный файл — важные правила теряются. Сокращайте.

Поверил — не проверил

Правдоподобный код без проверки краевых случаев. Нет проверки — не выпускайте.

Бесконечное исследование

«Изучи всё» без рамок съедает контекст. Сужайте задачу или отдайте её помощнику.

Попробуйте сейчас

Возьмите следующую задачу из трекера. Начните в режиме плана, прочитайте план и поправьте его. Затем попросите реализовать и запустить тесты, показав вывод. Если после двух поправок результат всё ещё не тот — /clear и новый, более точный запрос.
