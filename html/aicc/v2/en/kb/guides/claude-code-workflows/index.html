После этого руководства вы сможете взять готовый рецепт — разобраться в чужом коде, исправить ошибку, написать тесты, подготовить PR — и пройти его в своём репозитории.

Каждый рецепт — цепочка запросов: начинайте с широкого вопроса и сужайте. Запросы можно писать по-русски.

Разобраться в чужом коде

«Дай обзор этого проекта» → «какие основные архитектурные решения?» → «где ключевые модели данных?» → «как устроена авторизация?». Попросите глоссарий терминов проекта.

Найти нужное место

«Найди файлы, которые отвечают за вход пользователя» → «как они связаны?» → «проследи вход от интерфейса до базы».

Исправить ошибку

Дайте команду, которая воспроизводит ошибку, и текст ошибки → попросите несколько вариантов исправления → примените выбранный → проверьте.

Переработать код

«Найди устаревшие вызовы API» → «предложи, как переписать utils.js» → «перепиши, сохранив поведение» → «запусти тесты». Мелкими шагами.

Тесты

«Какие функции не покрыты тестами?» → «добавь тесты» → «добавь граничные случаи» → «запусти и исправь падения». Claude повторит стиль ваших тестов. Тестовые данные — только вымышленные.

Запрос на слияние (PR)

«Кратко опиши мои изменения» → «создай PR» → «дополни описание». Перед отправкой попросите назвать риски. Ревью коллегой это не заменяет.

Документация

«Найди функции без комментариев» → «добавь документацию» → «улучши примерами» → «проверь по нашему стандарту».

Картинки

Вставьте скриншот ошибки, макет или схему: «что здесь не так?», «сверстай по этому макету». На скриншоте не должно быть данных клиентов.

Не только код

Claude Code работает в любой папке — заметки, документация, наборы markdown-файлов: искать, править, переупорядочивать.

Попробуйте сейчас: тесты к одному модулю

  1. «Какие функции в путь/к/модулю не покрыты тестами?»
  2. «Напиши к ним тесты в стиле существующих. Данные — только вымышленные. Код модуля не меняй».
  3. «Запусти тесты и покажи вывод».
  4. Сами посмотрите git diff: изменены только файлы тестов, в них нет реальных данных, ни одна существующая проверка не ослаблена.

Полезные приёмы

  • @путь/к/файлу — включить файл в запрос сразу; @папка — показать её структуру.
  • claude --continue — продолжить вчерашнюю работу; /rename — дать сеансу понятное имя.
  • claude --worktree имя — второй сеанс на отдельной ветке, чтобы правки не мешали друг другу.
  • claude --permission-mode plan или Shift+Tab — сначала план, потом правки.
  • «Поручи помощнику выяснить, как устроено обновление токенов» — помощник (subagent) исследует в своём контексте, и основной разговор не засоряется. Подробно — в Помощники в Claude Code.
  • git log --oneline -20 | claude -p "кратко опиши последние коммиты" — Claude в скриптах, без диалога. Учтите: такой запуск без флага --bare выполняет хуки и подключения MCP, настроенные в репозитории, и не спрашивает, доверяете ли вы папке. В чужом или непроверенном репозитории так не запускайте — подробно в Claude Code в действии.

Запуская Claude из скрипта или по расписанию, формулируйте запрос особенно ясно — что считается успехом и куда девать результат: уточнить у вас Claude не сможет.
