This guide is for anyone with work that repeats: a weekly report, replies to typical requests, summaries based on the same procedure. By the end, you will have put together your first project with documents and instructions.

A project is a separate workspace in Claude with its own conversations, documents, and instructions. Claude takes everything in the project into account in every conversation inside it. You don't need to attach the procedure again or explain who you are.

What a project is made of

Project knowledge

The documents you upload to the project for Claude to rely on: procedures, templates, reference lists, examples of good results.

Project instructions

Standing rules you write once: your role, the tone, the answer format, what not to do.

Conversations

Each task is a separate conversation, but all of them see the project's knowledge and instructions.

How to build a good project

  1. One topic, one project. “Replies to customer requests”, “Weekly department report”, not “Everything for work”.
  2. Create the project. In the left sidebar in Claude, open Projects → + New Project. The name and description are for people: Claude doesn't see them, so put everything important in the instructions.
  3. Put only what's needed into knowledge. Current versions of documents with clear file names, no drafts and nothing out of date.
  4. Write short instructions. For example: “You help a contact center employee. Reply politely in 5–7 sentences, relying only on the project documents. If the documents don't have the answer, say so.”
  5. Add an example. One model answer in the project knowledge works better than a long description of the style.
  6. Keep it up to date. When a document changes, replace it in the project, or Claude will answer from the old version.

Try it now. Take one of your recurring tasks, for example the one that landed in the “project” row in Claude: what it can do and where to start. Create a project, upload one or two documents that may be shared, write instructions of three or four sentences, and ask your first work question in the project. If the answer isn't right, fix the instructions, not just the question.

Working together

On team plans, you can share a project with colleagues, for viewing or for editing. That way the whole group has the same documents and the same rules, while colleagues don't see your own conversations in the project unless you share them yourself.

Mind the data: put into project knowledge only what may be shared with this service. Customers' personal data and banking secrecy never go into a project.

For details on writing strong instructions and sharing a project, with ready-made examples, see the guide Working in Claude: projects, documents, Office, and Cowork.
