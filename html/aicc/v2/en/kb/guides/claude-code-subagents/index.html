После этого руководства вы сможете решать, нужен ли помощник для задачи, и сделать своего — например, ревьюера, который только читает код и отчитывается в заданном формате.

Помощник (subagent) — это отдельный исполнитель внутри сеанса: со своим контекстом, своими инструкциями и своим набором разрешённых инструментов. Основной Claude поручает ему часть работы и получает обратно только выводы.

Зачем

Чистый контекст

Поиск по коду, логи, длинные выводы остаются у помощника и не засоряют разговор.

Ограничения

Помощнику-ревьюеру можно разрешить только чтение.

Специализация

Свои инструкции под одну задачу: безопасность, тесты, документация.

Экономия

Простые задачи можно отдать более быстрой и дешёвой модели.

Готовые помощники уже есть: Explore — быстрый поиск по коду только на чтение, Plan — исследование в режиме плана, General-purpose — многошаговые задачи.

Как сделать своего

Проще всего попросить: «Создай помощника code-improver, который предлагает улучшения читаемости и производительности». Или вручную — файл .claude/agents/code-improver.md:

---
name: code-improver
description: Ищет и предлагает улучшения читаемости и производительности
tools: Read, Grep, Glob
model: sonnet
---
Ты — специалист по улучшению кода. Для каждой находки объясни проблему,
покажи текущий код и предложи улучшенный вариант. Сам код не меняй.

.claude/agents/ — помощники проекта (храните в git, чтобы были у всей команды), ~/.claude/agents/ — ваши личные для всех проектов. Обязательны только name и description; если не указать tools, помощник получит все инструменты основного сеанса — поэтому список лучше задавать явно.

Как вызвать

  • Словами: «Используй помощника code-improver, чтобы проверить этот модуль».
  • Гарантированно — упоминанием: введите @ и выберите помощника из списка.
  • Независимая проверка готовой работы: «Поручи помощнику проверить изменения по плану и перечислить пробелы» — свежий взгляд не зависит от рассуждений того, кто писал код.

Как спроектировать хорошего помощника

По курсу Introduction to Subagents:

  • Описание решает, что поручит основной Claude. Имя и описание всех помощников видны основному агенту, и по описанию он пишет поручение. Впишите туда, что помощнику нужно получить: «назови точно, какие файлы проверить», «верни источники, на которые можно сослаться».
  • Формат ответа — главное улучшение. Он даёт помощнику точку остановки. Для ревью: итог · критичное · важное · мелкое · рекомендации · вердикт.
  • Раздел «Препятствия». Пусть помощник сообщает о проблемах настройки, обходных путях и капризных зависимостях — иначе основной Claude будет открывать их заново.
  • Минимум инструментов. Исследователю — поиск и чтение; ревьюеру — плюс команды для git diff; правки — только тому, кто правит.

Нужен ли помощник

Решающий вопрос: важна ли вам промежуточная работа? Если важен только вывод — помощник экономит контекст. Если нужен ход рассуждений — делайте в основном разговоре: помощник возвращает только итог, а как он к нему пришёл, не видно.

Хорошо подходят: исследование, ревью (Claude лучше проверяет код, «написанный кем-то другим»), задачи с особыми правилами — тексты, оформление по дизайн-системе.

Чего не делать

  • Роли-«эксперты». «Ты — эксперт по Python» ничего не добавляет.
  • Последовательные цепочки «воспроизвести → отладить → исправить» разными помощниками: контекст теряется при каждой передаче.
  • Помощник для запуска тестов, который прячет полный вывод: по тестам Anthropic такой вариант показал худший результат.

Когда не нужен

Для мелких точечных правок и задач, где нужно часто переспрашивать, — помощник только добавит лишний шаг.

Попробуйте сейчас

Попросите Claude: «Создай помощника проекта security-reviewer в .claude/agents/. Инструменты — только Read, Grep, Glob. Он проверяет переданные ему файлы на пароли, ключи и токены, на реальные данные клиентов в тестах и примерах и на отключённые проверки. Формат ответа: итог · критичное · важное · мелкое · вердикт. Сам ничего не меняет». Прочитайте созданный файл, затем вызовите помощника через @ на файлах из вашего последнего изменения. Его отчёт — подсказка для вашего ревью, а не замена ему.
