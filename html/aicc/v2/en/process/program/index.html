Program

The program is the level where a started initiative turns into a result. It is run by the project manager, and the order of work across projects is set by the program decision forum.

What an initiative is made of

An initiative is broken down into Capabilities: large parts of the result that can be shown and checked. Each Capability in turn is made up of Features: finished pieces that the team completes in one iteration. On the project card they are recorded as rows with Jira keys.

Program board

The live program board is in the Projects → Program section.

Program backlog

The backlog is an ordered list of the Capabilities and Features of all started initiatives. The order within an initiative is set by the product manager; the order across initiatives and the dependencies are set by the program decision forum. An item moves to “Ready” when its outcome and acceptance criteria are clear. A review is not acceptance: the product manager accepts a Feature, and the business owner accepts the working solution.

Working cycle

Period Length What happens
Iteration about a month at the start, Features are chosen; at the end come the review and demo, acceptance, and a short retrospective; the project manager updates the card
Program increment about a quarter at the start, Capabilities and dependencies are planned; at the end, the business owners decide whether to continue
Program decision forum once per iteration order of work, dependencies, missed deadlines, out-of-turn requests

A small project that fits into one iteration needs only a card, a short demo of the result, and a record of the decision.

Team level and Jira

Each work row on the card carries a Jira key; when the team closes a Feature, the project manager marks it on the card.

Closing

When an initiative is done, the project manager records the results and the lessons learned on the card, and the business owner confirms whether the intended outcome was achieved. Further improvements and support continue as run-rate work.
