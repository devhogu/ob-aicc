Project profiles

A project profile is a ready-made description of a type of work: when it fits, what stages it has, and what is usually checked in it. A profile is a pattern; a real project is run on a card that names its profile. The practice checklist in each profile is a prompt, not a requirement: each project checks it against its own rules.

  7. Capabilities and Features
  8. Acceptancecheckpoint

When it fits

A new result is needed, and it can't be produced in one iteration from a template: for example, an assistant for one group of employees, or new analytics.

Practice checklist

  • what data is used and who is responsible for it
  • the risk tier, and whether a human in the loop is needed
  • how quality was checked and what to do if it drops
  • who accepts the result, and how
  • what has been recorded as experience

HRrun-rate work

Stages and checkpoints

  1. A line on a standing card
  2. Room under the WIP limit
  3. One iteration
  4. Acceptancecheckpoint

When it fits

The request is small, it recurs, and the result is clear in advance: for example, preparing standard reports and forms with a workplace assistant.

Practice checklist

  • what the workplace assistant sees and changes, and where the results are stored
  • what was checked together with information security
  • how the employee checks the result before using it
  • what to do if the assistant makes a mistake

ExampleRecurring check

Monthly check of AI solutions in operation

Doing
Business owner
the owner of the solutions in the department
Next step
run the check for October
Checklist
2 of 4
any departmentrun-rate work

Stages and checkpoints

  1. What we check and how often
  2. Running the check
  3. Result on the card
  4. Fix, accept, or stopcheckpoint

When it fits

A recurring check with a clear rhythm is needed: for example, how AI solutions already in operation are working, or how data quality is changing.

Practice checklist

  • what material the conclusion is based on
  • what was found and what was done about it
  • who knows about the result
  • how the rhythm changes if there are many findings or few

Stages and checkpoints

  1. Whom we teach and what
  2. A program of short sessions
  3. Sessions
  4. Is the knowledge being appliedcheckpoint

When it fits

The task is not to build a solution but to teach people to use it: training, hands-on workshops, help in the first weeks.

Practice checklist

  • which data-handling rules to explain first
  • which examples make sense to these particular people
  • how to check that the knowledge is being applied
