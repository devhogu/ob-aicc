Здесь простыми словами объяснены технологические термины, которые встречаются в разделе «Ответственный AI». Термины процесса работы Хаба собраны в общем [словаре](page:vocabulary).

## Виды систем {#systems}

| Термин | Что это значит |
| --- | --- |
| Искусственный интеллект, AI | Машинная система, которая по входным данным решает, как сформировать результат ради заданных целей: прогноз, содержание, рекомендацию или решение, способное повлиять на физическую или цифровую среду. Это определение используют ОЭСР и ЕС |
| [[machine-learning]] | Способ построить модель на примерах, а не прописывать её правила: модель находит закономерность в примерах и применяет её к новым случаям |
| Модель | Сама закономерность, найденная при обучении: функция, которая превращает входные данные в результат. Скоринговая карта, модель выявления мошенничества и языковая модель — всё это модели |
| [[llm]] | Модель, обученная на очень больших массивах текста предсказывать следующий фрагмент; основа генеративного AI для работы с языком |
| [[generative-ai]] | AI, который создаёт содержание — текст, изображения, код, аудио, — а не только прогноз или класс |
| [[foundation-model]] | Крупная модель общего назначения, которую обучают для широкого круга задач, а затем подстраивают под конкретные; Акт ЕС об AI называет её моделью общего назначения |
| [[ai-agent]] | Система, в которой модель планирует и действует ради цели с помощью инструментов: получает данные, вызывает сервисы, заполняет формы, выполняет код и выстраивает шаги в цепочку |
| Ассистент | Приложение, которое помогает пользователю ответами, предложениями или черновиками. Ассистент только выдаёт результат; система, которая сама действует через инструменты, — уже AI-агент |

## Создание и использование {#building}

| Термин | Что это значит |
| --- | --- |
| Обучение модели | Процесс, в котором параметры модели подбирают по данным |
| [[fine-tuning]] | Дополнительное обучение готовой модели на данных конкретной задачи или организации |
| [[prompt]] | Инструкции и контекст, которые модель получает в момент использования; системный запрос — постоянная инструкция от разработчика |
| [[context-window]] | Объём текста, который модель учитывает одновременно; того, что не поместилось, она не видит |
| [[token]] | Единица текста для языковой модели: слово или его часть; в токенах считают затраты и лимиты |
| [[rag]] | В момент вопроса модель получает подходящие фрагменты проверенных документов, чтобы отвечать по ним и ссылаться на них, а не полагаться на память |
| [[embedding]] | Числовое представление текста, по которому система находит фрагменты, близкие к вопросу по смыслу; хранят их в векторном хранилище |
| [[grounding]] | Привязка ответов модели к проверенным источникам, чтобы их можно было перепроверить |
| [[evaluation-set]] | Набор случаев из практики с ожидаемыми результатами; по нему проверяют решение до запуска и после каждого заметного изменения |
| [[benchmark]] | Стандартная оценка для сравнения моделей; полезна при выборе модели, но не говорит, как модель справится с вашей задачей |
| [[guardrails]] | Правила, фильтры и ограничения вокруг модели: на что ей можно отвечать, на что нельзя, какие действия ей разрешены |
| [[human-in-the-loop]] | Человек проверяет каждый результат до того, как тот начнёт действовать |
| [[human-on-the-loop]] | Человек наблюдает за системой и может вмешаться и остановить её |
| [[model-gateway]] | Единая точка доступа к моделям: маршрутизация запросов, учёт затрат, журналы, защита данных |
| [[tool-gateway]] | Доступ системы AI к информационным системам и сервисам по разрешениям, с ограничениями для каждого инструмента |

## Виды сбоев {#failures}

| Термин | Что это значит |
| --- | --- |
| [[hallucination]] | Гладкий, уверенный и ошибочный результат: несуществующий факт, число или ссылка на источник; её ещё называют конфабуляцией |
| [[bias]] | Систематическая несправедливость результатов, усвоенная из данных или заложенная при проектировании |
| [[model-drift]] | Ухудшение качества модели по мере того, как жизнь уходит всё дальше от данных, на которых она обучена |
| [[prompt-injection]] | Текст во входных данных, который модель выполняет как инструкцию вопреки замыслу разработчика: прямая — если его пишет пользователь, косвенная — если он спрятан в документе или веб-странице |
| [[data-leakage]] | Данные попадают туда, где их быть не должно: в обучающий набор поставщика, в ответ другому пользователю, в журнал |
| [[jailbreak]] | Специально составленный запрос, который заставляет модель забыть о защитных механизмах |
| [[data-poisoning]] | Намеренное искажение данных, на которых учится модель, или документов, из которых она берёт сведения |
| [[excessive-agency]] | У AI-агента больше функций, прав доступа или автономности, чем нужно для его задачи |
| [[overreliance]] | Люди принимают результаты, не перепроверяя их, потому что система обычно права |
| [[model-collapse]] | Деградация моделей, которые всё больше учатся на содержании, созданном другими моделями |

## Работа с риском {#risk}

| Термин | Что это значит |
| --- | --- |
| [[responsible-ai]] | Принципы и практики, благодаря которым организация отвечает за то, как применяет AI; подробнее на странице [Что такое ответственный AI](page:responsible-ai/what-responsible-ai-means) |
| [[risk-tier]] | Оценка того, насколько серьёзны последствия ошибки решения с AI; её определяют данные, влияние на решение, выход к клиенту и автономность, и решающим становится самый высокий из этих признаков |
| [[risk-based-approach]] | Меры контроля соразмерны риску; на этом построены Акт ЕС об AI, NIST AI RMF и уровни риска в наших проектах |
| [[high-risk-ai]] | В Акте ЕС об AI — перечисленные в нём применения, в том числе кредитный скоринг физических лиц, к которым предъявляется полный набор требований |
| [[model-risk-management]] | Банковская практика проверки, описания и наблюдения за моделями с понятным владельцем; работа с AI распространяет её на новые системы |
| [[independent-review]] | Проверка решения человеком, который не участвовал в разработке; для среднего и высокого уровня риска — специалистами по рискам и безопасности |
| [[explainability]] | Способность объяснить, почему система выдала такой результат, так, чтобы затронутый человек, надзорный орган или аудитор мог на это объяснение опереться |
| Прозрачность | Люди знают, что имеют дело с AI и как он используется |
| [[impact-assessment]] | Оценка того, как применение с повышенным риском повлияет на людей и их права; её делают до запуска |
| [[model-card]] | Короткое описание модели или системы: что это, для чего, как тестировали, где её не стоит применять |
| [[ai-literacy]] | Понимание того, что AI умеет и чего не умеет; нужно каждому, кто им пользуется, и прямо упомянуто в Акте ЕС об AI |
| [[ai-incident]] | Событие, при котором применение AI причиняет или может причинить вред, ведёт к нарушению правил или к потере контроля, включая предотвращённый вред |
| [[shadow-ai]] | Инструменты AI, которыми пользуются в работе в обход тех, что Банк предоставляет для таких данных |

## Финтех {#fintech}

| Термин | Что это значит |
| --- | --- |
| [[kyc]] | Установление и проверка личности клиента и оценка связанного с ним риска при оформлении и в ходе обслуживания |
| [[open-banking]] | Доступ лицензированных третьих лиц к данным о счетах и к инициированию платежей через интерфейсы, с согласия клиента |
| [[embedded-finance]] | Финансовые услуги внутри нефинансового продукта или приложения через банк-партнёр |
| [[regtech]] | Технологии, в том числе AI, в работе по соблюдению требований: скрининг, мониторинг, отчётность, отслеживание изменений регулирования |
| [[alternative-data]] | Данные помимо кредитной истории, по которым оценивают клиента: транзакционные, мобильные, поведенческие; с ними связаны вопросы справедливости и согласия |
| [[liveness-check]] | Проверка того, что документ предъявляет живой человек, который действительно присутствует, а не его фотография или запись |
| [[real-time-scoring]] | Оценка, которую модель выдаёт за время самой транзакции или обращения, например при выявлении мошенничества и проведении платежей |
