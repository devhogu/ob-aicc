После этого руководства вы сможете подключить к Claude Code одобренную внешнюю систему — трекер, базу данных, документацию — с минимальными правами, понимать, где хранится настройка и кто её увидит, и держать ключи доступа вне репозитория.

MCP (Model Context Protocol) — открытый стандарт подключения Claude к внешним системам: трекеру задач, базе данных, мониторингу, дизайну, почте. Вместо того чтобы копировать данные в разговор, Claude сам обращается к системе через подключённый сервер MCP.

## Что это даёт {#what}

- Реализовать задачу прямо из трекера (например, Jira или GitHub).
- Посмотреть ошибки и метрики в системе мониторинга.
- Сделать запрос к базе данных — лучше к тестовой, без данных клиентов, и только на чтение.
- Сверстать по макету из дизайн-системы.

Всё это — только если подключение одобрено в организации.

## Как подключить {#add}

```bash
# удалённый сервер по HTTP — рекомендуемый способ
claude mcp add --transport http имя https://адрес-сервера/mcp

# локальный сервер, который запускается на вашей машине
claude mcp add --transport stdio имя -- команда-запуска-сервера

claude mcp list          # что подключено
claude mcp remove имя    # отключить
```

В сеансе команда `/mcp` показывает состояние подключений и помогает пройти вход.

## Где хранится настройка {#scope}

| Область | Для кого | Где |
| --- | --- | --- |
| local (по умолчанию) | только вы, в этом проекте | ваши личные настройки |
| project | вся команда проекта | файл `.mcp.json` в репозитории |
| user | вы, во всех проектах | ваши личные настройки |

Область задаёт флаг `--scope`, например `--scope project`.

`.mcp.json` хранится в git, поэтому ключей доступа в нём быть не должно. Подставляйте их из переменных окружения — запись `${ИМЯ}` заменяется значением переменной:

```json
{
  "mcpServers": {
    "tracker": {
      "type": "http",
      "url": "https://адрес-сервера/mcp",
      "headers": { "Authorization": "Bearer ${TRACKER_TOKEN}" }
    }
  }
}
```

В обычном сеансе серверы из `.mcp.json` перед первым использованием требуют вашего подтверждения. При запуске `claude -p` без флага `--bare` они подключаются **без вопроса** — учитывайте это, запуская Claude из скриптов в чужом репозитории.

## Осторожно {#safety}

- Подключайте только нужные и одобренные в организации серверы: сервер получает доступ к вашей среде.
- Сервер, который читает внешний контент, может принести [[prompt-injection|промпт-инъекцию]].
- Давайте минимальные права: база — на чтение, трекер — к нужному проекту.
- Неиспользуемые подключения отключайте: так и безопаснее, и контекст чище.

Если инструмент есть в виде командной строки (`gh`, `aws`, `gcloud`), часто проще дать Claude её: это экономнее по контексту, чем MCP.

**Попробуйте:** в своём репозитории выполните `claude mcp list` — посмотрите, что уже подключено, в том числе из `.mcp.json`. В сеансе откройте `/mcp` и отключите то, что для текущей задачи не нужно.
