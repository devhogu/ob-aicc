## Решение вопросов по платежам {#journey-payment-payment-issue-resolution}

Вариант клиентского маршрута для инициативы INI-013 (состояние «Предложено»; воронка портфеля). Если этот вариант будет выбран на стадии определения объёма, страница станет приложением по клиентскому маршруту к паспорту инициативы (см. [Карта маршрутов и порядок выбора](#journeys)). Здесь приведено только то, что относится к данному клиентскому маршруту; общие положения изложены на страницах [Паспорт инициативы](#charter), [Управление инициативой и роли](#governance) и [Контрольные процедуры и подтверждающие материалы](#controls), технический профиль — на странице [Технические профили клиентских маршрутов](#journey-profiles).

**Цель:** сократить число повторных обращений по неисполненным, находящимся в обработке и сторнированным платежам. Для этого работник, обслуживающий клиента, видит единое описание состояния платежа, историю предыдущего обслуживания, ответственного исполнителя и одобренный следующий шаг, и каждое из этих сведений подтверждается ссылкой на запись в системе-источнике. **Объём, на который запрашивается одобрение:** один вид внутренних розничных платежей и одна очередь обслуживания.

### Объём и исключения {#journey-payment-scope-and-exclusions}

| Предмет | Порядок в пилотном применении | Основание |
| --- | --- | --- |
| Один вид внутренних розничных платежей, выбираемый на стадии определения объёма; одна очередь обслуживания | Включено | Объём достаточно мал, чтобы результат можно было измерить |
| Состояния «не исполнен», «в обработке» и «сторнирован», которые фиксирует платёжная система и для которых существует одобренный шаг урегулирования; связанные обращения, кейсы, статус разбора и предыдущие сообщения клиенту | Включено | Это история, которую работник сегодня восстанавливает вручную |
| Источник сведений о состоянии платежа | Включается, только если у платёжной системы есть интерфейс для чтения или одобренная выгрузка по выбранному виду платежей (подтверждается на стадии определения объёма) | Состояние платежа никогда не выводится из заметок по обращениям |
| Операции, не признаваемые клиентом; подозрение на мошенничество | Исключено; действующий процесс противодействия мошенничеству | Собственный порядок расследования, права клиента и полномочия на принятие решений |
| Споры и опротестование операций (чарджбэк) | Исключено; действующий процесс рассмотрения споров | Правила платёжных систем, сроки, установленные законодательством, и рассмотрение спора по существу |
| Приостановление платежей по санкционным требованиям и в целях противодействия отмыванию денег и финансированию терроризма (ПОД/ФТ) | Исключено; контрольная функция по комплаенсу | Конфиденциальная оценка, проводимая по требованиям законодательства |
| Трансграничные платежи и платежи через банки-корреспонденты, включая входящие денежные переводы | Исключено для первого пилотного применения после того, как на стадии определения объёма будут проверены объёмы обращений по видам платежей | Статус может зависеть от других финансовых организаций; входящие переводы могут оказаться самой многочисленной категорией, поэтому исключение подтверждается данными, а не принимается как допущение |
| Возмещение и компенсация | Исключено; остаётся за подразделениями, которые решают эти вопросы сегодня | Они определяют, на что клиент имеет право |
| Перевод, сторнирование или исправление операций со средствами | Исключено; выполняется работником в рамках действующих контрольных процедур по операциям | У ассистента нет инструментов |

### Профильное подразделение и предмет его одобрения {#journey-payment-process-function-and-what-it-approves}

| Позиция | Для этого клиентского маршрута |
| --- | --- |
| Профильное подразделение (зависимость) | Подразделение платёжных операций: зависимость инициативы, а не второе направление, если только оно не заявляет часть выгоды. Его специалисты выступают экспертами направления, если их назначает владелец направления |
| Предмет одобрения | Состояния платежей, входящие в объём, и пояснение к каждому из них; перечень действий (следующие шаги, которые ассистент вправе предлагать для каждого состояния); что считается урегулированием и что — повторным обращением по тому же платёжному событию; трактовка исторических кейсов оценочного набора; процедура обслуживания по платежам, за которую подразделение отвечает как за источник знаний, что указано в реестре AI-решений |
| Первые пользователи | Команда подразделения обслуживания клиентов, которая обрабатывает обращения по выбранному виду платежей |
| Дополнительные области компетенции контрольных функций | Сверх общего перечня отсутствуют; контрольная функция по комплаенсу определяет, какие требования к информированию клиентов о платежах применимы |

### Базовые значения показателей {#journey-payment-baseline-measures}

Каждое базовое значение представляет собой ссылку на источник, как правило на управленческий отчёт (MI); его фиксирует ответственный за источник в ходе проработки, на стадии бизнес-кейса. Формулы и схема сравнения приведены в приложении об измерениях на странице [Паспорт инициативы](#charter).

| Показатель | Назначение | Ссылка на источник |
| --- | --- | --- |
| Повторные обращения по одному и тому же платёжному событию, отвечающему условиям отбора | Опережающий индикатор: повторные обращения | [Отчёт MI: повторные обращения на одно платёжное событие в разрезе видов платежей] |
| Трудозатраты на разбор или обработку одного кейса, отвечающего условиям отбора | Опережающий индикатор: трудозатраты на обработку | [Отчёт о загрузке персонала или отметки времени в кейсах; наличие отметок времени подлежит подтверждению] |
| Время от первого обращения до подтверждённого урегулирования | Индикатор клиентского маршрута (раздел 2 паспорта инициативы) | [Система учёта кейсов: даты обращения и урегулирования; подлежит подтверждению] |
| Передача кейсов в подразделение платёжных операций | Вспомогательный показатель | [Система учёта кейсов: число передач на один кейс] |
| Жалобы на обслуживание по платежам и повторно открытые кейсы | Контрольное ограничение | [Реестр жалоб и система учёта кейсов] |

### Критерии качества и контрольные ограничения {#journey-payment-quality-and-control-limit-criteria}

Значения по этому клиентскому маршруту для единого правила приёмки, установленного на странице [Контрольные процедуры и подтверждающие материалы](#controls).

| Критерий | Для этого клиентского маршрута |
| --- | --- |
| Качество определения состояния | Не менее 95% определений состояния платежа и следующего шага в выборке из оценочного набора верны по всем языкам записей (русский, кыргызский, смешанный). Это предлагаемый минимальный уровень; он подтверждается с подразделением платёжных операций после определения базовых значений и может быть повышен, но не понижен |
| Критические ошибки | Показано состояние, противоречащее данным платёжной системы; пропущен признак мошенничества или спора, и кейс не направлен по соответствующему маршруту; клиенту сообщено о возврате средств при отсутствии зарегистрированного сторнирования. Требование: ни одной такой ошибки в оценочном наборе; любая выявленная ошибка блокирует начало использования до её исправления и повторного тестирования |
| Ссылки на источники | Каждый показанный факт о платеже, статус и предыдущее действие подтверждаются ссылкой на запись в системе-источнике |
| Недопустимые события | Кейс, связанный с мошенничеством, спором или санкционными требованиями, обработан в рамках пилотного применения, а не в предназначенном для него процессе; сведения о платеже раскрыты лицу, не имеющему права на их получение |
| Отслеживаемые ограничения | Показатели жалоб и повторно открытых кейсов не ухудшаются по сравнению с базовыми значениями сверх согласованного допуска |

### Условия остановки {#journey-payment-stop-conditions}

- Состояние платежа выбранного вида невозможно надёжно установить по данным платёжной системы.
- Подразделение платёжных операций не может одобрить перечень действий для состояний, входящих в объём.
- Рабочая панель существенно увеличивает трудозатраты работника по сравнению с действующим процессом.
- Невозможно соблюсти одно из указанных выше контрольных ограничений.

### Ожидаемый объём {#journey-payment-expected-volume}

Получает ли одна команда за период наблюдения достаточно обращений по выбранному виду платежей, отвечающих условиям отбора, чтобы сделать обоснованный вывод о повторных обращениях? Значение: [отчёт MI: число обращений в месяц по выбранному виду платежей в очереди пилотного применения, отвечающих условиям отбора]. Из трёх клиентских маршрутов именно этот с наибольшей вероятностью достигнет объёма выборки, рассчитанного в приложении об измерениях; в этом случае для индикатора повторных обращений устанавливается целевое значение. Если объём не будет достигнут, результат для клиента рассматривается как ориентировочное свидетельство (указание на эффект, а не его доказательство), а управленческое решение по итогам MVP принимается на основе трудозатрат, качества определения состояния и правильности следующего шага — их можно подтвердить и на меньшей выборке. Вид платежей с большим числом обращений или более длительный период наблюдения выбирается на стадии определения объёма, а не после получения результата.
