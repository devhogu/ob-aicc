Циклы управления данными

Повторяющиеся циклы управления данными — оценка качества данных (BCBS 239), представление регуляторных данных, стюардство над нормативно-справочными данными и аттестация происхождения и контролей.

Качество управления активами

Цикл оценки качества данных (BCBS 239)

Ежемесячная оценка качества данных по ключевым элементам данных — профилирование, оценка, выявление проблем, устранение и повторная проверка, — в соответствии с Принципами 2 и 3 BCBS 239 (точность и целостность, полнота) и утверждёнными банком измерениями качества данных. Якорь цикла — период от оценки качества до подтверждённого устранения.

Цикл оценки качества данных (BCBS 239) — основной механизм банка для измерения, управления и улучшения качества ключевых элементов данных (CDE), существенных для агрегирования рисков, регуляторной отчётности и принятия бизнес-решений. В соответствии с BCBS 239 (Принципы Базельского комитета по банковскому надзору об эффективном агрегировании риск-данных и риск-отчётности, январь 2013 г.) банки должны выстраивать архитектуру данных и систему качества, обеспечивающую точность, полноту, своевременность, согласованность и агрегируемость риск-данных по требованию. НБКР, НБК/АРРФР и ЦБР ссылаются на принципы BCBS 239 в своих надзорных ожиданиях для системно значимых банков. Цикл проходит ежемесячно для оценки качества CDE и ежеквартально для комплексной оценки по всем измерениям качества — полнота, точность, своевременность, согласованность, достоверность и уникальность — по всему операционному и риск-информационному хозяйству. Проблемы качества данных, выявленные в ходе цикла, поступают в конвейер устранения, которым управляют стюарды доменов данных совместно с ИТ и владельцами систем-источников. ИИ может ускорить цикл, автоматизируя профилирование данных по большим популяциям CDE, классифицируя проблемы качества из выходных данных профилирования и формируя планы устранения из структурированных записей о проблемах — позволяя команде по качеству данных обрабатывать больший реестр CDE за цикл без пропорционального роста численности персонала.

Analyze

Оценки качества по измерениям CDE проводятся ежемесячно, но отслеживаются неформально между циклами. Директору по данным недоступно непрерывное представление о динамике качества данных — какие CDE улучшаются, какие стабильны, какие деградируют — и связь между трендами качества и влиянием на нижестоящую риск-отчётность не отображается регулярно.

Optimize

Распределение ресурсов по устранению в рамках очереди проблем не оптимизируется системно с учётом влияния на нижестоящую регуляторную отчётность. Проблемы в менее видимых доменах данных, влияющие на агрегирование рисков по BCBS 239, могут деприворитизироваться относительно проблем в высокопрофильных бизнес-системах отчётности, создавая комплаенс-риск, который стандартный процесс приоритизации не обнаруживает.

Automate

Выполнение профилирования данных, расчёт оценок качества, классификация проблем из выходных данных профилирования и формирование планов устранения из структурированных записей о проблемах — структурированные, основанные на правилах задачи, применяемые к большим объёмам данных в каждом цикле. Проверки измерений качества BCBS 239 следуют предписанным определениям, поддающимся оценке с участием агента и проверкой стюарда.

Enrich

Истории проблем качества данных — первопричины, действия по устранению и время до разрешения — хранятся в отдельных записях о проблемах, а не в структурированной базе знаний. Системные паттерны сбоев качества — одно и то же ETL-преобразование, стабильно производящее нулевые значения для категории CDE, — не обнаруживаются по истории проблем, что препятствует приоритизации проактивных инженерных исправлений.

Автоматизация профилирования и скоринга CDE

Агент выполняет ежемесячный прогон профилирования CDE и скоринг качественных измерений по всему инвентарю CDE, применяя определения качественных измерений BCBS 239 к каждому элементу и формируя оценённый вывод для проверки стюардами. Охват распространяется на полный утверждённый инвентарь CDE, а не только на подмножество, достижимое в рамках доступных мощностей инженерной команды за цикл. Команда по качеству данных проверяет оценённый вывод и утверждает результаты цикла.

S

Регуляторный горизонт: Данные о рисках и надзорная отчётность

Решаемая задача

Охват профилирования не полон в каждом цикле — примерно 60–70% выявленных CDE профилируются, — поскольку подключение новых источников данных к системе профилирования требует инженерных усилий, конкурирующих с другими приоритетами. Скоринг качественных измерений применяется доменными стюардами непоследовательно при отсутствии автоматизированного скоринга, снижая сопоставимость по доменам.

Решение

Агент ежемесячно применяет предварительно настроенные правила профилирования ко всем подключённым системам-источникам — проверки на нулевые значения, валидация диапазонов, ссылочная целостность, согласованность форматов и обнаружение дублей — и переводит выводы профилирования в оценки качественных измерений по утверждённым определениям BCBS 239. Оценённый вывод передаётся доменным стюардам для проверки в рамках цикла оценки. Пробелы в покрытии по неподключённым источникам маркируются отдельно для инженерной приоритизации.

OKR

Ежемесячное профилирование CDE и скоринг качественных измерений охватывают 100% утверждённого инвентаря CDE, определения измерений BCBS 239 применяются единообразно по всем доменам, оценённый вывод предоставляется для проверки стюардами в рамках цикла оценки.

Внедрение

Агент выполняет полный ежемесячный прогон профилирования, охватывающий 100% подключённых CDE, ≥ 12 месяцев подряд; флаги пробелов покрытия для неподключённых источников передаются в очередь инженерной приоритизации каждый цикл.

Принятие

≥ 90% оценённых выводов приняты доменными стюардами без пересчёта; согласованность скоринга по измерениям BCBS 239 подтверждена как единообразная по доменам в ≥ 85% ежемесячных циклов.

Цикл

Охват профилирования расширен примерно с 60–70% инвентаря CDE до 100% подключённых CDE без дополнительных инженерных ресурсов за цикл.

Подготовка плана устранения проблем качества данных

Для каждой приоритизированной проблемы качества данных агент формирует структурированный план устранения из записи о проблеме — гипотеза первопричины, рекомендуемое действие по устранению, ответственный ИТ-владелец и целевая дата повторного тестирования, — позволяя стюардам данных инициировать устранение без шага ручной подготовки. Стюард проверяет и подтверждает план до обращения в ИТ. Качество подготовки откалибровано в соответствии с системой устранения банка и классификацией первопричин BCBS 239.

S
Решаемая задача

Расследование первопричины проблем качества данных требует от команды по качеству данных трассировки проблемы через ETL-пайплайн до системы-источника; там, где документация линейки неполна, расследования могут занимать дни до выявления первопричины. Каждое расследование и план устранения составляются стюардом с нуля, потребляя время, которое можно было бы направить на более ответственную работу по качеству.

Решение

Агент читает запись о проблеме — затронутый CDE, сбой качественного измерения, вывод профилирования — и обходит доступную документацию линейки для формирования гипотезы первопричины и предварительно заполненного плана устранения, охватывающего рекомендуемое действие, ответственного ИТ-владельца, определённого из реестра владельцев CDE, и предложение по дате повторного тестирования. Стюард проверяет, при необходимости корректирует и передаёт план в ИТ. Там, где документации линейки недостаточно для автоматического обхода, агент маркирует пробел для расследования стюардом.

OKR

Стюарды данных инициируют устранение каждой приоритизированной проблемы качества на основе сформированного агентом плана, охватывающего гипотезу первопричины, рекомендуемое действие, ответственного ИТ-владельца и целевую дату повторного тестирования, откалиброванного в соответствии с системой классификации первопричин BCBS 239 банка.

Внедрение

Агент формирует план устранения для ≥ 90% приоритизированных проблем в течение 1 рабочего дня после подтверждения проблемы; флаги пробелов в документации линейки происхождения подняты для ≥ 95% проблем, где документация линейки недостаточна для автоматического обхода.

Принятие

≥ 80% сформированных агентом планов подтверждены и переданы в ИТ стюардами без существенных поправок; гипотезы первопричины подтверждены по выводам ИТ в ≥ 75% закрытых проблем.

Цикл

Время стюарда на план устранения сокращено с ручного расследования и подготовки (как правило, от половины до полного рабочего дня) до ≤ 1 часа проверки и подтверждения на проблему.

Монитор траектории качества CDE

Агент на непрерывной основе отслеживает оценки качественных измерений CDE между плановыми ежемесячными оценками, сигнализируя CDO об ухудшающихся измерениях и их влиянии на рисковую отчётность до следующего цикла скоринга. Дашборд отслеживает траектории полноты, точности, своевременности и согласованности по домену CDE и маркирует CDE, качество которых стремится ниже порогового значения. CDO использует представление о траектории для направления упреждающего взаимодействия со стюардами.

M
Решаемая задача

Оценки качественных измерений формируются ежемесячно и отслеживаются неформально между циклами. CDO не имеет непрерывного представления о том, какие CDE деградируют, и не может связать тренды качества с влиянием на нижестоящую регуляторную отчётность без проведения ручной выгрузки данных. Деградация, начинающаяся между циклами, становится видимой только после следующего планового цикла скоринга.

Решение

Агент считывает результаты профилирования и оценки качества по мере их формирования и поддерживает скользящую траекторию по каждому CDE и домену. Измерения, стремящиеся ниже порогового значения, инициируют оповещение с оценкой влияния на нижестоящее звено, определяющей, какие выходные данные агрегирования рисков BCBS 239 и регуляторные представления потребляют затронутый CDE. CDO проверяет дашборд траекторий еженедельно.

OKR

CDO располагает непрерывным представлением о траектории качества по домену CDE между плановыми ежемесячными оценками, с ухудшающимися измерениями и их влиянием на выполнение требований BCBS 239, отображаемыми еженедельно.

Внедрение

Агент поддерживает непрерывный дашборд траекторий, охватывающий 100% зарегистрированных CDE; еженедельные оповещения о пересечении порогового значения выпускаются для ≥ 95% квалифицируемых случаев ухудшения в течение 12 месяцев с момента запуска.

Принятие

≥ 80% оповещений о пересечении порогового значения оценены CDO как требующие упреждающего взаимодействия со стюардами; оценки воздействия на выполнение требований BCBS 239 подтверждены командой рисковой отчётности как точные в ≥ 85% оповещений.

Цикл

Деградация качества CDE выявляется в течение 7 дней после пересечения порогового значения, а не на следующем плановом ежемесячном цикле скоринга.

Приоритизация устранения проблем качества данных по влиянию

Агент оценивает каждую открытую проблему качества данных по её влиянию на нижестоящее звено — точность агрегирования рисков BCBS 239 и регуляторных представлений, — переупорядочивая бэклог устранения по регуляторной существенности, а не по видимости проблемы. Команда по качеству данных направляет ресурсы на устранение проблем с наибольшей комплаенс-экспозицией в первую очередь. CDO использует ранжированный бэклог для обоснования распределения ресурсов на устранение перед советом по управлению данными.

M

Регуляторный горизонт: Данные о рисках и надзорная отчётность

Решаемая задача

Распределение ресурсов на устранение по бэклогу проблем не систематически согласовано с влиянием на нижестоящую регуляторную отчётность. Проблемы в менее заметных доменах данных, затрагивающие агрегирование рисков BCBS 239, могут де-приоритизироваться относительно проблем в высококрупных системах бизнес-отчётности, накапливая комплаенс-экспозицию, которую стандартный процесс приоритизации не выявляет.

Решение

Агент сопоставляет каждую открытую проблему с нижестоящими отчётами, метриками риска и регуляторными представлениями, потребляющими затронутый CDE, оценивает влияние по регуляторной существенности и переупорядочивает очередь устранения соответствующим образом. Проблемы, затрагивающие CDE агрегирования рисков BCBS 239 и срочные регуляторные представления, выносятся в верхнюю часть очереди с кратким изложением комплаенс-экспозиции. Команда по качеству данных проверяет ранжированную очередь в начале каждого спринта по устранению.

OKR

Ресурсы команды по качеству данных на устранение направляются бэклогом, ранжированным по регуляторной существенности, с CDE агрегирования рисков BCBS 239 и срочными регуляторными представлениями в верхней части очереди каждого спринта.

Внедрение

Агент переупорядочивает очередь устранения по регуляторной существенности для ≥ 95% спринт-циклов в течение 12 месяцев с момента запуска; сопоставление влияния на нижестоящее звено охватывает 100% открытых проблем по каталогу данных.

Принятие

≥ 85% позиций с наивысшим рангом подтверждены командой по качеству данных как правильно приоритизированные в начале спринта; сводная информация о комплаенс-экспозиции принята без существенных правок для ≥ 80% флагов существенности BCBS 239.

Цикл

Ранжирование очереди устранения доступно команде в начале каждого спринта, заменяя ручные проверки приоритизации в конце спринта.

База знаний паттернов сбоев качества данных

Агент анализирует накопленную историю проблем по завершённым циклам устранения для выявления системных паттернов сбоев — повторяющихся первопричин, категорий ETL-преобразований, генерирующих непропорциональные сбои качества, систем-источников с устойчивыми пробелами в точности, — и представляет их в виде приоритизированной инженерной программы CDO и руководителю по разработке данных. Анализ паттернов переключает инвестиции с реактивного устранения в рамках отдельных циклов на проактивное повышение качества пайплайна. Выявление проводится ежеквартально по реестру закрытых проблем.

M
Решаемая задача

История проблем качества данных хранится в отдельных записях о проблемах, а не в структурированной базе знаний. Системные паттерны — одно и то же ETL-преобразование, последовательно генерирующее нулевые значения для категории CDE, или конкретная система-источник, регулярно нарушающая стандарты своевременности, — не выявляются по истории проблем, а инженерные инвестиции в повышение качества пайплайна не опираются на накопленные свидетельства сбоев.

Решение

Агент читает реестр закрытых проблем по всем завершённым циклам устранения, кластеризует проблемы по категории первопричины, типу ETL-преобразования и системе-источнику и выявляет паттерны, где одна и та же первопричина встречается по нескольким CDE или циклам. Формируется ежеквартальный отчёт о паттернах, ранжирующий системные категории сбоев по совокупному влиянию на качество и рекомендующий инженерные меры по устранению с оценкой выигрыша по охвату CDE. CDO использует отчёт для формирования программы инвестиций в качество пайплайна наряду со стандартными усилиями по устранению в рамках отдельных циклов.

OKR

CDO направляет инвестиции в качество пайплайна на основе ежеквартального анализа паттернов по закрытым проблемам устранения, выявляя системные категории сбоев ETL и пробелы систем-источников, ранжированные по совокупному влиянию на качество.

Внедрение

Цикл стюардства над нормативно-справочными данными

Цикл стюардства над нормативно-справочными данными регулирует авторитетные записи банка по клиентам, контрагентам, продуктам, счетам, инструментам, а также справочные данные и таблицы кодов, классифицирующие транзакционные и риск-данные в масштабах предприятия. Управление нормативно-справочными данными — практика поддержания единой, точной и авторитетной записи по каждой критической сущности — является фундаментальным для агрегирования риск-данных по BCBS 239; без согласованных идентификаторов клиентов, контрагентов и инструментов агрегирование рисков по подсистемам даёт несогласованные картины экспозиций. Цикл проводится ежеквартально для комплексного обзора качества НСИ и управленческих решений — новые определения CDE, изменения владельцев, инициативы по дедупликации и обновление справочных данных — с ежемесячным мониторингом оценок качества золотых записей. Требования FATF к надлежащей проверке клиентов (CDD) и стандарты данных KYC НБКР/НБК/АРРФР предъявляют конкретные требования к точности и полноте клиентских НСИ, которые должен удовлетворять цикл стюардства. Выявление кандидатов на дедупликацию с помощью статистического сопоставления, обновление справочных данных из авторитетных внешних источников, запросы для валидации кросс-доменной согласованности и документирование решений по стюардству данных — структурированные, высокообъёмные задачи, поддающиеся исполнению с участием агента при проверке стюарда.

Агент еженедельно читает записи сущностей из всех систем-источников и применяет вероятностное сопоставление по вариантам имён, транслитерациям, налоговым идентификаторам и полям адресов, формируя список кандидатов с оценкой уверенности. Высококонфидентные совпадения представляются стюарду в виде потока пакетного утверждения; пограничные случаи и совпадения с меньшей уверенностью ставятся в очередь на индивидуальную экспертную проверку. Монитор состояния массива мастер-данных

Агент непрерывно отслеживает оценки качества золотых записей, показатели охвата дедупликацией и согласованность идентификаторов между доменами по всему массиву мастер-данных между ежеквартальными циклами стюардства, сигнализируя CDO о деградации и влиянии непогашенного бэклога. Монитор отслеживает CDE клиентов, контрагентов и инструментов по домену и количественно оценивает экспозицию агрегирования рисков BCBS 239 от бэклогов дедупликации и несоответствий идентификаторов в разных системах. CDO использует вывод для ежеквартальной отчётности перед советом по управлению данными.

M
Решаемая задача

Качество мастер-данных оценивается ежеквартально; между циклами пробелы накапливаются по мере роста бэклогов дедупликации и деградации согласованности идентификаторов между системами без систематического обнаружения. CDO не может количественно оценить влияние непогашенных бэклогов дедупликации на точность агрегирования рисков нижестоящего звена без проведения ручной оценки. Отчётность перед советом директоров по качеству данных опирается на ручную агрегацию из доменных входных данных без единой базы для скоринга.

Решение

Агент еженедельно считывает метрики качества золотых записей, показатели охвата дедупликацией и оценки согласованности идентификаторов между доменами из хаба MDM и производящих систем. Поддерживается непрерывный дашборд состояния мастер-данных по домену CDE с ретроспективными линиями трендов качества и оценкой бэклога дедупликации, выраженной как доля от общей популяции сущностей. Раздел по влиянию BCBS 239 количественно оценивает, как непогашенные бэклоги влияют на точность агрегирования экспозиции контрагентов и инструментов.

OKR

CDO отслеживает качество золотых записей, охват дедупликацией и согласованность идентификаторов между доменами на непрерывной еженедельной основе, при этом экспозиция агрегирования рисков BCBS 239 от непогашенных бэклогов количественно оценивается и ежеквартально отражается в отчётности перед советом по управлению данными.

Внедрение

Агент поддерживает непрерывный дашборд состояния мастер-данных, охватывающий домены CDE клиентов, контрагентов и инструментов, ≥ 48 недель в течение первых 12 месяцев; раздел по влиянию BCBS 239 включён в каждый ежеквартальный отчёт перед советом по управлению данными.

Принятие

≥ 85% оценок качества на дашборде подтверждены командой по управлению данными по выводам хаба MDM при ежеквартальной проверке; оценки влияния бэклога дедупликации BCBS 239 приняты командой рисковой отчётности как направленно точные в ≥ 80% кварталов.

Цикл

Цикл оценки состояния мастер-данных сокращён с ежеквартальной ручной агрегации до непрерывного еженедельного дашборда; подготовка отчётности для совета по управлению данными осуществляется на основе вывода дашборда в ≤ 1 рабочий день.

Приоритизация влияния кандидатов на дедупликацию

Агент ранжирует очередь кандидатов на дедупликацию по влиянию на регуляторные и рисковые нижестоящие звенья затронутого типа сущности, направляя мощности проверки стюардов на CDE контрагентов и финансовых инструментов, влияющих на агрегирование рисков BCBS 239, прежде чем переходить к высокообъёмным парам совпадений розничных клиентов с меньшим влиянием. Ранжирование учитывает тип сущности, существенность экспозиции и зависимость потребляющих отчётов для формирования расписания проверки стюардами, согласованного с обязательствами по соответствию BCBS 239. Руководитель по управлению данными использует ранжированное расписание для распределения мощностей команды стюардов.

M
Решаемая задача

Приоритизация проверки кандидатов на дедупликацию не систематически согласована с регуляторным и рисковым влиянием конкретных CDE мастер-данных на нижестоящее звено. Высокообъёмные пары совпадений розничных клиентов потребляют мощности проверки, которые принесли бы большую комплаенс-ценность, если бы были направлены на CDE контрагентов и инструментов, существенные для агрегирования рисков BCBS 239. Бэклог по сборке накапливается по циклам без дифференциации по существенности сущностей.

Решение

Агент читает очередь кандидатов на дедупликацию и сопоставляет каждый тип сущности и пару кандидатов с зависимостями риска и регуляторных отчётов нижестоящего звена, взятыми из каталога данных. Каждая пара оценивается по существенности типа сущности — CDE контрагентов и инструментов, используемые в агрегировании BCBS 239, получают наибольший вес, — и формируется ранжированное расписание проверки стюардами. Высококонфидентные розничные пары выше установленного порога совпадения выделяются в поток пакетного утверждения, резервируя очередь для суждений по высокосущественным совпадениям с низкой уверенностью.

OKR

Мощности команды стюардов данных направляются на кандидатов на дедупликацию CDE контрагентов и инструментов с наибольшей существенностью агрегирования рисков BCBS 239, а высокообъёмные розничные пары управляются через отдельный поток пакетного утверждения.

Внедрение

Агент формирует ранжированное расписание проверки стюардами для ≥ 95% еженедельных очередей кандидатов на дедупликацию в течение 12 месяцев с момента запуска; поток пакетного утверждения для высококонфидентных розничных пар активен с момента запуска.

Принятие

≥ 85% ранжирований приоритизации по существенности подтверждены руководителем по управлению данными как правильно упорядоченные; бэклог существенных CDE BCBS 239 разбирается темпом на ≥ 50% выше, чем базовый показатель до внедрения агента, в течение 12 месяцев.

Цикл

Темп разбора очереди дедупликации CDE контрагентов и инструментов повышен с кампанийных ежеквартальных проверок до непрерывного еженедельного ритма стюардов.

Синтез паттернов выводов аттестации

CDO и руководитель по разработке данных используют анализ паттернов для формирования структурированной программы повышения качества пайплайна наряду со стандартными усилиями по устранению в рамках отдельных циклов. Формируется синтез паттернов, ранжирующий системные недостатки по частоте повторений и существенности BCBS 239, с рекомендуемой приоритизацией инженерного устранения. CDO представляет синтез паттернов руководителю по разработке данных по закрытии каждого цикла аттестации как основу для плана инвестиций в качество пайплайна.

Принятие

Цикл регуляторных представлений данных

Ежемесячные и ежеквартальные регуляторные представления данных в НБКР, НБК/АРРФР и ЦБР — агрегирование данных, форматная валидация, представление, сверка после представления и разрешение надзорных запросов. В соответствии с требованиями BCBS 239 к агрегированию данных и стандартами регуляторных представлений СНГ.

Цикл регуляторных представлений данных регулирует периодические представления банка в НБКР (Кыргызская Республика), НБК/АРРФМ (Казахстан) и ЦБР (Россия) — предписанные наборы данных, лежащие в основе пруденциального надзора, мониторинга финансовой стабильности и статистической отчётности. Каждый регулятор публикует собственные формы представлений, правила контроля и протоколы электронной подачи. Для банковских групп с операциями в нескольких юрисдикциях СНГ цикл представлений проходит параллельно в трёх регуляторных периметрах с различными календарями, форматами и определениями данных. Принцип 2 BCBS 239 (точность и целостность данных) требует, чтобы банк мог представлять регуляторам полные, точные и своевременные данные. Цикл представлений — операционное выражение соответствия BCBS 239: повторяющаяся проверка работоспособности архитектуры данных и системы качества. Запросы надзорных данных вне стандартного календаря представлений — внеплановые запросы в ходе надзорных расследований, проверок на месте или анализа финансовой стабильности — должны исполняться по требованию из той же инфраструктуры данных. ИИ может поддержать цикл, автоматизируя комментарии к валидации агрегирования данных, формируя пояснительные записки к исключениям представлений и составляя пакеты ответов на надзорные запросы из документации о происхождении данных и записей о качестве данных.

Analyze

Результативность представлений — частота ошибок валидации, объёмы исключений, частота запросов по регуляторам — неформально отслеживается командой регуляторной отчётности, но не агрегируется в анализ трендов качества по представлениям и регуляторам. Директор по данным не может сформировать систему показателей соответствия BCBS 239 без ручного извлечения из записей представлений.

Optimize

Разрешение исключений валидации выполняется последовательно командой отчётности относительно сроков каждого регулятора. Анализ паттернов по нескольким регуляторам — выявление проблем качества данных, стабильно генерирующих исключения у нескольких регуляторов, поскольку они берут начало в одной системе-источнике, — не применяется в рамках стандартного цикла представления.

Automate

Комментарии к агрегированию регуляторных представлений, пояснительные записки к исключениям валидации, комментарии к расхождениям сверки после представления и черновики ответов на надзорные запросы — структурированные задачи написания с последовательными фреймворками. Обход происхождения данных BCBS 239 для конкретных CDE следует воспроизводимому пути от источника до представленного значения, поддающемуся генерации ответов с участием агента.

Enrich

Истории надзорных запросов по НБКР, НБК/АРРФР и ЦБР — какие точки данных оспаривались, какие объяснения принимались, какие методологические изменения запрашивались — накапливаются в отдельных файлах запросов, а не в консолидированной базе знаний. Каждый цикл запросов повторяет исследовательские и редакционные усилия, которые могли быть обеспечены ответами предыдущих циклов.

Выявляются первопричины систем-источников, генерирующие исключения по нескольким регуляторным периметрам, и ранжируются по агрегированному объёму исключений по всем трём регуляторам. Команда по качеству данных устраняет первопричины с наивысшим рангом до следующего срока представления, снижая общий объём исключений по всем периметрам посредством одного действия по устранению.

OKR

Команда данных устраняет исключения регуляторного представления из кросс-регуляторной очереди первопричин, направляя усилия по устранению на проблемы систем-источников, одновременно закрывающие исключения по НБКР, НБК/АРФР и ЦБР.

Внедрение

Агент формирует анализ кросс-регуляторных паттернов исключений до ≥ 90% сроков представления по всем трём регуляторным периметрам; охват распространяется на 100% категорий исключений в каждом цикле.

Принятие

≥ 80% выявленных общих первопричин подтверждены командой по качеству данных как точные; не менее одной кросс-периметровой первопричины урегулировано за цикл в ≥ 75% периодов представления.

Цикл

Общий объём кросс-регуляторных исключений снижен на ≥ 20% год к году по мере систематического устранения общих первопричин; анализ паттернов передаётся ≥ 5 рабочих дней до каждого срока представления.

База знаний надзорных запросов

Агент консолидирует историю надзорных запросов по НБКР, НБК/АРФР и ЦБР в структурированную базу знаний, классифицируя каждый запрос по точке данных, типу вызова и подходу к урегулированию и представляя CDO и команде регуляторной отчётности повторяющиеся паттерны. База знаний используется для прогнозирования категорий запросов до представления, ускорения составления черновиков ответов по ссылке на предыдущие принятые обоснования и направления предпредставительного повышения качества данных в хронически оспариваемые точки данных. CDO использует анализ паттернов для отчётности по программе управления BCBS 239.

Решаемая задача

Истории надзорных запросов по трём регуляторным периметрам накапливаются в отдельных файлах запросов, а не в консолидированной базе знаний. Каждый цикл запросов повторно выполняет расследование и усилия по составлению черновиков, которые могли бы быть подсказаны ответами предыдущего цикла. Повторяющиеся вызовы по одним и тем же точкам данных — свидетельство системной проблемы качества данных или методологии — не выявляются как паттерн, поскольку записи запросов не агрегируются и не классифицируются.

Решение

Агент читает все исторические записи надзорных запросов и ответов по НБКР, НБК/АРФР и ЦБР, классифицирует каждый запрос по CDE, измерению качества данных, форме представления и типу урегулирования и формирует структурированную базу знаний, доступную команде регуляторной отчётности. База знаний представляет повторяющиеся паттерны запросов, ранжированные по частоте, и выявляет точки данных, оспаривавшиеся несколькими регуляторами. Предпредставительные брифинги для команды регуляторной отчётности включают основные повторяющиеся категории вызовов по каждому предстоящему сроку представления.

OKR

Команда регуляторной отчётности применяет консолидированную базу знаний надзорных запросов — классифицируя запросы по CDE, типу вызова и подходу к урегулированию по НБКР, НБК/АРФР и ЦБР — для прогнозирования повторяющихся категорий запросов и ускорения составления черновиков ответов.

Внедрение

Агент загружает и классифицирует ≥ 95% исторических записей надзорных запросов по всем трём периметрам к концу месяца 3; база знаний обновляется по каждому новому циклу запросов в течение 2 рабочих дней после закрытия ответа.

Принятие

≥ 80% повторяющихся паттернов запросов подтверждены командой регуляторной отчётности как релевантные для принятия решений; брифинги по категориям вызовов до представления используются в ≥ 90% предстоящих циклов подготовки к представлению в течение 12 месяцев.

Цикл

Время составления черновика ответа на запрос сокращено на ≥ 40% для повторяющихся категорий вызовов в течение 12 месяцев, поскольку предыдущие принятые обоснования извлекаются из базы знаний до начала составления черновика.
