# Бэклог программы

Бэклог программы, также называемый бэклогом PI, — перечень Capabilities и Features в порядке приоритета. Работа над Capability может продолжаться несколько программных инкрементов. Feature завершается в пределах своего программного инкремента или разделяется. Бэклог программы проходит через канбан-доску программы (board.md). Feature одобряется, только если известны её зависимости. Инициативы INI-002, INI-003, INI-004, INI-006, INI-007 и INI-008 находятся в состоянии «Проработка», поэтому Capabilities у них пока нет. Их Capabilities определяются после управленческого решения о продолжении работы по итогам MVP (п. 7.2 Модели управления портфелем).

Начальная мощность установлена в board.md по DR-2026-063: одна Feature в работе в целом по обычной работе и текущим работам, не более двух Features в колонке «Готово к работе». Четыре постоянные инициативы одобрены; на дату их установления ни одна Feature текущих работ не принята.

## Features

Для Feature в качестве родительского элемента указывается её Capability, а для текущих работ — постоянная инициатива. Принятие текущих работ фиксируется на еженедельном обзоре после одобрения паспорта постоянной инициативы. В записи о Feature указываются заказчик и владелец домена, одобрение применения для класса данных, если применяется AI, критерии приёмки и зависимости. Даты одобрения и завершения используются для расчёта ожидаемого времени выполнения; ожидание и возвраты после одобрения учитываются в этом измеряемом потоке до приёмки или иного завершения (пп. 3.1, 4.1 и 10.3 Модели жизненного цикла решений).
