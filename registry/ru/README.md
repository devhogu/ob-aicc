# Реестр

Реестр содержит Записи AICC: процессные записи о текущей и выполненной работе, Управленческие решения, Предложения и записи по управлению. Он не содержит числовых данных Банка, данных или кода. В Записи о назначениях указаны лица, исполняющие Роли. Комментарий в квадратных скобках обозначает незаполненное место и поясняет ожидаемое содержание. Правила установлены в Операционной модели 7: при Переходе Рабочее состояние переносится в Jira и Confluence, а Подтверждающие записи всегда остаются здесь в виде закрытых датированных выгрузок. Jira, Confluence и Service Management не являются хранилищем подтверждений. Руководитель AICC несёт итоговую ответственность за все Записи.

## Подтверждающие записи

Закрытые датированные выгрузки, всегда хранящиеся здесь. Операционная модель 8 перечисляет контрольные процедуры и запись, подтверждающую каждую из них.

| Запись | Расположение | Содержание |
| --- | --- | --- |
| Журнал решений | [decision-log.md](decision-log.md) | Управленческие решения, по одной строке на каждое |
| Управленческие решения | [decisions/](decisions) | Записи о решениях начиная с DR-2026-060 |
| Инициативы | [initiatives/](initiatives) | Папка для каждой: `INI-nnn-short-title/` с Паспортом, Соглашениями о взаимодействии, Отчётами о результатах, Функциональными возможностями и Функциональностями |
| Отчёты | [reports/](reports) | Квартальные отчёты с именами вида `2026-PIQ4.md` |
| Управляющие совещания | [steering/](steering) | Итоги Управляющих совещаний |
| Предложения | `proposals/` | Предложения по масштабному внедрению Решения и ежегодное Предложение по стратегии внедрения ИИ. Папка создаётся с первым Предложением |
| Контрольные листы приёмки | `checklists/` | Контрольный лист приёмки каждого Решения при Выпуске за пределы Первых пользователей; имя файла — `ACL-001.md`. Папка создаётся с первым листом |
| Заключения контрольных функций | `sign-offs/` | Решения Представителей контрольных функций; имя файла — `SGN-001.md`. Папка создаётся с первым заключением |
| Разборы Инцидентов ИИ | `incident-reviews/` | Разбор каждого Инцидента ИИ; имя файла — `AIR-001.md`. Папка создаётся с первым разбором |
| Снимки Реестра | `snapshots/` | Закрытая выгрузка по завершении каждой Итерации и PI; имя файла — `SNP-2026-PIQ4-I10.md`. Первый Снимок требуется при завершении I10 |
| Назначения | [appointments.md](appointments.md) | Журнал части C Записи о назначениях подтверждает каждое назначение, изменение и освобождение от исполнения Роли |

Идентификаторы: PRI-n — приоритет; INI-nnn — Инициатива; SOL-nnn — Решение (в Портфеле); PKG-nnn — Пакет (в Портфеле); CAP-nnn — Функциональная возможность; FT-nnn — Функциональность; DEP-nnn — Зависимость; MS-nnn — Веха; DR-yyyy-nnn — Управленческое решение; RI-nnn — риск или проблема; ARC-nnn и PLT-nnn — стандарты; AGR-nnn — Соглашение о взаимодействии; OUT-nnn — Отчёт о результатах; SGN-nnn — Заключение контрольной функции; AIR-nnn — Разбор Инцидента ИИ; ACL-nnn — Контрольный лист приёмки; SNP-yyyy-PIQn-Inn (завершение Итерации) или SNP-yyyy-PIQn (завершение PI) — Снимок Реестра; PRP-nnn — Предложение; AP-nnn — запись о назначении. Соглашение о взаимодействии и Отчёт о результатах хранятся в папке своей Инициативы под именами `AGR-001.md` и `OUT-001.md`.

Реестр содержит необходимые аудитору сведения об отсутствии событий или записей. Запись о рисках и проблемах указывает Инциденты ИИ и Исключения на текущую дату; Реестр ИИ — перечисленные к этой дате применения.

Решения, которые AICC определяет и испытывает, находятся в Портфеле (`portfolio/`); ритм работы описан в рабочих процессах корпуса документов.

Базовая редакция корпуса и четыре Постоянные инициативы одобрены по [DR-2026-063](decisions/DR-2026-063-approved-english-baseline.md). После её установления Реестр продолжает отражать фактическую работу и подтверждения. Операционное действие остаётся здесь до выполнения и не является неурегулированным положением корпуса документов.
