## charter/ru/documents/solution-lifecycle-model.md

- DRIFT — 1.3 and 6.6: the old text had «workflows корпуса Положения» and «в корпусе Положения», which made "the charter" (the corpus) into the AICC Charter. Now «рабочие процессы корпуса» and «в корпусе».
- DRIFT — 4.1: the old text had «Каждый бэклог ранжируется», while the English "Each is ranked … scored 1 to 5" refers to the items. Now «Элементы бэклогов ранжируются …; ценность, срочность … оцениваются по шкале от 1 до 5».
- DRIFT — 2.1: the old text had «подтверждающих данных перед мнением». "Evidence over opinion" is now «фактические данные важнее мнений» (map row "evidence (основание решений)"). The other three values follow the Manifesto form «… важнее …».
- QUESTION — PDCA "Check" (6.2–6.4, 8.4, figures 5–7, 11): written as «Контроль», not «Проверка», so that «проверка» alone still means the AICC term Check (STYLE §3). Vocabulary 4.1 «Цикл» still has «Планирование — Выполнение — Проверка — Корректировка», so the documents need to agree on one form.
- QUESTION — Inspect and Adapt: kept in Latin as the accepted form of the terminology reference («на мероприятии Inspect and Adapt»). The old text and Vocabulary use «Анализ и адаптация».
- QUESTION — Work Item: «рабочий элемент», following STYLE §4. Vocabulary and the terminology reference use «рабочая задача».
- QUESTION — Events: Iteration Review and Demo → «ревью и демонстрация итерации», Iteration Retrospective → «ретроспектива итерации», Daily Stand-up → «планёрка», PI Planning → «PI-планирование», all lowercase (terminology reference accepted forms). The Vocabulary list of events («Ежедневная короткая встреча», «Обзор и демонстрация Итерации» …) differs.
- QUESTION — 8.1, 5.2 and elsewhere: "a Solution is delivered" → «поставка решения завершена», not «внедрено», so that it does not clash with «внедрённое решение» (Adopted Solution). The stage name «Поставка» is kept.
- QUESTION — 8.8: the service step names («Допущен», «Внесён в каталог», «Обслуживает», «Улучшается», «Переход запланирован», «Мигрирует») are kept as they were, because the template «Описание решения», the workflow service-delivery and portal pages use them. «Обслуживает» and «Мигрирует» read awkwardly as step names; «В эксплуатации» and «Миграция» would be better if all files change together.
- QUESTION — 4.5: the labels «(критерии готовности к работе, DoR)» and «(критерии завершённости, DoD)» were added to name the two definitions that the 2.0 change log refers to. The English 4.5 does not name them.
- QUESTION — 7.3(c) and 7.5: "requester" → «заказчик». The alternative is «представитель заказчика по приёмке» (term Business acceptor), but the English does not use that term here.
- QUESTION — 8.10: "checklist" (light mode) → «контрольный перечень», to keep it apart from «контрольный лист приёмки».
